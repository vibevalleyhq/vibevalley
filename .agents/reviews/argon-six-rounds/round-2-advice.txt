#### 四、关键风险与注意事项

1. **`repro` 第二轮恢复工作区**：在 `FakeWork` 里，`this.written.delete("fix")` 只是改内存 Set；在真实 Git worktree 中，第 1 轮 `repro` 已经提交了 `steps/fix.txt`，所以第 2 轮 `repro` 帮工脚本需执行 `git rm -f steps/fix.txt` 并 `git commit`（而第 2 轮 `fix` 帮工脚本需执行 `git checkout HEAD~1 -- steps/repro_test.txt` 恢复被第 1 轮污染的冻结文件再提交 `steps/fix.txt`），这样才能通过真实的 `projects.changedFiles(cwd, graph.branch)` 检查。
2. **重启测试的开机顺序**：第 446 行的重启测试在去掉 `FakeWork` 后，第二次启动必须按 `services.ts` 的真实顺序先跑 `sessionReady`（把在途的 `w1` 从 `session` 表恢复并施加 `interrupted` 的 `report` 事实），再跑 `tasks.comeBack`（或先 `comeBack` 把 `running` 标为 `paused`，再 `sessionReady`），无需再在测试里手写 `f.core.apply({ type: "report", outcome: "interrupted" })`！
3. **`world` 的预置仓库**：测试中用到的项目名（`"diamond"`、`"bug"`、`"shaky"`、`"circle"`、`"slowpoke"`、`"test"`）需放入 `world({ repos: [...] })`，使 `Project.openBranch` 和 worktree 创建在真实 Git 仓库上运行。
