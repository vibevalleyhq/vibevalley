# Agent Note: 帮工的权限请求变成地里的杂草

Status: rejected — 帮工不做权限确认是常驻规矩：靠本机、工作目录和院门划边界，逐条批准会让帮工停在命令上等人，和无人值守冲突；「除草」留着位置

## Problem

帮工现在不要权限确认（[帮工](docs/subsystems/session.md)），能在这台机器上执行任意命令。有些操作主人想先看一眼再放行（删文件、装依赖、联网）。农场里的「除草」工具一直留着位置，没有接上。

## Proposal

- 打开 runtime 的权限确认（smith 把它记成 toApp 请求；现在 smith 跑每个会话都不带权限确认），服务端不自动应答，而是施加一个事实：帮工在等你批准，带上它要做什么。
- 地里长杂草，挂「等你批准」；「除草」打开一张卡片，写清要执行什么，可以批准或拒绝；管家的「农场现状」里也会说。
- 按项目或按命令记住「总是允许」，免得每次都问。

## Alternatives considered

**全部自动批准（现状）。** 快，但没有任何拦截。

**开沙箱代替确认。** 各 runtime 的沙箱能力不一样；有沙箱的（codex）可以叠加，不能代替。

## Acceptance criteria

- 帮工要执行一条需要确认的命令时，它停下、地里长草；批准后接着干，拒绝后它收到拒绝并换个办法。
- 「总是允许」之后，同样的请求不再问。

## Risks

- 主人不在时帮工会一直等，占着地；要和「没动静」的提醒区分开。
- 各 runtime 的确认请求格式不同，要逐个对。
