# Agent Note: 页面里有一个按同样规则跑的模拟服务器和调试台

Status: implemented

> 已被取代：网页连同它的模拟服务器删掉了，调画面要开一个服务端，Flutter 的测试用 `MockClient` 假扮它；调试台还在（`app/lib/shell/debug/`，`` ` `` 键），只对着真的服务端，不强制状态、不施加事实（[网页退役](../simplification/2026-10-14-retire-the-web-page.md)）。下面是当时的决策。

## Problem

画面和交互要在各种局面下调：六块地都满、一片失败、派不出去、插话打断、断线重连、马上升级。等真实的帮工跑出这些局面又慢又花钱，有的（比如连不上语音）根本造不出来。最早服务端还不存在。

## Decision

见 [development.md](../../../../docs/development.md)「调试台」：

- 页面里跑一个模拟服务器（`web/src/mock/`），按服务端的规则扮演管家和帮工，说同一套工地事件，用同一个 `reduce` 维护一份核心状态；`/api/health` 不答应时自动用它，`?mock` 强制用它。（自动用它这一条已经被[页面只给真实数据](../simplification/2026-10-12-real-data-only.md)取代：现在只有 `?mock` 才用。）
- 所有等待跑在一个可控的虚拟时钟上（替换了 Effect 的 `Clock`），能暂停、倍速、单步。
- 调试台（`` ` `` 键，或控制台的 `hb`）能强制状态、施加任意事实、改规则、一键摆出局面、回放事件流。

## Alternatives considered

**只对真实服务端调。** 局面难造、要花钱、不能单步；服务端出问题时页面也没法开发。

**写死的假数据。** 不会动，也不按规则走：派不出去、插话这些行为调不了。

## Consequences

画面在任何局面下都能调，接上服务端是一样的。代价是模拟服务器要跟着服务端的规则一起改；它没有的（干活过程、收成清单、花费）只能对真实服务端调。
