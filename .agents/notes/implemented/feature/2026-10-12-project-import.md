# Agent Note: 开新地与 GitHub 串门

Status: implemented

## Problem

项目页只能列出工作目录已有的文件夹。主人想看一个公开 GitHub 项目时，要先在终端里克隆，才能在农场里查看代码分布、提交记录或安排帮工。

## Decision

项目页的「新增项目」提供「开一块新地」和「去别人家看看」。前者创建带初始提交的仓库，后者接收公开 GitHub 仓库主页 HTTPS 地址，自动建议项目名并允许修改。两者都在 `VIBEVALLEY_WORK_ROOT` 下创建一个直接子目录。协议在 protocol（`NewProject`、`FarmCreateProject`），纯校验在 `server/internal/project/project.go`（`projectProblem`；表单提交前经 `POST /api/projects/check` 问它，客户端不再照搬一份），文件系统操作在 Projects 服务；HTTP 处理只转发，客户端成功后刷新项目列表，页面打开新项目。

导入只克隆，不派帮工、不安装依赖、不运行项目。保留原仓库历史与 origin。下载期间显示进行中，不伪造百分比；克隆最多 3 分钟，关闭终端认证提示，失败返回可重试原因。目录通过排他 mkdir 取得，存在任何同名目录或符号链接都拒绝；失败只清理本次创建的目录。创建与帮工开工共用项目队列，进行中的目录不进入项目列表。

模拟服务器仅在当前页面会话新增空的模拟项目，不访问 GitHub；页面的模拟数据标记沿用现有工作台。（这一段后来被 [网页退役](../simplification/2026-10-14-retire-the-web-page.md) 取代：模拟服务器随网页删了，新增项目只走真的服务端。）

## Alternatives considered

**导入完成立即派人读代码。** 导入与使用模型是两件事，主人进入项目后自行安排任务。

**任意 git 地址与私有仓库。** 第一版限定公开 GitHub HTTPS 仓库主页，避免额外引入认证、SSH、凭据存储和其他传输协议。

**浅克隆。** 项目页的提交日历与统计需要历史，因此保留正常克隆。

## Consequences

大仓库下载可能较慢；进行中不能关闭这个表单，但服务端超时会解除等待。同名目录原样保留。源码快照镜像的提交日历只表示镜像历史，不能代表原项目开发频率。

## Verification

离线测试使用真实 git 仓库，并把测试用 GitHub 地址重写到临时本地仓库。覆盖输入校验、初始提交、拒绝覆盖、同名并发、保留历史和 origin、失败清理及重试。
