# Agent Note: 项目页：把代码库当一块地看

Status: implemented

## Problem

帮工在工作目录下的项目里干活，可农场里看不到这些项目本身：一个项目是用什么写的、各占多少，这一年谁在上面干了多少活、哪段时间忙。主人要一个统计的按钮看代码分布，要 GitHub 那样的提交日历，而且整页要从游戏的角度来展示一个代码库，不是一张报表。

## Decision

一个配置页 `/projects`：左边是项目，右边把选中的项目当一块地。规则在客户端的 `app/lib/workbench/projects/codebase.dart`（纯函数，有测试），数据由服务端的 `server/internal/project/codebase.go`现算，页面在 `app/lib/workbench/projects/projects_page.dart`。

- **长势**：项目前面画一块地，按最近一次提交长成什么样（一天内开花，一周内长叶，一个月内冒芽，三个月内有点干，再久就荒了）。用的是农场现成的地块图，一眼看出哪个项目还有人在干。
- **地契**：开垦于（第一个提交）、耕作（提交数）、庄稼（行数）、种了几样，和「统计」按钮。
- **种了什么**：语言的占比画成一块地里的几垄，大的垄上有语言的 logo（36 种，[生图流水线](../process/2026-10-09-image-pipeline-with-codex.md)；当时手绘和像素各一套，[只留像素村](../simplification/2026-10-12-pixel-only.md) 以后只剩像素的，手绘的原图留在 `design/assets/raw/` 给像素版照着画）。按非空行算（代码加注释）：tokei 把 Markdown 的正文算成注释，只按代码算文档就没了。
- **耕作日历**：53 周、周一在上，一格一天，提交越多长得越高（五档，从空地到开花），档位按这一年忙的日子（第 95 百分位）定，一天特别多的不会让别的日子都显得空。连着干的天数、最忙的一天。
- **谁来干过活**：按提交数排；名字和帮工一样的显示帮工的脸。
- **数代码用 tokei**：它快（这个仓库 0.04 秒），读 .gitignore，分得清代码、注释、空行，认两百多种语言。锁文件、压缩文件、依赖和构建目录另外排除。没装就拒绝，说怎么装。
- **提交算所有分支、不算合并**：帮工还没收的活也算这块地上的耕作；收获的合并提交不重复算一天。
- 语言的名字、别名（TSX 算 TypeScript）和颜色（GitHub linguist 的）在 `codebase.dart` 的 `langs`，一处定义；logo 按 `lang-<id>` 的名字取。

## Alternatives considered

**自己写一个按扩展名数行的计数器**，扫 `git ls-files`。不用装东西，但要自己维护语言表、注释语法、生成文件的判断，结果也没 tokei 准。和 tokei 并存当后备的话就是两条路径、两套结果。tokei 一行 `brew install` 就有，桌面客户端的服务端也找得到它。

**scc**：和 tokei 差不多（Go 写的，还算复杂度），这台机器上没有，主人提的是 tokei。

**GitHub linguist**：GitHub 用它，按字节算、会认生成文件和 vendored 代码，但要装 Ruby 和一个 gem，慢，本地用太重。

**按字节或按代码行算占比**：字节会让长行的文件（JSON、压缩过的）占得太多；只算代码行会让文档消失。

**做成农场里的一个面板**：一开始是这样打算的，但日历要一整行的宽度，几个区块一起看也要地方，配置页那样的整页更合适。

**只算主分支的提交**（GitHub 的算法）：帮工在自己分支上的活要等收获才出现，日历就落后于地里正在发生的事。

## Consequences

- 统计要装 tokei；没装时这一块显示怎么装，日历和提交照常。
- 每次打开都现数：大仓库也只要零点几秒，所以没有缓存，也就不会过期。
- 日子按服务端那台机器的时区算；页面和服务端在同一台机器上时两边一致，经 [院门](2026-10-14-yard-gate.md) 连来的设备要和它在同一个时区才一致。
- 作者按 git 的名字认，帮工用的是机器的 git 用户，所以帮工的提交算在那个人名下；只有名字和帮工一样时才显示帮工的脸。
