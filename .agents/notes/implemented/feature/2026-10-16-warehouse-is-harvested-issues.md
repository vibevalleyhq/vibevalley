# Agent Note: 仓库装收获了的工单

Status: implemented

## Problem

农场院子里的「仓库」装的是核心状态里的 `reports`：帮工每交一轮汇报就多一格，没做成的也放进去，只留最近 50 格。主人看了说没看明白它是干什么的：

- 名字和空着时的话（「收一下就会放进来」）说的是收获，装的却是每一轮的汇报，和收没收获无关；
- 同样的东西在看板的工单、工单的干活过程、田头工单串里的汇报、农场日志里都有；
- 照 [概念先行](../../proposed/architecture/2026-10-15-concepts-first.md)，轮从执行的步骤里切出来，不该另存一份。`reports`（`TurnReport`）是还没有看板时留下的。

## Decision

行为见 [farm-ui.md](../../../../docs/reference/farm-ui.md)「仓库」「农场日志」。

- **仓库装收进主分支的成果**：核心状态里关成 `merged` 的工单，一张一格（整个种植计划收获了也是一格），最近收的在前；点开是那张工单（计划打开计划板）。顶栏上仓库挂的数是它们的张数。不另存，读的是工单。
- **日志里的汇报读田头**：帮工交的每一轮汇报本来就是工单串里的一条汇报消息（结论、结果、花费），日志直接读它们，工单名从帮工的执行找到它的工单。被叫停的一轮没有汇报消息，日志里也就不再有。
- **播种的「派过的活」读工单**：最近写下或派出的工单标题，计划的除外。
- **核心状态去掉 `reports`**：`TurnReport`、`KeepReports` 和 `state.json` 里的这一份都没了；从更早的 `site.json` 读汇报的兼容也一起删了。帮工身上仍有最后一轮（`Helper.last`）。

## Alternatives considered

**保留仓库现在的样子，只改说明文字。** 最省事，但它还是和看板、日志重复，核心状态里也还多一份汇报。

**把仓库去掉。** 院子里少一个入口，可「收获」就没有一个看得见的去处；收获了的工单和看板的「已关」也不一样，已关里还有没收就收工的。

## Consequences

- 收获在农场里有了结果：收一张工单，仓库就多一格。
- 日志里不再有被叫停的那一轮。
- 黄金数据里的状态去掉了 `reports`，用 Go 的结果重写过。

## Verification

- `app/test/farm_panels_test.dart`：仓库里是收获了的工单（标题、谁、项目、多久前收的），日志里是田头里的汇报消息，空着时各自的话；播种表单里排第一的是最近的工单标题。
