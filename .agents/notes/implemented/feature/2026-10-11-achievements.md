# Agent Note: 成就和金币：奖结果，记在服务端的账本里，看得到进度

Status: implemented

## Problem

原来的成就、金币、连胜在页面里算，存在浏览器的 localStorage：

- **只有页面开着才算**：帮工在页面关着时做完、收获，没有金币也没有成就；浏览器和桌面版各算各的一份，清掉浏览器数据就没了。
- **奖的是消耗**：10 个成就里一半在数命令、读写文件的次数，等于奖励多花 token；「五湖四海」鼓励去请用不上的农机；金币按「一轮做完」给，这件活最后有没有收进主分支都一样。
- **一次性、平的**：拿到和没拿到两种状态，没有档位和进度，不知道是哪天、因为哪件活拿到的。
- **拿到了没用**：金币花不出去，成就什么也不解锁。
- **和新东西脱节**：田头、工单串、语音、种植计划、收成清单都没有成就。

## Decision

行为和规则表见 [game-ui.md](../../../../docs/game-ui.md)「计分」和界面 8「任务与成就」，账本怎么记见 [server.md](../../../../docs/server.md)「账本」。

- **奖结果，不奖消耗**：金币、连胜、成就都以「收进主分支的活」为准，和等级按真实的 commit 数算一个道理。一轮做完不给金币；命令数、读写次数不进任何规则。
- **一本账本，在服务端**：服务端把值得记的事按顺序记进数据库的 `ledger` 表（`server/internal/game/ledger.go`）。金币、连胜、成就是账本按顺序折出来的（protocol 的 `progress.go`：`ProgressStep` 一次折一条，`ProgressFold` 折整本），放进核心状态的 `FarmState.progress`，由 `progress` 事实施加；这一条带来了什么（金币、给哪个帮工、到了哪几档）跟在事实的 `news` 里。各个客户端、重启后看到的是同一份；客户端关着时发生的事也算；规则改了，重启时从账本重新折一遍就是新的结果。`farm.json` 不存进度。
- **每个档案的战绩也由账本折出来**：派出帮工、收进主分支、一轮没做成这三种条目带上帮工的档案，折成 `progress.agents`（雇过、收成、没做成）。原来这些数在页面里随看到的事件累加、存在浏览器里，关着页面时的事不算，换浏览器就是另一个数。
- **事实说的事由一个纯函数挑**：`EntriesFor(before, fact, after)` 决定哪些事实记进账本（一轮没做成、会冲突、开工、派出帮工、收获、拆好计划、收获计划、带话、点名、交接、升级、六块地都在干活）；只有主人在应用里做的事由看到它的地方记（语音、看收成清单、称号、旧金币）。收获、带话、点名、交接原来也由看到它的地方记，后来改成从帮工离开和田头消息的事实里读出来，游戏只听事实（[概念先行](../../proposed/architecture/2026-10-15-concepts-first.md) 第 2 步）。服务端的账本看工地事件、自己折一份核心状态来调用它。（当时网页的模拟服务器也在 `apply` 里调用它，模拟服务器随网页删掉了。）
- **档位和进度**：计数的成就分铜、银、金三档，带进度条和拿到的日期；新手任务和彩蛋是一次性的。成就单在 protocol 的 `Achievements`（`progress.go`）；客户端的 `app/lib/rules/progress.dart` 有一份 Dart 移植，任务与成就面板、成就提示和 macOS 的通知读它。
- **新手任务**：七件第一次该做的事（开门、派活、带话、验收、说话、规划、点名），在「任务与成就」面板最上面打勾，每个 20 金币。
- **回报不碰干活**：金币以后在商店换装饰，成就给称号（新手任务除外）；帮工怎么派、地有几块，规则不变（地块跟等级走）。
- **客户端只显示**：读核心状态的 `progress` 和帧里 `view` 的等级，不另存；`progress` 事实的 `news` 由 protocol 的 `EffectsOf` 变成帧里要放的效果（金币飘起、成就提示），升级横幅来自 commit 数（`LevelUps`）。调试台改不了金币、等级和成就，只能放一遍横幅和提示，什么都不记。
- **奖章是框加图案**：codex 画了三张（`design/assets/gen.sh` 的 `medals`、`emblems`、`starter`）：铜、银、金、木头和锁着的框，每个成就一个图案，新手任务的图案和打勾的章。客户端把图案叠在框的圆盘里（`app/lib/farm/achievements.dart` 的 `Medal`）。
- **旧进度**：浏览器存档里的旧金币，页面连上服务端时经 `/api/progress/carry` 记进账本一次；旧成就不搬（新规则下意思不一样）。网页删掉以后没有谁再调这个接口，接口和账本里的 `carried` 条目还在。

## Alternatives considered

**接着在页面里算，只是存进服务端。** 页面关着时的事还是漏，两个页面还是会各算一遍再互相覆盖。规则在服务端从账本折，才只有一份。

**直接存计数（`counters`），不存账本。** 简单，但规则一改，旧的数就对不上；也说不清某一档是哪天、因为哪件活拿到的。账本按顺序折，结果总能重算，也带着每一档的日期。

**按 token、命令数给奖励。** 最好算，但奖的是花钱，正好和「管住花费」相反。

**「哪些事实要记」写在服务端的账本服务里。** 一开始就是这样写的；可模拟服务器也要记同样的账，抄一份迟早对不上。挪成 protocol 的纯函数 `entriesFor`，两边调用同一个，也能单独测。（模拟服务器随网页删了；现在是 Go 的 `EntriesFor`，`server/internal/protocol/progress.go`。）

**每个档位一张奖章图。** 21 个成就 × 3 档要画 60 多张，风格也难一致。框和图案分开画，叠起来。

**称号能挂新手任务。** 「开门」「派活」挂在农场卡上没有意思；称号只从计数的成就和彩蛋里挑，规则里也拦着。

## Consequences

- 金币和成就跟着服务端走：连着同一个服务端的客户端看到同一份，换一个 `VIBEVALLEY_HOME` 就是另一个农场。
- 一轮做完不再给金币，金币来得比以前晚、也少；连胜只看收进去的活，一轮没做成就断。
- 「一分钱一分货」只算知道花费的农机：claude、codex 只报 token，它们的活不算。
- 刷成就：派凑数的活收进去也能刷收成；奖励只有金币和称号，地块不靠它，刷了也没多大意思。
- 账本只增不减。一条记不下来只记日志，农场照常，那一条就少了。

## Verification

- `server/internal/protocol/progress_rules_test.go`：收获的金币和连胜加成、失败断连胜、一气呵成的条件、解铃人、浴火重生、一分钱一分货、物尽其用、新手任务各一次、计划的步数和同时做的一批、档位按顺序各一次、彩蛋、称号只能挂拿到的档位且不挂新手任务、旧金币；`EntriesFor` 对每种事实记什么、计划只记一次、跨级、六块地填满；`CatchUp`。
- `server/internal/farm/crew_test.go` 的 `TestCrewHarvestGoesInTheLedger`：脚本扮演的帮工收获后，账本里有这一笔。`server/internal/game/ledger_test.go` 的 `TestPlanLedger`：记一笔收获，进度事实带着金币；派活、没做成、升级由事实记下；旧金币只记一次；重启后折回同样的进度。
- `news` 变成什么效果（金币、成就）、commit 数带来的升级：protocol 的黄金数据逐条比（`server/internal/protocol/parity_test.go` 的 `TestReduceGolden`）。原来测页面这一半的 `packages/core/test/` 随网页删掉了。
- `app/test/desktop_notify_test.dart`：到了一档弹通知、点开任务与成就。
- 模拟农场里截图看过：收获后金币从帮工头上飘起、成就提示里是奖章、面板的新手任务、成就墙、彩蛋、称号的选单和农场卡上的称号。
