# Agent Note: 院门：局域网里别的设备用同一个农场

Status: implemented

## Problem

VibeValley 是 C/S 架构：状态在服务端，客户端只是订阅它。主人想在手机上、在另一台 Mac 上看同一个农场、派活、在田头说话，而不是每台设备各有一个农场。可是服务端只听 127.0.0.1，这条规矩是有原因的：帮工没有权限确认，能在这台机器上执行任意命令，谁能连上服务端，谁就能让帮工在这台机器上干任何事。开局域网访问，等于在 Wi-Fi 上开一个远程执行命令的口子，所以不能只是把监听地址改成 0.0.0.0。

## Decision

行为见 [server.md](../../../../docs/server.md)「院门」和 [desktop.md](../../../../docs/desktop.md)。

- **主监听不动，另开一道「院门」**（`server/internal/channels/lan.go`，服务 `Lan`）。服务端照旧只听 127.0.0.1；院门是另一个监听（`VIBEVALLEY_LAN_PORT`，默认 8790，所有网卡），默认关着，主人在「院门」页打开，重启后保持主人留下的样子。和语音线路一样，单开一个监听，上面的东西比主监听少：只有 `VibeValleyApi` 和两条工地流（`apiMux`），没有 `/mcp`（帮工的工具）和网页（后来 [网页退役](../simplification/2026-10-14-retire-the-web-page.md)，服务端不再发页面，主监听上也没有了）。
- **每个请求都要设备的钥匙**，只有配对请求不要。院门的开关、配对、设备列表这些接口只在本机的监听上能用，经院门来的请求一律 403：一台设备进了院门，也不能放别的设备进来。
- **配对**：主人点「添加设备」，服务端发一个一次性的配对码（2 分钟有效，错 5 次作废），装在链接 `vibevalley://pair?u=<院门地址>&c=<码>` 里，页面画成二维码。设备扫码（手机）或粘贴链接（Mac），带着码和自己的名字发 `POST /api/lan/pair`，然后一直等着；主人在这台电脑上点「让它进来」或「不让」。同意以后设备拿到一把自己的钥匙，数据库只存钥匙的 SHA-256。同一时间只有一台设备在等。
- **移除设备立即生效**：它的钥匙不再认，它正连着的请求（包括状态流）当场断开。
- **地址变了不做发现**：二维码里只放一个地址（这台电脑首选网卡的私有 IPv4）。电脑换了地址，设备就连不上了，主人在院门里再添加一次设备、让它扫一下。设备手上已经有这个农场的钥匙时，先拿钥匙去问新地址（`GET /api/lan/me`），认就直接用，不用主人再点头。
- **客户端**（`app/lib/data/farm_choice.dart`）：选用哪个农场，本机的或者别的电脑的，存在 shared_preferences 里。换农场时整个 `ProviderScope` 重建，所有 provider 都在新农场上重新开始。Mac 选了别的电脑的农场时，启动时不拉起自己的服务端；切回本机时再拉起。已经在跑的本机农场在切走以后照常运行。
- **一样的权限**：配对过的设备和主人一样用农场，不分只读。这些都是主人自己的设备。

## Alternatives considered

**把主监听改成 0.0.0.0，加一个全局令牌。** 改动最小，可是 `/mcp` 和网页也跟着出去了，令牌一旦泄露就没法只撤一台设备。拆成单独的监听，口子能收得更窄，每台设备一把钥匙也能单独移除。

**自签证书，指纹放在二维码里。** 二维码本身就是可信的带外通道，用它传证书指纹，客户端只认这张证书，就能防同一个网络里的人偷听。主人决定第一版不做：用明文 HTTP 加设备钥匙，页面上提示只在信得过的网络里开院门。

**Bonjour（mDNS）发现。** 电脑的 IP 变了，设备能自己再找到它。可是要在 iOS 上申请 Bonjour 权限，还要维护广播；家里路由器给的地址通常很久不变。主人选了最简单的做法：连不上就回那台电脑上重新扫码。也考虑过在二维码里多放几个候选地址（所有网卡的地址、`主机名.local`），同样没做。

**二维码里直接放长期钥匙。** 扫一下就能用，少一步主人点头。可是二维码被截图或者被旁边的人拍到，钥匙就漏了。一次性配对码加主人点头，漏出去的码没有用。

**分「只看」和「能指挥」两种设备。** 主人的设备不需要分，第一版不做。要做的话，加在设备上、由院门的中间件按接口拦。

## Consequences

- 规矩「服务端只听 127.0.0.1」多了第二个例外（第一个是语音线路）。它默认关着，只有主人打开、并且在这台电脑上同意过的设备才能进来。
- 院门走明文 HTTP：同一个网络里的人能看到传的内容，也能抓到钥匙去冒充那台设备，直到主人移除它。只在家里、自己的热点这类网络里开。
- 电脑换了网络，设备要重新扫一次码（钥匙不变，不用再点头）。
- 应用退出，农场就停了，用这个农场的设备也就连不上了。
- Flutter 多了 `mobile_scanner`，用来在手机上扫码；iOS 要声明相机和本地网络的用途，Android 要 `INTERNET` 权限和允许明文 HTTP。
