# Agent Note: 项目、每人一个 worktree，收获前先查冲突

Status: implemented

## Problem

帮工直接在主人的仓库里改，几个帮工同时改同一个仓库会互相覆盖，做坏了也难以撤回；主人要的是先看清改了什么、再决定要不要。最早的收获直接合并，有冲突时帮工被打发走，分支没人管。

## Decision

见 [server.md](../../../../docs/server.md)「项目和收获」，要点：

- 工作目录（`VIBEVALLEY_WORK_ROOT`）下的每个文件夹是一个项目，都是 git 仓库；派活必须指定项目，不存在就新建并做初始提交。
- 每个帮工在 `<工作目录>/.worktrees/` 下有自己的 worktree，分支 `vibevalley/<帮工>-<时间>`；帮工按规矩做完一轮就提交。
- 收获之前先看收成清单；合并前用 `git merge-tree --write-tree` 预检，会冲突就不合并，帮工留在地里，让它在自己的分支上把主分支合进来解决。
- 收工时有提交的分支留着，帮工做过的东西不会丢。
- 同一个项目里改仓库的操作排队一个一个来（两个帮工同时派到一个新项目时，`git init` 曾经撞在一起）。
- 工作目录的 `AGENTS.md` 是所有项目的约定，派活时附在帮工的说明里。

## Alternatives considered

**直接在项目目录里改。** 档案可以关掉 worktree，这时帮工直接在项目里改，没有分支可合；默认开着，因为几个人改同一个仓库时必须隔开。

**合并时遇到冲突再中止。** 要碰主人的工作区，中止失败还得收拾；`merge-tree` 不碰任何工作区就能知道会不会冲突。

**冲突交给主人在终端里解决。** 帮工最清楚自己改了什么，让它解决、跑测试、在结论里说怎么取舍，主人只看结果。

## Consequences

每个帮工的改动可看、可撤、可以一个个收；冲突不会弄脏主分支。代价是磁盘上多了 worktree 和分支，项目必须是 git 仓库，收获多一步确认。
