# Agent Note: 调用方交意图，模块拥有完整的协调

Status: implemented

## Problem

一个包只导出一个 Service，并不保证接口深。处理函数仍要先查工单、找最新执行、判状态、拼评论再送消息；收获调用方要安排停止写入、合并、离场。客户端两张皮各自拼历史、管理已读、判断何时加载轨迹。调用方必须知道这些顺序，模块只是把实现拆开。

[动作结果和生命周期](.agents/notes/implemented/architecture/2026-10-17-operation-results-and-lifetimes.md)修正了失败与竞态，但增加检查并没有自动减少这份接口负担。

## Decision

| 概念的拥有者 | 收回的知识 | 调用方现在交什么 |
|---|---|---|
| 工单 | 工单到最新执行的解析、关闭状态、评论上下文、消息递送 | 工单 id 和动作 |
| Session | 收获时停止写入、合并、冲突与离场 | 收获或合进目标分支 |
| 项目 | Git 发布与后续清理的不同结果 | 目录和目标；成功结果带清理提醒 |
| 农机 | 模型回退、effort、环境覆盖、缓存 token 单价和人民币换算 | 档案或用量 |
| 群聊 | 消息提交后发布、原子阅读回执、工单串创建与关注 | 一条消息、读到的位置、工单串意图 |
| agent 事件 | tag 与必填载荷的关联；工具和消息结果的可用字段 | 具体事件类型；`Kind()` 由类型计算 |
| Agent 完整运行 | 本轮与实例累计用量、未结束响应的已消费快照、结果与结算屏障 | 运行输入；读取 `Progress` 或 `AgentSettled.Run` |
| 管家输入 | 频道、档案、静默标记、语音流与队列项的绑定 | 内容和来源；入队不抢当前回复上下文 |
| 客户端数据 | 按档案的记忆、按 Session 的回放与增量、项目目录、聊天读取投影 | 观察对象 id 或声明当前可见频道 |
| 客户端通话和宿主 | 通话实例、原生命令分发、本机切换、手机前后台资源 | 通话动作、路由动作或本机选择意图 |

重复的推导也归回已有主人：MCP 使用 protocol 的阶段说明；API 生成器先绑定参数来源和线上名字，Go 处理函数、Go/Dart 客户端和能力元数据读取同一个绑定结果。没有第二个实现的持久化 Session 接口改成具体类型；没有生产调用者的旧原生语音宿主接口删除。

agent 事件使用开放的 `AgentEvent` 接口，核心循环提供具体载荷类型，上层 agent 的压缩和整轮结果实现同一接口。工具终态结果和消息增量是值；压缩无摘要是压缩结束事件自己的可选结果。生产者、核心归约、管家执行记录、CLI 与 smith Adapter 同时迁移，不保留字符串 tag 加可空大结构的第二条路。

Agent 的用量与结果归整轮运行所有者。已结束运行、当前已结束模型消息、当前 partial 三部分不重叠，最终模型消息替换 partial；关闭时先消费完循环发布的事件，再交付回执。CLI 每轮展示、smith 每个实例累计的口径保持。模型失败后同轮继续成功，结果有意改按最后模型成功结算，修正旧 Adapter 保留早先失败标记造成的误报；工具报错仍只是工具结果。

模块可以包含内部实现，但不把步骤重新暴露成一套配置。新增的抽象必须让实际调用点删除协调代码；仅搬文件、加同复杂度的转发层、补错误分支不算接口变深。

## Alternatives considered

**只补更多 guard。** 可以修当前失败路径，但新的调用方仍要记住同一套调用顺序；顺序和资源所有权留在拥有者内部，调用方不再复制它。

**把每个 callback、存储或消息入口都改成通用接口。** 只有一个实现时会增加导航成本。本次复用真实 Adapter 和已有测试设施，不为测试另造仓储或工作流框架。

**把迁移创建函数从命令行搬到 migrations 包。** 原函数已经隐藏命名和写入过程，同签名搬家没有减少调用方知识，撤回这项改动。

**只给原来的事件结构加构造器。** 仍能直接构造不匹配的 tag 和载荷，消费者仍要记住可空字段矩阵；没有删除接口知识。开放载荷类型同时允许上层添加事件，不要求核心包导入上层。

**只在 settled 时返回用量。** Dispose 可以发生在运行中，host 仍需自己扫描已收到消息。保留运行中的已消费快照，并让结束回执来自同一份归约。

## Consequences

行为测试跨完整动作验证：工单评论不需要测试先手工找 Session，消息写入不需要测试分别发布，客户端观察轨迹不需要页面先发一次加载。具体回归跟着拥有者包，跨模块调用的检查保留在集成测试中。

项目成功发布 Git ref 后，清理失败不再把已完成发布伪装成未合并；提醒保留清理范围。处理函数仍负责传输层错误码和展示语气，界面仍负责布局；它们不接管领域动作的中间状态。

核心事件的测试逐种验证 `Kind()` 和状态映射，并检查新增具体类型有对应消费用例；工具取消仍只产生一次终态，压缩映射分别验证有摘要和无摘要，避免把可选结果改成伪成功。
