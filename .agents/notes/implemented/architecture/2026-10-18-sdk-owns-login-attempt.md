# Agent Note: 扫码登录由平台 SDK 拥有

Status: implemented

## Problem

微信 SDK 只暴露取码和查状态，连接器自己持有二维码、重定向域、8 分钟期限、刷新次数和验证码规则。飞书 SDK 只暴露注册和轮询，连接器解释 device code、间隔、有效期以及 Feishu 到 Lark 的域切换。新增调用方需要复制平台登录协议。

## Decision

两个 SDK 各自提供一次 `Login`：进度回调只含给人看的二维码和阶段，成功返回最终账号。微信原始 QR 状态、飞书注册和轮询结果收为包内实现；连接器不再接触这些中间形状。

微信保留等待、已扫码、输入数字三种进度，过期或验证码被禁用累计三次后结束。飞书按注册返回的 interval 和 expires 等待；SDK 更新当前租户域。请求和等待都属于同一个 context，取消后不返回成功账号；飞书的 AppID 或 AppSecret 为空时也不能成功，缺少主人 OpenID 仍交给现有配对流程。

这不替换[账号代际](2026-10-18-connector-inbox-and-generation.md)：代际仍决定何时取消旧登录、何时保存新账号。SDK 只拥有一次登录的协议，不碰农场数据库和频道。

## Alternatives considered

**只把两个循环改成连接器包内 helper。** 调用方仍必须取得并传递原始 SDK 状态，平台规则没有回到其拥有者。

**给三个平台增加通用登录状态机。** QQ 使用已有 AppID 和密钥，微信需要验证码和二维码刷新，飞书按租户域轮询注册；统一可配置流程会把差异变成更多配置，保留各 SDK 的真实协议。

## Consequences

连接器的登录 Adapter 只映射页面进度和最终账号，SDK 外不再有 QR 状态字符串分支或注册租约计时。持久化的账号字段和页面叫法不变，飞书未提供主人 OpenID 时仍由现有配对流程确认主人。

## Verification

- 本机 HTTP/TLS 假端点验证微信重定向、验证码、两次换码、第三次过期终止、取消正在进行的轮询。
- 飞书假端点验证轮询间隔、Lark 域交接、取消、过期前停止轮询及拒绝登录。
- 连接器测试验证三种微信 SDK 进度和最终账号的映射，以及既有三平台收发、重启和账号代际行为。
- 不登录真实外部账号，不调用付费模型。
