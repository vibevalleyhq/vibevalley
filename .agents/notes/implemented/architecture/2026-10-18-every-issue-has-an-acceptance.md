# Agent Note: 一块地就是一张工单，每张工单都有验收

Status: implemented

## Problem

农场画的地原来跟着帮工走，工单交回来就画成「熟了、可收获」：帮工说做完了，地就结果了。主人想要的是一块地就是一张工单，按「聊清楚、安排活、完成」三段走：

- **「交回来」和「做完了」分不开。** 帮工交回来只是这一轮停了，活合不合格要有人看过才算。没有这一关，「结果」就只是帮工自己说的，看板上也分不出「等你看」和「可以收了」。
- **帮工缺信息时没有地方说。** 它卡在一个要主人定的问题上，只能写在汇报里，地上看不出来；主人回答了，也没有东西记着「问题答了」。
- **一块地不一定是代码活。** 写周报、查账单也是一张工单，也是一块地；只有代码活才有 worktree。

设计稿在 `design/issue-farming/index.html`（三段、九个样子、农活、地上的人、验收、地块详情）。

## Decision

**一块地就是一张工单；代码相关的带一个 worktree。每张工单都有一道验收，过了才算结果。** 工单的六个状态不变，`in_review` 的意思收窄成「等验收」；只在工单上加四样东西。行为见 [server.md](../../../../docs/reference/server.md)「工单」，农场的样子见 [farm-ui.md](../../../../docs/reference/farm-ui.md)「地里长什么」，用语见 [concepts.md](../../../../docs/concepts.md)「农场是皮」。

| 加的 | 是什么 |
|---|---|
| `Issue.Acceptance` | 验收方式：`glance`（默认，主人收获本身就算验收）或 `required`（没验收通过不能收获） |
| `Issue.AcceptedAt` | 验收通过的时候；新的一轮开始就作废 |
| `Issue.Findings` | 草：没过验收的意见，一条一棵；下一次验收通过才拔 |
| `Issue.Asks` | 缺肥：帮工汇报里「要问主人：」的行；主人带一句话就算回答 |

- **验收的接口**：`issue.accept`（`POST /api/v1/issues/{id}/accept`）。通过记下 `AcceptedAt`、拔掉所有的草；没过至少要一条意见，记成草，再把还没拔的草编号写成一句话交给帮工，接着修一轮（和评论同一条路）。只有等验收（`in_review`）的工单能验，派给管家的、种植计划里的不能。
- **收获的关卡在转换表里**：`statusMove` 里 `in_review → done` 在 `required` 且没通过时拒绝，`moves` 里也就没有 `done`；看板、地块详情、管家的 `merge` 都照它。`glance` 的工单不挡，主人点收获就是看过了。
- **管家也能验收**：工具 `accept`。它判过没过，过了只是能收获，收获照旧要主人说一声（`merge` 的老规矩）。
- **缺肥从汇报里读**：农场的规矩教帮工把「缺信息、要主人定的」写成「要问主人：」开头的行；`readReport` 读出来放进 `FactReport.Asks`，工单服务记到 `Issue.Asks`。下一轮汇报照它的新问题改写，主人的评论清掉。
- **地的样子按工单算**：`protocol.PlotOf(session, issue)`。交回来以后先看缺肥（干裂），再看验收过没过（结果）、草（杂草，修的时候是「除草中」），都没有就是开花、「等验收」；新牌子的色调是 `wait`。
- **地块详情**（`shared/issue_view.dart`）按三段排：最上面一条进度轨（聊清楚、安排活、完成），接着「这块地现在需要你」只放一件事（施肥、验收、收获），下面是地上的人（做过这块地的帮工、锄头在谁手上）、验收方式、草。写工单的表单里能选验收方式。

## Alternatives considered

**验收按工单选有没有。** 小改动省一步，但「交回来」和「做完了」又分不开了，地的阶段也没法标。所以验收每张都有，按工单变的是谁验、怎么验：最轻的 `glance` 就是主人看一眼收下。

**加一个「等验收」状态。** 和 `in_review` 是同一件事，多一个状态，看板、转换表、管家的说法都要跟着加；把 `in_review` 的意思说清楚就够了。

**缺肥让管家读工单串来判。** 不用帮工照格式写，但要调模型、会判错；帮工自己最清楚它缺什么，一行固定的开头就能读准。

**草按条单独拔。** 更细，但要知道帮工这一轮修了哪几条，汇报里读不准；先整批：下一次验收通过就都拔掉，没过的意见会再写进来。

## Consequences

- 每张工单在 `in_review` 时，地块详情顶上都有「验收」这一块；`glance` 的写明直接收获也行。
- 管家的工具多了 `accept`，`merge` 多了一道关卡；管家的提示变了，下次改管家时要真模型跑一遍样例（`verify-manager-evals`）。
- `issue` 表多了 `acceptance`、`accepted_at`、`findings`、`asks` 四列（直接改基线，本机的旧库作废）。

### 还没做的

- **几个人一起种**：@ 谁就让谁下地、分工（主种、帮手、看地的），锄头交接。现在「地上的人」只列做过这块地的帮工，锄头在现在干活的那个手上。
- **派一个看地的**：另一个帮工读验收标准和改动、逐条打勾，再调 `accept`。现在验收是主人或管家。
- **验收标准**：聊清楚时写下几条，验收时逐条打勾（设计稿第五节）。
- **农具**：肥料袋（施肥）和稻草人（验收）的贴图和工具栏；现在施肥是带话，验收在地块详情里点。
