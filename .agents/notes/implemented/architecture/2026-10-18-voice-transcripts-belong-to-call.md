# Agent Note: 电话的字幕归这通电话

Status: implemented

## Problem

主人字幕由管家按当前设置决定是否旁听，快嘴字幕却按通话开始时的模式记录。中途修改「谁接电话」，同一通电话的两种字幕会按两份规则分流；客户端也必须知道两条入口各自需要什么身份。

## Decision

`voice` 拥有两种字幕的接受与分流，按 `agentId` 找到通话建立时的模式。管家只接受已经确定要旁听的一句话，不再读通话配置。挂断开始时终止字幕资格，即使声网暂时停止失败，保留重试资源也不重新接收字幕。

当前协议见 [语音参考](../../../../docs/reference/voice.md)。v1 的无通话编号入口仍由同一个所有者适配，只在能唯一绑定一通电话时接受；它是旧客户端入口，不涉及旧持久化格式。

## Alternatives considered

**客户端读设置再决定要不要转话。** 设置不是当前通话的模式快照，客户端同样会受中途修改影响，还会重复服务端规则。

**删掉原 v1 入口。** 已配对设备可能还在旧版本；保留受限适配，新的明确身份入口负责全部新客户端。

## Consequences

两种字幕只依赖建立通话时的决定。声网的启动请求返回前收到的字幕，客户端暂存到取得通话编号后再发；取消通话会清掉它们。没有身份的旧客户端不能同时操作几通电话。

## Verification

服务端测试覆盖两种模式中途互换设置、挂断失败后的字幕拒绝、旧入口零个/一个/多个有效通话；客户端测试覆盖启动时字幕等待编号以及挂断后的迟到字幕。
