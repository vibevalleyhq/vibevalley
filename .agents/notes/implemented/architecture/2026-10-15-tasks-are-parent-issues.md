# Agent Note: 种植计划是带子工单的父工单

Status: implemented

## Problem

种植计划（`Task`）是和工单并排的另一样东西：它整张放在核心状态的 `tasks` 里、存在 `state.json`，每一步是计划里的一个节点。派出去做某一步的帮工，又各自开一张工单；拆计划的帮工也开一张。于是看板上同一件事有好几个样子：计划卡、拆计划的那张工单、每一步各一张工单，它们之间只靠帮工身上的标签连着。

照 [概念先行](../../proposed/architecture/2026-10-15-concepts-first.md) 第 6 步，计划就是 Linear 里带子工单的父工单：子工单之间有先后（blocked by），合进父工单的分支，最后父工单合进主分支。

## Decision

行为见 [server.md](../../../../docs/reference/server.md)「工单」「种植计划」。

- **计划是父工单，每一步是子工单**：父工单的 id 就是计划的 id（`p1`……），标题和说明是计划的标题和目标，多一块 `task`（计划的状态、计划分支、并行数、一句说明）。每一步是一张子工单，id 是 `<计划>.<步骤>`（`p1.api`），`parent` 指向父工单，`blockedBy` 是它要等的子工单，标题和说明是步骤的标题和工单，`step` 里是步骤的其余部分（状态、检查命令、该改的地方、是不是验收、冻结的文件、谁在做、结论、提交、花费、重试和失败的次数）。
- **执行挂在工单下面**：拆计划的帮工是父工单的一次执行，做某一步的帮工是那张子工单的执行，和普通工单一样。
- **计划的规则不变，读写换成工单**：protocol 的 `task.go` 仍按整张计划算（能开工的步骤、改计划、交给帮工的话、验收……）。`TaskOf`、`TasksOf` 从核心状态里的工单把计划拼出来，`TaskIssues` 再拆回工单（`task_issues.go`）；服务端的 `Tasks` 每写一次计划，`Issues.PutTask` 就在一个事务里写整家工单，先发子工单的事实、最后发父工单的，计划在核心状态里总是完整的。没有了 `task` 事实，`CoreState` 里也没有了 `tasks`。
- **状态跟着计划**：父工单在拆、在做时是 `working`，等你看、暂停、做完等收获是 `waiting`，收了或放弃了就关上（`merged`、`dismissed`）。子工单没轮到是 `todo`，在做看它的帮工，没做成是 `waiting`，合进去了关成 `merged_into_task`，跳过或计划放弃了关成 `dismissed`。帮工离开不会关计划的工单，看板也不能改、开工、重开它们，都在计划里做。
- **客户端**：帧上多了 `tasks`，是服务端拼好的计划（新的在后），计划板和农场读它。看板上计划是一张卡（就是父工单），子工单有人做过才出现，标题前加计划名。
- **老数据**：开机时把 `state.json` 里的计划变成它们的工单（`Issues.adoptTasks`），把从前拆计划、做步骤的那些工单的执行挪过来，删掉那些工单；`state.json` 当时的样子另存为 `state.json.tasks`。只做一次：父工单已经在了就跳过。

## Alternatives considered

**计划留在核心状态，工单只记它属于哪个计划。** 改动最小，但同一件事还是两份：计划节点的状态和那一步的工单各记一份，得靠代码保持一致。

**把计划的规则也改成按工单写。** 一千多行规则和它们的测试、黄金数据要全部重写，换来的只是少一次拼装。拼装是纯函数，两头都测，先这样；以后要改名、拆包时再看。

**子工单用新的随机 id。** 和普通工单一样，但计划的规则、管家的工具、计划板都用步骤的 id（`api`），每次都要查一遍对应。用 `<计划>.<步骤>` 一眼就看得出是哪个计划的哪一步。

**核心状态只留最近 50 张关了的工单时不管家人。** 关了的子工单可能先被挤掉，留下的计划就缺步骤。所以只按没有父工单的数，子工单跟着父工单留、跟着父工单走。

## Consequences

- 看板、计划板、地图、管家看到的计划和工单是同一份数据。
- 计划在数据库里有了家，不再占 `state.json`；关了的计划和普通工单一样，核心状态只留最近的。
- 一次写计划要写整家工单（最多 13 张），发多条事实；没变的不算变化。
- 黄金数据（`reduce.jsonl.gz`）里去掉了 `task` 事实；`play.jsonl.gz` 里录下的计划和 `task` 事实，测试时换成它们的工单再算。
