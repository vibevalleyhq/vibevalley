# Agent Note: MyGo 与 Go 后端最小通路

Status: implemented

> 已被取代：MyGo 桌面版（`apps/mygo`）随 [一个服务端、一个客户端](../simplification/2026-10-14-one-server-one-client.md) 删掉了；Go 服务端留了下来（[服务端用 Go 重写](2026-10-13-go-server-on-smith.md)），桌面宿主换成了 Flutter（[客户端迁到 Flutter](2026-10-13-flutter-client-over-ts-server.md)）。下面是原型当时的决策。

## Problem

MyGo 迁移报告的判断仍缺少真实 VibeValley 页面在 WKWebView 中运行、Go 接口与现有前端协议连接，以及带前端资源包体的实测。

## Decision

在 `experiments/mygo` 建独立原型（后来挪成 `apps/mygo`，后端换成了真的 Go 农场，见 [服务端用 Go 重写](2026-10-13-go-server-on-smith.md)；`apps/mygo` 已删，见 git 历史），固定 MyGo v0.4.6，不更改现有 Electron 和生产后端。一个 Go 进程绑定 loopback 随机端口，提供内嵌 Web 资源、SSE 快照和田头回声。聊天先保存到独立原型文件，再推送；样本由 production protocol 生成，开发期用原协议解码器检查 Go 输出。

原型不使用真实模型、Agora 原生 SDK、oar/pi、PGlite或正式农场目录。未实现的接口明确拒绝。它验证换运行容器与协议接线，而不是宣称业务迁移完成。

## Alternatives considered

**只跑 MyGo hello-world。** 不能验证实际前端资源、Pixi 和现有协议。

**第一步移植所有服务端和语音。** 无法隔离 WebView、协议与 SDK 适配问题，也无法迅速得到最小可用证据。

## Consequences

本机 `.app` 约 28 MiB，DMG 约 18 MiB；这只是现有前端与最小 Go 后端的基线，不是完整产品体积。Go 使用生成样本上的动态 JSON 操作，不作为正式类型系统迁移方案。

## Verification

Go 单元测试、生产 TS 协议校验、无 cgo 构建通过。真实 MyGo macOS 窗口能显示聊天和 Pixi 农场；从窗口输入验收消息后，页面收到 Go 本地回声。重载存档通过 Go 单元测试；未宣称完成 GUI 重启、持续性能或原生语音验收。
