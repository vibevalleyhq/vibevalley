# Agent Note: 官网放在 site/，用游戏自己的图，会动的部分是 React

Status: implemented

## Problem

项目要开源，主人注册了 vibevalley.dev，要一个游戏官网：一眼看出它是什么，好看、能传开，像游戏官网那样有视差，还要有一部分像样的动画。官网要用的图（首页的场景、帮工、图标、截图）和像素字都在 `app/` 里；单独开一个仓库或另存一份图，游戏改了画面官网就旧了。主人要样式用 Tailwind、动画用 React。

## Decision

- **一页静态网页，在仓库的 `site/`**：Astro 生成，Bun 管依赖和命令（`bun run site:check`、`bun run site:build`）。中文在 `/`，英文在 `/en/`，文字在 `site/src/i18n/` 两份同形状的字典里，类型查两边是否对齐。地址不对时给一页两种语言的 404。
- **样式用 Tailwind（v4，经 Vite 插件）**：游戏的主题写在 `site/src/styles/global.css` 的 `@theme`：颜色、字体、没有模糊的硬阴影、首页场景的动法。组件上只写 utility。几样 utility 写不清的自己定义：
  - 游戏的面板 `panel`；
  - 按 `<html data-scene>` 的时辰变体 `night:` 等；
  - 照时辰调光的 `lit-*`。每个时辰的滤镜写成同样几项、同样顺序，换时辰时光能渐变。
- **会动的部分是 React island，动画用 Motion**：顶栏和各段是 `site/src/components/*.tsx`，由 `Home.astro` 放进页面。构建时和别的部分一样渲染成完整的 HTML，没有脚本内容也都在。浏览器里，顶栏和首页的场景等页面加载完就接管（场景不等脚本就在、就动，背景图不该排在脚本后面），下面几段快滚到时才接管。不做每次请求的 SSR：动画都在浏览器里，页面没有要按请求变的东西。
- **一直在动的留给 CSS，跟着页面动的交给 Motion**：
  - CSS：云、炊烟、萤火虫、花草、帮工走路，不靠脚本。横穿场景的只动 `translate`（距离用 `cqw`、`cqh`），交给合成器，不动 `left`、`top`。整段出了屏幕，它的动画就停。
  - Motion：
    - 视差，滚动加带弹簧的指针，见下一条；
    - 「怎么玩」跟着滚动讲故事：这一段停在屏幕上，镜头沿田横着走，各层快慢不同。帮工在四个地方各干一步的活：看工单、播种、敲锤子（冒出工具图标）、收获（金币、完成章）。地方和时机写在 `site/src/lib/story.ts`，没有脚本时是长好的田和四张卡片；
    - 换时辰：新的背景淡入，旧的垫在下面；
    - 段落滚到时一格一格地进场；
    - 截图点开放大；
    - 复制按钮的反馈。
- **跟着滚动的用 Motion 的 `scroll()`，只动 `transform` 和 `opacity`**（`useScrollLinked`）：浏览器有滚动时间线时，Motion 把动画挂在原生的 scroll 或 view timeline 上，在合成线程里跟滚动同步；没有时，Motion 用脚本跟。
- **卖点是一种日子：写代码，如收菜**：页面先讲这个，功能放在后面。
  - 首页占两屏，第一屏的滚动里场景钉在屏幕上，走完一天：清晨、白天、傍晚、夜里的背景按滚到的位置一层层叠上去（渐变，往回滚就褪掉），每个时辰一句押韵的话，镜头慢慢推近。
  - 第二屏整个场景滚走，后面是第二天清早的金色横幅「一觉醒过来，满园都是菜」。
  - 中文都押「菜」的 -ai 韵，五言两句；英文两两押韵。
  - 开场固定是清晨：要让每个访客都走一遍这一天，不再按访客的钟点挑。右下的时辰按钮把页面滚到那个时辰的那句话。
- **视差靠各层的快慢和游戏自己的前景，不切画**：首页的画还是一整张，滚动时只走页面一半的速度。
  - 比它更慢的是云；比它快的是底下的花草，和最前面一层游戏里给村子画面镶边的树枝、灌木（比页面还快）；
  - 管家和狗跟画同一层；
  - 文字比页面快，并且淡出。
  - 近的层只会越过远的层往上走，层边不会露出后面。
- **没有脚本、减少动画时都完整**：
  - 进场只藏还在屏幕下面的部分，脚本醒来后才藏，所以没有脚本时不藏。
  - 那条田构建出来就是长好的样子，脚本醒来后才变回空地、等帮工走过来。
  - 系统要求减少动画时，CSS 动画停在原处，Motion 不动。
- **大图在构建时压缩，只压官网的副本**（`site/src/lib/images.ts`，Astro 的图片服务）：
  - 首页的背景和场景贴图转成 WebP，尺寸不变；截图转成几种宽度的 WebP；分享卡片保持 JPEG。
  - `app/assets` 的原图不动，游戏照样用高清原图。
  - 首页背景在 `Base.astro` 开头按时辰预加载；首页以下的图滚近了才加载。
- **不另存游戏的图**：
  - 场景、图标、帮工的帧、地块、农机的 logo 都从 `app/assets/` import，截图从 `docs/images/`（README 也用它们），构建时复制成带 hash 的文件。
  - 图的地址在 `Home.astro` 里算好、传给 island，所以 island 的脚本里不带图的清单。
  - 像素字太大（5 MB），每次 check、build 之前由 `site/scripts/prepare.ts` 裁成网页用到的字，连同应用的图标和字体的授权放进 `site/public/gen/`（不进 git）。
- **页面讲三件事**：
  - 「写代码，如收菜」：首页的一天，和天亮时那条收菜的横幅；
  - 一件活怎么种出来（滚动的故事）。田下面画它的 git 分支：分出来、提交、合回 main，计数往上跳；金色横幅里是同一件活的收成单。地块就是分支，收菜就是合并，画出来比字说得清楚；
  - 一排往上数的农场数字（4 台农机、28 种帮工、6 块地、21 个成就、5 个小游戏、3 个聊天软件），都是游戏代码里的真数（`site/src/lib/facts.ts` 注明出处），不放使用量这类没有来源的数；
  - 在哪都能看农场：Flutter 写的同一套界面，Mac 跑农场，iPhone、安卓经院门连进来。手机版要自己构建、院门只在信得过的网络里开，照实写在旁边。展示的是真截图：Mac 上的农场，手机上的田头和工单。手机上的农场画面还小，不拿来展示。
- **首页就是游戏的首页**：清晨、白天、傍晚、夜里四张背景，开场只下载清晨那张，页面一动再加载另外三张；云、炊烟、花草、蒲公英的种子、萤火虫、管家的姿势和狗的动法照游戏画（搬自当初网页版首页的 CSS，游戏的 Dart 也是照它移植的），摆放的数在 `site/src/lib/scene.ts`。
- **不开 `astro dev` 当检查**：`check` 再 `build`；要看样子，用静态服务器打开 `site/dist/`。
- **放在 Cloudflare，一个只有静态文件的 Worker**：
  - vibevalley.dev 的 DNS 本来就在 Cloudflare，自定义域名写在 `site/wrangler.jsonc`，发布时 Cloudflare 自己加解析和证书。
  - 主人在本机登录 wrangler 后，用 `bun run site:deploy` 发布。

## Alternatives considered

**单独开一个仓库。** 官网自己发版方便，但要另存一份游戏的图和字，游戏改了画面官网不会跟着变。

**用 Flutter Web 把游戏的首页直接搬上网。** 画面完全一样，但包大、首屏慢，字是画出来的，搜索引擎读不到。

**每次请求都在服务端渲染（Astro 的 SSR 或 Next.js）。** 搜索引擎和首屏拿到的 HTML，和构建时渲染的一样；动画也一样在浏览器里跑。它多出来的只有按请求变的东西，比如按 IP 的时区挑时辰、实时的 star 数，这一页都用不上。代价却要每次访问都跑一次服务端，比放在边缘的静态文件慢。Next.js 还要经 OpenNext 才能上 Cloudflare，对一页官网太重。以后真有要按请求变的页，Astro 能单独给那一页开。

**整页一个 React 应用。** 写法统一，但没有脚本时什么也没有，首屏要等脚本。island 只让会动的部分带脚本，别的部分构建完就在。

**手写 CSS（第一版就是这样）。** 一千多行，类名和样式两处来回找；主人要 Tailwind。Tailwind 把游戏的主题收在一处，组件上一眼看出样子。

**动画全用原生脚本、CSS 的滚动驱动动画，或 GSAP、Lenis。** 原生脚本只有几 KB；CSS 滚动驱动动画 Firefox 还不全。主人要 React，Motion 是 React 里最顺手的：带弹簧的值、跟着滚动的值、图从原处长出来的放大，都是现成的。代价是页面的脚本从几 KB 变成约 130 KB（gzip，React 和 Motion 占大头），不过图仍然是页面的大头。

**把首页的画按远近切成几层（天、远山、山谷、近坡）。** 真正的纵深，近坡升起来盖住山谷。代价是要给四个时辰的画各切一遍：
- 试过用颜色的变化加动态规划找天际线，四张画细节各不相同，有的时辰切在山脊上，有的跑到山谷的树上；
- 切歪的地方，层一错开就把东西撕成两半（风车、灯塔）；
- 后层被前层挡住的地方还得补画。

快慢分层加游戏自己的前景，已经有明显的纵深，又不碰画。

**GSAP（ScrollTrigger）。** 编排一段钉住的滚动叙事很顺手。但它也是主线程每帧读滚动、再挪元素，同样会比合成器的滚动晚一帧；看着顺，主要是 `scrub` 把滚动平滑了。再加一个库就是两套动画写法。Motion 的 `scroll()` 能交给浏览器原生的时间线，又已经在用；主人也定了用 Motion。

**自己写 CSS 的滚动时间线（`animation-timeline: scroll()`）。** 效果一样在合成线程上，但不支持的浏览器要另写一份脚本，两处都得维护。Motion 的 `scroll()` 自己判断用不用原生的，一种写法。

**压成 AVIF。** 比 WebP 再小三成，但放大看更糊，手机上解码也更慢；WebP 在这些图上看不出差别。

**整个像素字一起发。** 5 MB，首屏太慢。裁剪以后十几 KB；加了字要重新裁，check 和 build 前自动做。

**Cloudflare Pages，或 GitHub Pages。**
- Pages 的自定义域名要在面板里点，Cloudflare 也把新项目引向 Workers 的静态资源。Worker 的配置能写进仓库，一条命令发布。
- GitHub Pages 在仓库公开以前用不了，而且域名的 DNS 本来就在 Cloudflare。

## Consequences

- 游戏首页的场景（`app/lib/shell/title/`）和官网（`site/src/lib/scene.ts`，动法在 `global.css` 的 `@theme`）各有一份摆放的数：改了一边，另一边跟着改。
- 截图在 `docs/images/`，README 和官网共用；界面变了用 `app/tool/screens/live_screens_test.dart` 重拍。
- 官网上的 GitHub 链接在仓库公开以前打不开。
- Tailwind 只认源码里完整的类名：按时辰拼出来的类（`night:opacity-100` 这种）要写成完整的字符串表，不能拼。
- 发布要主人在本机登录 wrangler；没有按分支的预览地址。
- 农场的数字（`facts.ts`）是抄来的：游戏里加了农机、成就、小游戏，要记得改这里。
- 「怎么玩」的故事在构建时就按它的全高渲染：要是先放短的、醒来再换成故事，醒来时页面会突然变高，点导航跳到它下面的段落会被推走（截图时撞见过）。
- Firefox 没有滚动时间线，跟着滚动的动画在那里由 Motion 的脚本跑，主线程每帧有一点活。
- 页面用到的场景贴图要列在 `images.ts` 的导入清单里：导入了却没做副本的原图会留在构建里，代码里也别读导入的图的属性，读了 Astro 就会把原图一起发出去。

## Verification

- 检查和构建：
  - `bun run site:check`：`astro check` 没有错误；`bunx tsc --noEmit` 通过。
  - `bun run site:build`：三页生成到 `site/dist/`，站点地图里没有 404 页。
- 用 Chrome 无头模式（puppeteer）截图看过：
  - 四个时辰的首页，和手写 CSS 的版本并排比过。
  - 1440 宽的整页和 390 宽的手机，都开着减少动画。
  - 「怎么玩」的故事在 6 个滚动位置截过图，1440 宽和 390 宽都有：走路、看工单冒气泡、播种、敲锤子冒工具图标、收获冒金币、盖章，下面的说明跟着换。前景的草起初挡住了收获时的帮工，压低缩小以后只在脚边。
  - 两屏的首页：在第一屏的 0、25%、50%、75%、100% 和第二屏一半处截图量过。傍晚那张的不透明度依次是 0、0.39、1、1、1，夜里那张是 0、0、0、0.66、1；光和姿势在 30%、70% 换；文字到 25% 时剩 0.16。手机上也看过。
  - 首页往下滚 0、200、400、600 px 各拍一张，又录了一段滚动和指针绕场景一圈的视频：画走页面一半的速度，文字先走并淡出，前景的树枝和灌木最快；手机上和减少动画时也看过。
  - 截图放大后焦点在关闭按钮上，Esc 能关，关后焦点回到原处。
  - 控制台没有报错，也没有 hydration 的报错。
- 卡顿：用 Chrome 的追踪量了静止 3 秒和整页平滑滚动 11 秒，改成 `translate`、交给 Motion 的 `scroll()` 前后各一次，也在 CPU 降速 4 倍时各量一次：
  - 静止：每秒排版从 60 次降到约 0，重绘从约 650 次降到约 3，主线程占用从 13% 降到 8%（降速 4 倍时从 37% 到 24%）；
  - 滚动：重绘从 7516 次降到 915 次，主线程占用 13% 到 12%（降速 4 倍时 39% 到 27%）。
  - 跟着滚动的动画都挂在 ViewTimeline 上：首页四层各两段（推近、滚走），加上文字、往下看的提示、两张背景，共 13 个，田埂醒来后再加 2 个。
- 图片：构建出的图从 8.5 MB 降到 3.4 MB（其中 0.36 MB 是只给分享卡片用的 JPEG），一次访问下载 1.1 到 1.3 MB（原来 4 到 5 MB）。Lighthouse 在本机：桌面从 90 分到 95 分，LCP 从 2.1 秒到 1.5 秒；手机（模拟慢 4G）LCP 从 12.1 秒到 8 秒左右。手机上的 LCP 是前景框的树枝：铺满整屏的背景，Chrome 当背景不算 LCP。
- 发布：`bun run site:deploy` 发到 vibevalley.dev。`/`、`/en/`、乱写的地址给 404，`_headers` 不对外，带 hash 的文件一年缓存，图是 WebP。
