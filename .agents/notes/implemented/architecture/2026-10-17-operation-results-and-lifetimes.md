# Agent Note: 动作结果和资源生命周期由拥有它的模块保证

Status: implemented

## Problem

模块已经按概念分开，调用方仍承担隐含顺序：计划保存失败后继续叫醒执行，定时写入失败后仍派发，配置先改内存再存盘。客户端有一个连接入口，却只保存最后一条 SSE 的关闭句柄；多个配置写入入口各自维护档案分类和请求顺序。

这些错误发生在步骤之间，纯函数测试和成功路径不能证明动作的承诺成立。

## Decision

- **提交结果属于动作本身。** 计划的保存错误沿动作返回，自动推进将错误转成提醒；保存成功后才执行依赖它的通知、叫醒、清理。定时先保存运行时间，记忆的一轮写入用事务，档案和设置先保存再发布内存结果。底层返回的错误不能在转发时变成成功。
- **容量和资源由持有者收尾。** 派活的接纳约束在 Session 内检查；关联失败释放新开的执行资源。连接拥有全部活动流；语音线路拥有隧道、通话钥匙及空闲定时器，停止和过期回调不能重新取得资源。
- **异步结果由一个落点接纳。** 客户端配置刷新使用代次，读取期间的农机推送保留；所有档案写入经过同一归一化。院门的持久化和监听状态在同一个互斥区更新，设备注册请求时重新检查是否已被移除。
- **验证穿过实际接缝。** 数据库写入故障注入验证失败后的副作用；并发测试验证容量和局部设置；客户端双流测试用本机 HTTP 对端，避免 FakeServer 绕过生产连接实现。沿用已有替身，不新增通用工作流或存储框架。

当前行为分别见 [服务端](../../../../docs/reference/server.md)、[客户端](../../../../app/README.md) 和 [架构](../../../../docs/architecture.md)。这补充了[收敛接缝](2026-10-17-converge-the-seams.md)，不改变 Go 拥有核心状态和计划由父子工单组成的决策。

## Alternatives considered

**只在 HTTP 入口检查失败。** 计划自动推进、定时与管家不都经过 HTTP；修复落在拥有动作的模块里，所有调用者得到相同结果。

**把 Git、SQLite 和执行启动包成一个事务。** 它们没有共同的提交机制。Git 已合并而数据库保存失败时明确报告已发生的操作，保留分支结果；不能用一个事务名字掩盖跨资源失败。

**为每个小步骤新增接口。** 这会把顺序要求推回调用方。已有动作和生命周期入口足够；内部增强不变量，测试沿同一个入口施加故障。

## Consequences

写入失败不再假报成功，代价是调用方需要展示真实拒绝或允许重试。文件和数据库锁覆盖完整读改写，避免同时返回成功却丢失其中一次更新。外部 Git 操作与状态保存仍非原子，失败文案保留实际完成范围。

回归测试分布在各拥有者包内，故障、取消和并发的断言与修复一起维护；真实服务端和客户端验证沿用现有验证 skill。
