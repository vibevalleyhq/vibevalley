# Agent Note: 子进程发布自己的就绪地址

Status: implemented

## Problem

桌面启动器先绑定端口 0、读出端口、关闭监听，再把端口给服务端；端口被抢走时换一个重试。验证脚本则让服务端用端口 0，但从人读的日志里用正则找地址。两个宿主都在重建本来只有子进程知道的绑定结果，日志措辞也变成了隐式协议。

## Decision

服务端的监听与工作区就绪后，`--ready-json` 模式向 stdout 写一次 `ServerReady` 收据，带实际 URL 和进程 PID。形状由 Go 定义并生成 Dart；普通日志仍在 stderr 和日志文件里。

桌面启动器和验证 sandbox 都把端口交给服务端分配。只有本次子进程的收据才确认就绪；其他 stdout 保留为日志。启动失败或没有收据，宿主释放自己启动的进程。桌面从准备环境开始就共用一个启动任务；退出标记阻止准备结束后再生成进程。生成进程前登记同一个启动器，退出只调用它的 `stop`，连还没完成的 spawn 也等待并释放，不留待就绪后的资源登记空窗。连接外部服务端的入口不经过这个协议。

## Alternatives considered

**统一解析日志。** 少写一种输出，但仍要求日志格式稳定；绑定地址这个事实应该有明确形状。

**保留桌面的预选端口与重试。** 先关闭再重绑无法保有端口所有权，重试次数也成为调用方不该承担的配置。

## Consequences

启动器不再有选端口回调或换端口重试。Bun sandbox 仍用健康接口验证已公布的地址，并保存收据作证据。这里的收据只解决进程间启动事实的交付；监听、工作区和请求生命周期仍由已有服务端 owner 管理。

## Verification

- 桌面替身实际绑定随机端口；日志噪声不会被当作收据，无收据或 PID 不符会超时并杀掉子进程。
- 提前退出保留原因，不重复启动；拒绝 SIGTERM 的子进程最终被回收；等待收据时退出以及 spawn 尚未完成就取消都不会遗留子进程；真实 host 通道测试覆盖并发启动与准备中退出。
- sandbox 用真实服务端发布的收据完成健康和工单断言，结束后清理进程组和临时目录。
