# Agent Note: 贵的东西藏在模块后面，测试分层、有预算

Status: proposed

## Problem

服务端的测试顺序跑现在是 107 s（上一轮从 210 s 降下来，[foundation](docs/subsystems/foundation.md)「为什么这样」）。再看一遍 CPU profile 和计数：

| 去向 | 约 | 从哪来 |
|---|---|---|
| 空闲：等 git 子进程 | 25–35 s | 2175 次 git，`worktree`、`commit`、`rev-parse`、`show-ref`、`symbolic-ref` 最多 |
| 空闲：计时器、轮询、`settle` | 10–20 s | 测试真等后台的窗口，`until` 每 10 ms 问一次 |
| PGlite | 30 s | 49,521 条查询；`ConversationByID` 6036、`MessageByID` 3733、`ReadCursor` 2690、`Participants` 1728，一条消息把会话、参与者、已读位置又读一遍；约 2900 个事务 |
| 起子进程、文件 | 10 s | 跟着 git |
| Effect 和业务代码 | 7 s | 不值得动 |

慢和难测是同一个根子：调用的人直接碰到了贵的东西（墙钟、库、git、真等），而不是由拥有它的模块挡在接口后面。测试也没有分层：什么都搭一整座农场，有窗口的就真等，写测试的人不知道一个测试该花多少。

## Proposal

**一个原则：每个模块对它的贵东西负责，对外给便宜、好测的接口。**

| 贵的东西 | 谁管 | 对外给什么 |
|---|---|---|
| 时间 | `Clock`（已做） | `Time`；测试里时间是虚拟的 |
| 存储（PGlite） | 拥有那张表的模块 | 内存里的读模型，写穿到库；库是持久层，不是每次读的地方 |
| 外面的世界（git、进程、网络、模型） | 一个端口 | 生产是真的；测试是便宜的真货（git 模板）或假的（模型、网络） |
| 等待 | 发布事件的模块 | 能订阅的事件；测试订阅，不轮询、不睡 |

**测试分四层，各有搭法和预算**（写进 foundation，慢测试由检查报出来，不靠记）：

| 层 | 测什么 | 怎么搭 | 预算 |
|---|---|---|---|
| 规则 | 纯函数、黄金数据、策略（重试、窗口） | 直接调，`TestClock` | < 10 ms |
| 模块 | 一个模块和它下面的层 | 只搭到它那一层的农场；虚拟时间 | < 300 ms |
| 流程 | 跨模块的主线（派活、交回、合并） | 整座农场、真 git；虚拟时间 | < 2 s |
| 页面 | 界面、整个应用 | Playwright | 照旧 |

**四步，每步一个或几个 PR，每一步都删掉些什么，前后的数字写在 PR 里。**

1. **测试设施**：
   - 农场跑在虚拟时间上，系统闲下来时把时钟拨到下一个到点的等待，窗口不真等；`world` 的 `clock` 选项和 `testing/clock.ts` 删掉，改用 `TestClock.setTime`。
   - 等后台的事订阅事件（核心状态的变化）再判断，代替每 10 ms 的轮询；测试里的 `settle`、固定的 `Effect.sleep` 删掉。
   - `world` 能只搭到某一层（模块测试用），不再每个测试都搭十个模块。
   - 慢测试报告：每层有预算，超两倍的在 `server:check` 里列出来。
2. **聊天的读模型**：`Channels` 在内存里持有会话、参与者、已读位置，写的时候写穿到库；一条消息引起的几次写合成一个事务。删掉重复的按 id 读会话、读参与者。
3. **git 的仓库端口**：项目模块对每个仓库给一个 `Repo`，读的（`rev-parse`、`show-ref`、`symbolic-ref`、`for-each-ref`）走一个常驻的 git 进程或合成一次调用；`describe` 的三次 diff 合成一次。删掉 `project.ts` 里散落的 `gitRun(path, …)` 序列。
4. **沉淀**：「贵东西归谁管」和测试分层、预算写进 `docs/subsystems/foundation.md`，删掉本篇。

## Alternatives considered

**测试里换掉 git、PGlite。** AGENTS.md 定了真的 git 仓库；PGlite 是上线用的库，换成假的测不到 SQL 和事务。只让它们便宜。

**并行。** 主人要求不靠并行：每个测试先便宜。

**只在测试里加缓存（比如测试专用的读模型）。** 测试和上线跑的不再是同一份代码；读模型放在模块里，上线一样受益。

**事件驱动的测试框架、录放。** 现有的东西够用：核心状态的变化已经是流，`TestClock` 已在用，`world` 本来就是一层层组装的。

## Acceptance criteria

- 服务端测试顺序跑的时间从 107 s 明显下降，每一步的数字在它的 PR 里。
- 测试里没有为了等后台而睡的 `settle` / 固定 `Effect.sleep`；有窗口的不真等。
- 查询总数和 git 调用数各比现在少一大截（PR 里给计数）。
- 慢测试报告在 `server:check` 里；foundation 写着分层和预算。

## Risks

- 虚拟时间自动前进时，真实的 IO（git、PGlite、子进程）还没回来就拨钟，可能让超时提前到点：只在没有进行中的真实 IO 时前进，或者真实 IO 的截止本来就用真时间（`afterRealTime`）。
- 读模型和库不一致：一个家目录只有一个服务端（租约），写都经 `Channels`，写穿；启动时从库载入。
- 合并事务改了写的次序：只合同一条消息的写，次序照旧。
- 仓库端口动的是合并、派活的核心路径：流程测试覆盖住再动，一处一处换。
