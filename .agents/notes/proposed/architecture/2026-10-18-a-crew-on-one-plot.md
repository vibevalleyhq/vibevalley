# Agent Note: 一块地上几个人一起种

Status: proposed

## Problem

一张工单（[工单](docs/subsystems/issue.md)）目前一次只派给一个档案，重开才换下一个帮工。用户需要几个帮工在同一张工单上协作：
- **@ 谁就叫谁下地**：在工单串里 `@` 另一个档案即可来同一块地帮忙，无需另开工单。
- **写与看分工**：一个写代码，一个看改动挑毛病；验收不一定由用户或助手完成，可派专门的「看地的」帮工逐条核对验收标准。
- **小队复用**：将一组档案与协作顺序保存为小队方案，派活时直接按方案组织。

## Proposal

代码工单只有一个 worktree，因此**一块地可有多人（主种、帮手、看地的），但写锁（锄头）同一时刻只在一把人手里**：

1. **地上的人（`crew`）与锄头交接**：工单记录 `crew` 成员角色及当前持锄人；只有持锄人的 `Session` 可改 worktree，主种完成当轮后可将锄头交接给被 `@` 的帮手或由用户指定。
2. **@ 下地**：在工单串内 `@` 另一个帮工档案时，为其在同一工单下启动只读帮手 `Session`；需要改代码时再交接锄头。
3. **派看地的验收**：工单进入 `in_review` 时，可自动派出与主种不同档案的「看地的」帮工，对照工单 `criteria` 与 diff 逐条打勾并调用 `issue.review`（通过则标 `reviewedAt`，不过则写入 `findings` 打回）。
4. **小队方案**：复用父子工单 DAG 引擎保存固定角色协作模板，派给小队即按模板顺序启动或交接会话。

实施顺序：先做「看地的」独立验收，再做 `@` 下地与锄头交接，最后做小队模板。

## Alternatives considered

- **几个人拆成几张独立工单**：无需改模型，但同一件活的讨论、改动与验收散在多处，用户还得手工拼回。
- **两个帮工同时写同一个 worktree**：改同一批文件会互相覆盖且 git 提交交错；单写锁交接更稳妥。
- **固定由助手当看地的**：助手虽有 `issue_review` 工具，但逐行读代码 diff 会撑爆助手常驻上下文并破坏前缀缓存；派专门的帮工档案更经济。

## Acceptance criteria

- 工单交回后可派看地的档案读取 diff、逐条勾选 `criteria` 并调用 `issue.review` 完成通过或打回。
- 在工单串 `@` 另一档案可在同一工单下启动帮手 `Session`；交接锄头前帮手不可改文件，交接后可正常提交。
- 工单详情展示 `crew` 成员角色、当前持锄人与各轮执行人。

## Risks

- 同一工单下的多个在场 `Session` 均计入农场与仓库并发槽位上限。
- 交接锄头前必须先自动提交或暂存上一位持锄人未提交的改动，保证交接时工作区干净。
