# Agent Note: 先采样，再验收：规划和运行分开，故障回流成样本

Status: proposed

## Problem

验收子工单（先判红、合入父分支时冻结改动文件）已解决单次拆单内「改松测试混过检查」的问题，但还有三处缺口：
- **故障靠人描**：主分支测试挂了或线上出问题时，修复工单没有自动带上失败命令输出、出错工具调用和引入提交。
- **同一会话越补越歪**：子工单被退回两次以上时，旧会话上下文里塞满走错的尝试，继续在原会话打补丁成功率低。
- **固定套路每次调模型**：定时任务与巡查发现的固定处理每次都唤醒助手走一轮大模型，费钱且每次结果不一致；复杂活摸索出的通用步骤也没有沉淀成技能草稿。

## Proposal

### 1. 故障回流成样本，退回超限换新会话

- **从故障证据开单**：修复工单的第一步为验收子工单，输入自动附上失败命令输出、轨迹中出错的工具调用及引入提交；验收子工单必须复现同一条失败输出。
- **退回超限重开干净会话**：子工单第一次被退回仍在原 `Session` 修改；第二次被退回时，在从父分支新开的 worktree 中改派新 `Session`，只传入工单与前序失败样本，不继承旧对话。

### 2. 农活脚本：助手写、农场验、沙箱里跑

用于定时任务与巡查的固定自动化套路（不用于修代码）：
- **规划与样本校验**：助手按农场工具 Schema 编写 TypeScript 短脚本；农场用历史轨迹样本与边界 mock 输入试跑脚本，全部断言通过才挂载到定时任务。
- **沙箱运行与故障回流**：到点在 `quickjs-emscripten` WASM 沙箱中直接调用进程内工具实现，不调模型；若抛错或遇到新返回结构，将本次调用序列存为新样本并退回助手修脚本。

### 3. 技能草稿：帮工起草，用户批

- **起草（`skill_draft`）**：帮工做完多步复杂工单后，可提交 Agent Skills 格式的技能草稿（保存在 `agent_skill_draft` 表，不直接生效）。
- **用户审批与效果追踪**：用户在技能书页看到「待批」草稿与前后对比，点击同意才写入技能书；后续派活记录 `agent_skill_use` 统计该技能的成功与失败次数。

## Alternatives considered

- **用 LLM 当自动评审门槛**：模型评审本身也是一次采样，不稳定，不适合做硬门槛。
- **农活脚本使用 Node `vm` 或 `isolated-vm`**：`vm` 不是安全边界，`isolated-vm` 含原生模块需随 Electron 重编；QuickJS WASM 零原生依赖且隔离可控。
- **帮工写的技能直接生效**：写技能与用技能同一只手会让错误做法随每次派活扩散，必须经用户审批。

## Acceptance criteria

- 修复工单第一步复现故障输出；子工单第二次被退回时自动换新 `Session` 并附带前序失败样本。
- 定时农活脚本经样本校验后在 QuickJS 沙箱无模型运行；遇到未知返回自动沉淀新样本并交助手更新。
- 帮工通过 `skill_draft` 提交技能草稿，用户在技能书页批准后生效并统计后续使用成败。

## Risks

- 过多技能草稿会造成审批积压，需限制单档案待批数量。
- QuickJS WASM 绑定升级需隔离在统一执行接口后，保持脚本契约稳定。
