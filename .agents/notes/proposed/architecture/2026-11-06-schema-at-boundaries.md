# Agent Note: 边界与 Schema 约束准则、扫描脚本与全仓收敛清单

Status: proposed

## Problem

`scripts/api-client.ts` 生成的 HTTP 客户端信任成功响应，并手写错误字段校验。它没有与 SSE 一样验证返回值的形状，但加载结果 Schema 可能增加页面体积。是否改用契约解码，需要测量后决定。

源码里的可选字段、裸字符串和解码调用还需要逐条核实。[边界审计](docs/subsystems/foundation.md#边界审计)只给出线索，不证明存在缺陷，也不证明验证覆盖完整；归零不作为后续工作的目标。

## Proposal

1. 运行 `vpx scripts/schema-audit.ts`，沿调用链核实提示，只修改有证据的重复定义、类型退化与缺失验证。不扩大文件例外名单来减少提示。
2. 区分实体 ID 与未解析引用、缺省值与空值、存储值对象与线上值对象。具体边界照 [地基](docs/subsystems/foundation.md#边界审计)，不机械替换字符串或可选字段。
3. 单独评估 HTTP 客户端按 endpoint 结果 Schema 解码：修改生成器而不是生成文件，复用错误契约，并比较改动前后的页面构建体积与解码开销。若依赖成本不可接受，记录取舍，不把已有信任边界误报为已验证。
4. 确定客户端方案后，再补成功响应形状错误、空响应、未知错误与非 JSON 错误的测试。接口错误和响应不符合契约应可区分。

本 Note 的后续工作不要求改变存储格式、线上协议或模型可接受的输入别名。

## Alternatives considered

- **全部扫描类别强制归零**：字段名和局部调用不能证明语义，不作为硬门槛。对有明确来源的 SQL 枚举使用确定性检查。
- **每次 `JSON.parse` 都补 Schema**：传输层拆包后可以把 `unknown` 交给契约层，不重复验证同一契约。
- **存储层禁止复用协议 Schema**：同一个值对象可以共用定义。只有存储和线上模型不同才拆分。
- **用 SQL 生成类型校验 SQL 与协议一致**：生成物不能作为独立证据，也不能通过全仓同值枚举证明归属。
- **客户端直接加载全部 endpoint 定义**：先测按需引用结果 Schema 的成本，不为写法一致引入整套依赖。

## Acceptance criteria

- 每项收敛有调用链证据和对应测试，不用减少审计提示数量证明正确。
- HTTP 客户端方案附构建体积与解码开销的前后对比；若落地，响应不符合契约时不会把未经验证的值交给调用方。
- 修改生成器后，客户端生成物保持最新；`vp check --deny-warnings`、协议包测试、`vp run docs:verify` 与页面构建通过。

## Risks

源码扫描不解析完整类型与数据流，无法自行证明验证是否覆盖整条路径。HTTP 客户端引入结果 Schema 可能增加依赖体积与运行成本；是否接受应由测量结果决定。
