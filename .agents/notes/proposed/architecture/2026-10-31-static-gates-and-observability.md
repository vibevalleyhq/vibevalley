# Agent Note: 静态检查与可观测性：先封已有规则的绕过

Status: proposed

## Problem

本轮按主人指定的 `0e8bb950` 基线核查与收敛；`f527d936` 只用于核对原提案的出处，不将它新增的接口移植到本轮。验证结果见本篇的核查结论。

## Proposal

第一阶段只修已存在规则的漏检。每条候选先用最小源码确认误放行，再补正确放行样例，避免只追求匹配更多语法。候选为命名空间导入、对象方法简写、多行导入与重导出；括号是否保留为 AST 节点，应以实际解析器输出为准。

共用 AST 提取只在两个检查确有相同需求时抽取；接口键校验应区分源码 AST 与运行时 Schema AST，不假定递归比较文本就能证明编解码等价。

本地与 CI 严格度先比较实际命令与退出码，再调整 warning。日志先在会话、连接器、外部记忆入口补关联字段；指标只选能指导行动的查询耗时和积压，控制标签基数。

暂不新增禁止 `Effect.result`、串行 yield、所有 Unsafe 或所有前端定时器的规则。确有资源泄漏时，先提供能自动清理的原语，再决定可静态判断的限制。原语词典、契约 diff 摘要与更多棘轮等待实际评审成本证据。

实施顺序见[治理范围](.agents/notes/proposed/process/2026-10-30-code-quality-ratchets-and-boundaries.md)。

## 核查结论

| 候选 | 最终处置 |
|---|---|
| namespace/alias/globalThis 绕过 | 修复。两个时间规则共用按词法作用域解析的调用识别，支持 effect、effect/Effect、timers、timers/promises；新增非法形式与局部同名 Date/timers 的合法负例 |
| 方法简写、多行导入、重导出 | 不改。当前实际 AST 规则/模块检查已能捕获，原诊断不适用于此基线 |
| 缺失的 Effect 所有权 lint | 不按不存在的规则修绕过；运行时桥的所有权由 Scope 与对应生命周期测试验证，不新增全面禁令 |
| warning 分裂 | no-unused-vars 是本基线唯一 warn 规则，改成 error；本地与 CI 对同一样例都阻断 |
| JSON 错误解析 | MOSS 复用 base/json 的 Schema 解码，删去手写 JSON.parse 与类型断言 |
| AST 全面替换、额外棘轮 | 不采用。现有检查未出现对应实际绕过的部分，不以新扫描器或指标数量作为完成条件 |
| 日志/指标全量铺设、自动词典与 diff 摘要 | 本轮不引入新的观测产品或生成体系。已修故障保留诊断，其他成本收益未经证实；继续使用现有检查与测试日志 |

注释审查确认 lint 文件开头的规则概述重复了规则元数据和文档，删除该概述及两条复述代码的注释。Promise 门闩在 Node 测试里使用标准 withResolvers，保留全部行为断言；浏览器 ES2022 测试保留原实现，不升级运行目标。

## Alternatives considered

**五条风格禁令一起启用。** 合法的错误分支、串行语义和外部 SDK 边界会被误报。

**把全部 Effect Unsafe 调用计为只减不增的棘轮。** 合法底层桥接与缺陷无法仅凭函数名区分。

## Acceptance criteria

- 每条规则修复都有原先漏检的失败样例和合法边界的通过样例。
- 日志可关联一次真实请求到对应会话或连接器，不包含密钥。
- 新检查给出明确修复路径；没有证实的问题不进入硬门槛。

## Risks

低精度规则会促使 agent 添加豁免或改写语法绕过；规则的误报和检查耗时也应记录。
