# Agent Note: 话放进一个 i18n 模块：词典按语言分文件，代码里写 t("key")

Status: proposed

## Problem

对主人说的话现在散在 42 张词表里（`apps/*/src/**/words.ts`、`packages/protocol/src/words`），每张是一个 TS 对象：`const zh = {…}`，`const en: typeof zh = {…}`，代码里写 `settingsWording().keys.saved`。类型挡住了漏翻和参数对不上，但：

- **话和代码绑在一起**：改一句话、补一种语言、交给翻译或 agent 校对，都要改 TS 文件；词条是对象的路径，工具认不出来，按文字找不到它在哪。
- **没人管的问题没有检查**：没人用的词条（`voice.dirty`、`voice.clean` 这类，删页面时手工找出来的）、英文里混进中文、中英写成一样，类型都不报。
- **以后要加语言**：每加一种要复制 42 份对象，类型只认「和中文同形」。

量过（2026-10-28，`main`）：3222 条，其中 2339 条是纯文字、843 条是纯插值的函数（`(label) => \`配置 ${label}\``），只有 40 条有逻辑（大多是 `.join("、")` 拼列表）；调用处约 3000 个。99% 能机械地搬。

## Proposal

### 1. 一个包：`packages/i18n`（`@vibevalley/i18n`）

- **词典**：`packages/i18n/locales/<语言>/<命名空间>.json`，一种语言一个目录，一个命名空间一个文件。命名空间是「宿主.模块」：`web.setting`、`server.issue`、`desktop`、`shared`（原 `packages/protocol/src/words`）。文件里是嵌套的对象，键是概念（`keys.saved`），完整的键是 `web.setting.keys.saved`。
- **占位**：`{name}`，名字取原函数的参数名；值是字符串或数字。列表由 `list(items)` 按语言拼（中文「、」，英文「, 」），调用处拼好再传。复数、选择这类 ICU 写法等第一次真要用时再加，不预先做。
- **`t(key, params?)`**：按当前语言取，替换占位；`zh` 是来源，别的语言缺一条时用中文兜底并由检查报出来。语言的状态（`currentLocale`、`setLocale`）搬进这个包，`@vibevalley/protocol/words` 改为从它转出，读法不变（服务端读设置、页面读 `data-locale`）。
- **类型**：`vp run i18n:gen` 从中文词典写出 `src/messages.ts`（每个键和它的参数），`t` 照它查：键写错、少传或多传参数编不过，和今天一样硬。生成的不手改，`i18n:check` 查它是否最新。

### 2. 命令行：`vpx scripts/i18n.ts`（照 x18n 的路子，只做我们要的）

- `scan`：扫 `apps/*/src`、`packages/*/src` 里的 `t("…")`，列出每个键在哪用；写成模板的键（`` t(`web.tool.labels.${name}`) ``）记为一个前缀，前缀下的键都算用到。
- `check`（进 `docs:verify` 和 CI）：用到却不在词典的键；词典里没人用的键；别的语言比中文少的、多的键；同一个键各语言的占位不同；英文里有汉字；英文和中文一字不差而中文含汉字。
- `find <文字>`：按文字找键，给 agent 和人用。
- `migrate <words.ts>`：把一张词表搬成词典，并把调用处改成 `t("…")`（见下）。

### 3. 迁移

`migrate` 读一张词表在中英两种语言下的值：纯文字照抄；函数用探针参数调一次，结果是纯插值的写成 `{参数名}`；有逻辑的 40 条列出来手改（调用处先 `list(…)` 再传）。调用处按 `xWording().a.b` 和 `xWording().a.b(…)` 改写，`const w = xWording()` 这类别名和按变量取（`w.labels[name]`）由它报出、手改。改完 `vp check` 兜底：键和参数都有类型，搬错编不过。

一次一个宿主的一批模块，每批一个提交，整件事一个 PR；搬完的模块删掉它的 `words.ts`，全部搬完删掉 `localized`。试点是页面的 `features/setting`（字少，最近刚改过，测试齐）。

### 4. 规矩

- AGENTS.md「话放在哪」和 `docs/subsystems/foundation.md`「话放在哪」改成：对主人说的话进 `packages/i18n/locales`，代码里写 `t("…")`；对模型说的话照旧在模块的 `prompts.ts`，不进词典（只有中文）。
- lint `vibevalley/no-cjk-literal` 不变：代码里仍然不许写汉字，词典是 JSON，不在它的范围里。
- 种子和工单模板（`seeds.json`、`template_catalog.json` 和 `.en.json`）不动：它们是数据，不是界面上的话。

## Alternatives considered

**直接用 x18n。** 它的 `check`、MCP 和类型生成正是我们要的，等词典成了标准的 JSON 和 `t("key")` 也能接上；但它要单独装、要配置预设，我们只要其中五个命令，自己写两三百行更好控制，CI 不依赖外部服务。搬完以后可以随时接它，词典格式不用变。

**留在 TS 对象，只加一个检查脚本。** 能补上「没人用」「英文混中文」，但话还是和代码绑在一起，按文字找不到，翻译和 agent 校对仍要改代码；主人要的是单独的 i18n 模块。

**一种语言一个大文件。** 最简单，但几百个模块挤在一个文件里，并行的分支几乎每次都冲突；按命名空间分文件，冲突只在同一个模块里。

**用 i18next 之类的库。** 运行时、插件、后端加载都是我们用不上的；`t` 只要取值和替换占位，类型由我们生成，比给库写类型声明直接。

## Acceptance criteria

- `@vibevalley/i18n` 有 `t`、`list`、`currentLocale`、`setLocale`；词典在 `locales/zh`、`locales/en`；`src/messages.ts` 由 `i18n:gen` 写出，`i18n:check` 查它最新。
- `vpx scripts/i18n.ts scan|check|find|migrate` 能用；`check` 在 `docs:verify` 里，对现在的仓库通过；故意删一条英文、在英文里写汉字、留一条没人用的，各报一次。
- 写错键或参数，`vp check` 报错（有测试钉住类型）。
- 试点 `features/setting` 搬完：没有 `features/setting/words.ts`，页面照旧，`settings.spec.ts` 通过。
- 剩下的词表按批搬完，删掉所有 `words.ts` 和 `localized`；`vp check`、`server:check`、`web:check`、e2e、`desktop:test` 通过。
- AGENTS.md、`docs/subsystems/foundation.md` 写的是新的做法。

## Risks

- **改动面大**：约 3000 个调用处。靠机械改写加类型兜底；按批提交，出了问题能定位到批。
- **键变长**：`t("web.setting.keys.saved")` 比 `settingsWording().keys.saved` 长一截；换来的是一个键在全仓库唯一、能搜到。
- **兜底到中文会藏住漏翻**：运行时不报错是有意的，`check` 在 CI 里报。
- **按变量取的键**（`labels[name]`）只能按前缀算用到，前缀下真没人用的词条报不出来。
