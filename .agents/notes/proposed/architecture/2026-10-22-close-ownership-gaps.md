# Agent Note: 收回派活、工作区、配置、日志与手机线路的使用约束

Status: proposed

## Problem

即时派活在工单编号确定前创建工作区；起草丢弃和计划验收在 Session 停止写入前使用目录；农机预检与执行读取不同配置；日志快照和实时增量缺少新旧次序；手机桥将不同电话的资源共用。农具与关闭窗口还保留工单动作的第二套判断。连接器引用旧消息和文档同批改动另有正确性缺陷。

## Proposal

1. 工单确定稳定身份和工作区，Session 消费分配结果；即时派活、重开、PR 使用同一分支。
2. Session 封装停止写入和稳定工作区的使用期限，起草与 Tasks 保留自身规则。
3. Runtimes 对同一有效配置执行预检和启动校验。
4. 日志读取拥有快照、增量、新旧次序和重连恢复；工作台接回实时读取时重跑此前失败的并行时间线用例。
5. 手机 RTC Adapter 拥有每条线路的身份、事件与终结，旧线路清理不能影响新线路。
6. 所有工单动作入口使用服务端的 attention；连接器通过持久消息关系定位引用；文档批内属性修改保留文字版本的可见性。
7. 首批修复后继续两轮审查与修复。每轮先核对历史台账和已改路径；只计独立的 Depth 提升，旧项与附带缺陷单列。每轮目标五项新根因，证据不足时记录检查范围和不足项，不虚报完成。

累计审查、处置和验证证据写入临时目录的同一份 HTML 报告；当前行为沉淀在各子系统文档。

### 后续审查确认的职责

- 记忆来源管理拥有来源代次、已接受写入与关闭；检索层统一兑现项目范围，不把未知范围当成全局。
- 田头拥有未解决的主人提及及其读过、回复过的完成条件，不受近期消息窗口裁剪影响。
- 新文档块命令只含作者决定的位置与内容；文档模块填写归属、版本、作者和时间。
- 手机当前农场由同一个拥有者协调初次读取、配对尝试、持久提交和忘记；旧尝试不能覆盖新选择。
- 发送模块用完整发送意图绑定重试钥匙，换频道、串或档案形成新意图。
- 定时的时区解析与技能删除后的档案引用另按正确性修复，不计架构数量。

## Alternatives considered

**在调用者补判断、重试或锁。** 这会继续要求调用者理解编号、配置优先级、版本先后与资源生命周期；改由已有拥有者提供保证。

**引入统一工作流、通用资源框架。** 这批缺口可在既有 Module 内收回；持久副作用属于已有提案，不扩大本次改动。

**把计划验收移入 Session 或 Projects。** 验收与冻结规则仍归 Tasks；Session 只保证使用现场期间不会继续写入。

## Acceptance criteria

- 即时派活后取消、重开保留工单分支和提交；PR 不因入口不同产生分支身份错误。
- 丢弃或验收工作区期间不能并发启动写入；失败仍能恢复下一轮。
- 继承的 effort、env 与显式设置获得相同预检和启动判定。
- 断线恢复后，日志在保留窗口内补齐，旧增量不能覆盖新快照。
- 手机旧线路迟到完成、释放或发事件时，新线路仍可收听与控制。
- 必须验收的工单在各入口呈现相同动作；旧引用保持原对话；同批属性更新不制造文字冲突。
- 窄测试先给出失败证据，改后通过；类型、lint、全套相关检查及真实程序验证通过。
- 追加轮次保留根因、调用位置、职责变化、删除测试、验证证据与历史重合的累计台账。

## Risks

Session 与 Issues 同时改动会影响派活失败后的资源清理；测试应覆盖失败路径。工作台实时日志曾在并行时间线用例失败，不能只验证单次渲染。手机桥修改应同时验证两端，原生环境不可用时保留未验证项，不把桥单元测试写成原生验证。
