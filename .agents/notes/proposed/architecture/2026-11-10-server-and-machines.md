# Agent Note: 一个服务端管多台机器，库换成 Postgres

Status: proposed

## Problem

今天一个 VibeValley 进程就是一台机器的全部：工单、频道、管家、核心状态，和这台机器上的农机（编码 agent）、仓库、worktree 都在同一个进程里，存在同一个 SQLite 文件里。主人要在好几台机器上干活（家里的、公司的、一台跑长任务的服务器），只能每台各开一座农场，工单和频道互不相通。

按 2026-11-10 的代码数，碰本机的只有几块：`runtime`（探测本机装了哪些农机）、`repo`（git 仓库和 worktree）、`executor` 与 `session` 的启动部分（经 oar 起本机的编码 agent、收它的事件）、轨迹文件。其余的（`core`、`issue`、`channel`、`mailbox`、`orchestrator`、`cron`、`inbox`、`connector`、`setting`、`provider`、`agent` 档案、`memory`、`pkm`、`artifact`、`media`）不碰本机的进程和工作目录，本来就可以放在别处。

## Proposal

**拆成两样东西，名字照领域起：**

| 概念 | 名字 | 管什么 |
|---|---|---|
| 服务端 | server（`apps/server`） | 核心状态只有一份，在这里：工单、频道、信箱、管家（它只调模型接口，不需要本机的农机）、定时、收件箱、连接器、设置、稿子、笔记、媒体。库是 Postgres |
| 机器 | machine（新的 `apps/machine`，命令 `vibevalley machine …`） | 一台登记过的电脑：探测它的农机、管它的仓库和 worktree、经 oar 起帮工、把帮工的事件和轨迹交回服务端 |

帮工（会话）仍是服务端核心状态里的一个人，只是多了「在哪台机器上」（`Session.machine`）。派活时服务端按档案的农机和仓库挑一台有这个农机、有这个仓库的机器；页面上能看到每台机器在不在、装了什么、在干什么。

**机器只往外连。** 机器主动连服务端，一条带钥匙的长连接（WebSocket，消息是 `packages/protocol` 里的 Schema），服务端经它派活、机器经它交回事件；机器在 NAT 后面、在笔记本上合盖再开都行，服务端从不往机器里连。这和连接器「只走出站长连接」一个道理。

**命令行注册机器。** `vibevalley machine join <服务端地址>`：机器报上名字和农机，拿到一个配对码；主人在页面上点「让它进来」，服务端给这台机器签一把钥匙（存在机器的家目录）。照「连接到本机」的配对做：一台一把钥匙，主人点过头才签，随时能在页面上收回。

**帮工照旧只跟自己那台机器说话。** 帮工的命令行和 `/mcp` 今天连 `127.0.0.1` 的服务端；拆开后连本机的 machine 进程，machine 带着这次会话的令牌转给服务端。帮工拿不到机器的钥匙，也看不到别的机器。

**服务端要能对外，所以要登录。** 今天的安全底线是「服务端只听 127.0.0.1」（AGENTS.md）。纯服务端放到一台服务器上，就得听外面的连接，这条规矩要改成：服务端可以对外，但每个请求都要带钥匙。主人的设备用「连接到本机」那套设备钥匙，机器用机器钥匙，帮工用会话令牌，三种钥匙能做的事分开；`/mcp` 只经机器进来。只在本机用的人，照旧只听 `127.0.0.1`。

**库换成 Postgres，服务端只有一种 SQL。** `db/queries/*.sql` 和 `0001_schema.up.sql` 改写成 Postgres 的方言，`scripts/sqlite-generate.ts` 改成对着 Postgres 推类型（`pg-generate.ts`）。全文搜索从 FTS5 的 `bm25` 换成 `tsvector` 和 `ts_rank`（分词仍由 `gse.ts` 做好，Postgres 用 `simple` 配置）。驱动按配置选：`vibevalley.yaml` 写了 `database.url` 就连那个 Postgres（`@effect/sql-pg`）；没写就在家目录里跑 PGlite（`@effect/sql-pglite`，同一种方言跑在进程里），桌面版一个人一台机器时开箱即用，和今天一样。测试用内存里的 PGlite；CI 另跑一遍真的 Postgres。

**桌面版是一台机器，也可以带一个服务端。** 桌面版默认在本机起一个服务端（PGlite）和一台机器，体验和今天一样；在设置里填别的服务端地址并配对后，它就只是那个服务端的一台机器。

一步一个提交，每步都能单独上线、行为可验：

1. **Postgres。** 方言、生成器、全文搜索、测试里的触发器（造写入失败用的）改成 Postgres；驱动二选一（`database.url` 或 PGlite）。行为不变，旧的 SQLite 库作废（内部不留兼容）。
2. **机器这个概念。** 协议里加 `Machine`（名字、在不在、农机、仓库），表 `machine`，`Session.machine`；今天这一台就是唯一的那台机器，仍在同一个进程里。派活按机器挑。
3. **机器的链路。** 服务端与机器之间的消息（派活、交回事件、轨迹、探测结果）写成 Schema；`runtime`、`repo`、`executor` 与 `session` 的启动部分搬到 `apps/machine`，经链路和服务端说话。同一个进程里仍跑一份，靠链路的内存实现；测试照旧一个整农场。
4. **注册与钥匙。** `vibevalley machine join`、页面上的批准与收回、三种钥匙、服务端对外时的鉴权；帮工的命令行和 `/mcp` 改连本机的 machine。
5. **分开跑。** `vibevalley server`（纯服务端，读 `database.url`）和 `vibevalley machine`（一台机器）各自能起；桌面版默认两者都起，也能只当一台机器；文档、官网的说法跟着改。

## 进度

| 步 | 状态 | 提交 | 做了什么 |
|---|---|---|---|
| 1 Postgres | 完成 | 本步的提交 | 表结构与查询改成 Postgres 方言：时间 `double precision`（不用 `bigint`，Postgres 的驱动把它当字符串交回）、触发器改 plpgsql、全文搜索换成 `term_vector`/`term_query` 加 GIN 索引、JSON 文本列在查询里 `::jsonb`、`authorization` 加引号（保留字）、`channel.root_id` 的外键建完表再加。`scripts/pg-generate.ts` 让 PGlite 对每条查询做 Parse 和 Describe，参数与结果列的类型是 Postgres 说的，结果列来自哪张表哪一列也是它说的（`tableID`、`columnID`），只剩「算出来的列会不会为空」和取值集合靠查询里的记号。驱动二选一：`database.url`（`@effect/sql-pg`，按密钥读，空库才建表、记下哈希，别的一律拒绝启动），否则 PGlite 在 `db` 目录；内存库从每个进程建一次的模板拷一份（新起一个约 0.7 秒，拷一份约 0.1 秒）。服务端测试只开一半的核：PGlite 吃 CPU，开满时最重的几个媒体测试会等过超时。测试里手写的 SQLite 触发器都换成共用的 `refuse`/`allow`（plpgsql）；几个测试原来靠 SQLite 下碰巧的先后（外发消息的顺序、消费后才挂的 👀），改成等那件事本身 |

## Alternatives considered

- **只把 SQLite 换成 Postgres，不拆。** 换库本身不解决多台机器：农机、仓库、worktree 都绑在服务端所在的那台电脑上。Postgres 是拆开以后服务端需要的（多台机器同时写、服务端放在服务器上），所以排在第一步，但不是全部。
- **服务端主动连每台机器（SSH 或机器开一个端口）。** 笔记本、公司内网的机器大多连不进去，还要在每台机器上开放端口；机器往外连只要求服务端可达。
- **每台机器各自一座农场，之间同步。** 核心状态就有了好几份，违反「核心状态只有一份」；冲突怎么合也说不清。
- **只用真的 Postgres，不要 PGlite。** 一个人一台电脑的用法就得先装、先起一个 Postgres，桌面版开箱即用没了。两种驱动说的是同一种方言，生成的代码和查询只有一份。

## Acceptance criteria

- 服务端只有 Postgres 一种 SQL；配了 `database.url` 连它，没配跑 PGlite；`server:check` 在 PGlite 上过，CI 在真的 Postgres 上也过一遍。
- 两台机器登记到一个服务端：一张工单派到装了对应农机和仓库的那台，帮工在那台机器上干活，页面、频道、收件箱照旧看到它的进展和交付；另一台机器断线时，它的帮工在页面上显示离线，回来后接着干。
- `vibevalley machine join` 拿到配对码，主人在页面上批准后机器才进来；收回钥匙后那台机器的连接立即断开。
- 帮工拿不到机器的钥匙；没有钥匙的请求一律拒绝；`/mcp` 只经机器进来。
- 桌面版不改设置时，和今天一样开箱即用。
- 各项检查通过；行为变了的文档（`architecture.md`、`foundation.md`、`session.md`、`lan.md`、AGENTS.md 里「服务端只听 127.0.0.1」那条）在同一个改动里改。

## Risks

- **安全底线变了。** 服务端对外以后，鉴权有一处漏了就是远程执行命令（帮工能在机器上跑任何东西）。三种钥匙能做的事要写成每个接口上的声明，由检查拦着，不靠记得。
- **PGlite 的性能和单连接。** 服务端今天就是单连接串行写库，影响不大；全文搜索和大的轨迹表要实测。
- **轨迹和附件的位置。** 轨迹今天是家目录里的文件；拆开后由机器交回、存在服务端的库里或服务端的磁盘上，大小要有上限。
- **改动面大。** 第 3 步要搬好几个模块，测试的整农场要能在同一个进程里接上链路的内存实现，否则测试会全部变成多进程。
