# Agent Note: 协议与客户端：来源边界、调用回收与服务重启

Status: proposed

## Problem

本轮按主人指定的 `0e8bb950` 基线核查与收敛；`f527d936` 只用于核对原提案的出处，不将它新增的接口移植到本轮。验证结果见本篇的核查结论。

## Proposal

三项分别复现、修复和验收：

| 工作 | 代码观察 | 设计与测试 |
|---|---|---|
| HTTP 来源边界 | `http/api.ts` 读取文本 JSON，入口未调用来源守卫；`rpc.ts` 仅凭设备头放行 | 查完整路由和中间件；拒绝跨源及不合法 Host，明确 JSON 类型和请求体限制；本机 CLI、同源页面、配对设备各保留通过测试 |
| Bridge 生命周期 | `connect` 的 waiting 表缺少单次超时；push 监听器直接依次执行 | 按调用语义定义超时与取消，覆盖无回复、发送失败、迟到回复、关闭和监听器抛错；用户交互型长调用不能统一限为 15 秒 |
| 桌面重启退出 | `serverKeeper.restart` 未把新启动 Promise 纳入 `starting` | 用可控启动/停止屏障覆盖旧实例停止中、新实例启动中和并发 restart；stop 完成后无存活或待接管实例 |

LAN 转发标记应有进程内可验证的来源，剥离外部同名头；具体使用共享凭据还是进程内上下文由路由边界决定。测试区分本地进程请求和外部网页能发送的请求，不能把伪造头本身当作已完成的网页攻击复现。

请求体上限先核查框架配置，按普通 JSON、附件和语音的契约分别制定，不在 Schema 解码后才限流。开发页面按实际 proxy 配置测试来源，不声称 proxy 自动使 Origin 与 Host 相等。

画布归 [产出画布](.agents/notes/proposed/feature/2026-10-30-artifact-canvas.md)。Branded ID、存储 codec、前端定时器和流资源额度保留为后续候选，不绑入这三项修复。

实施顺序见[治理范围](.agents/notes/proposed/process/2026-10-30-code-quality-ratchets-and-boundaries.md)。

## 核查结论

| 候选 | 最终处置 |
|---|---|
| HTTP/WS 来源 | 已修。API 与 RPC 共用检查，LAN 在剥离来源前检查；伪造设备头不再绕过。公开页面不被 API 守卫误挡。真实跨源建频道请求被拒且列表不变；安卓配对、重载、通知和重启通过 |
| LAN 内部密钥 | 不增加。来源在每一入口校验，转发后移除来源头；设备头只携带身份，不授予绕过权，已消除原有错误信任 |
| Bridge 与 serverKeeper | 本基线不存在，不移植较新版本实现，也不把它们算成本轮未修缺陷 |
| 统一 2MB 请求体上限 | 不采用该固定值。框架默认无限制属实，但当前附件、产出、消息没有统一大小契约；来源检查已阻断外站驱动的写请求。本轮保持已授权客户端的载荷行为，不声称已实现字节级限流 |
| 全量 Branded ID、前端计时/存储封装、资源额度 | 未复现对应调用顺序错误、泄漏或解码错误，本轮不按数量重构；不改变宿主契约 |
| 画布 | 仍为独立产品提案，本轮工程验证与收敛未包含新功能实现 |

来源修复不覆盖主机上拥有本机进程权限的调用者；其本来就能使用主监听。保留公网语音线路原有的每通电话 Bearer 校验，不把它误当成无认证本机 API。

## Alternatives considered

**只验证 JSON Content-Type。** 来源、Host 和受信转发仍需分别界定。

**仅给 restart 赋值 starting。** stop 与重复 start/restart 的交接还可能覆盖实例所有权，应按完整状态转换验证。

## Acceptance criteria

- 来源边界测试覆盖拒绝与合法客户端，并在隔离服务端验收。
- Bridge 各终止路径清理 pending；一个监听器异常不阻止其他监听器，异常可诊断。
- 重启与退出各交接窗口可确定地复现，stop 后没有孤儿实例；通过桌面验收。

## Risks

超时仅终止等待，不自动撤销已经执行的动作；客户端不应因超时盲目重试写操作。来源守卫应保留配对设备和开发代理的正确访问。
