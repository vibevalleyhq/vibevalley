# Agent Note: 深模块：收回调用方重复承担的领域步骤

Status: proposed

## Problem

本轮按主人指定的 `0e8bb950` 基线核查与收敛；`f527d936` 只用于核对原提案的出处，不将它新增的接口移植到本轮。验证结果见本篇的核查结论。

## Proposal

选择至少两个调用方重复承担、顺序具有业务意义的一组步骤，先列出调用方必须知道的知识，再设计服务入口。候选包括引用解析与查询、项目刷新后的工单更新、工具与 HTTP 的重复默认值处理。

验收比较调用方是否仍需知道内部 ID 解析、默认频道、事务或联动顺序；允许内部保留多个文件。只对需要接收用户引用的入口使用 Ref，内部已有明确 ID 的调用不必再次解析。

Issue、Task、Cron 暂不合成 Work。共享主表不能单独证明生命周期相同。Core 与 Projection 保持依赖方向，agent 不引入农场契约依赖。预览与删除可以共享内部计划计算，保留外部独立命令以表达不同权限和结果。

实施顺序见[治理范围](.agents/notes/proposed/process/2026-10-30-code-quality-ratchets-and-boundaries.md)。

## 本轮落实

基线 `0e8bb950`：工单 get、timeline、previewRemove、previewStatus、changes 已在内部经 get 解析引用；HTTP 入口删除对应的外层 idOf。run.list 从 get 返回的工单取规范 id 再查执行，保留存在性检查。写操作仍保留外层解析，因为部分实现会把传入 id 直接写进 SQL，不能机械地一起删。

接口测试用 UUID、数字和带 # 的数字逐个验证查询、执行列表、时间线、删除预览、状态预览和 diff 拒绝行为，避免只以短了多少字判断正确。

## Alternatives considered

**按 10–12 个目录或接口方法减半验收。** 数量不代表隐藏了多少知识，宽但清晰的领域接口不应为指标改成通用命令。

**把固定联动全部改成事件。** 需要即时结果的命令会失去失败传播，需先区分同步承诺和可延后的副作用。

## Acceptance criteria

- 给出至少两个真实调用方的前后对比，指出删除的重复步骤。
- 领域行为与权限保持，失败传播和顺序有测试。
- 不以文件合并或接口数量下降替代行为证据。

## Risks

过度下沉引用解析会把用户输入语义扩散到内部调用；事件订阅可能引入重复执行和恢复责任。
