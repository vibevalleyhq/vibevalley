# Agent Note: 聊天补齐：跳到消息、频道和串的管理、通知、输入、媒体、搜索、和帮工档案的私聊

Status: proposed

## Problem

照 Discord 补了消息的回复、改删、回应、置顶、附件以后，日常还缺一截：搜到的、置顶的、被回复的话点了不跳过去；频道不能改名、归档、删、分组、排序，也不能静音；串没有列表，不能改名、归档；输入框没有完整的表情、不能拖文件、草稿刷新就没；链接、视频、PDF 不预览，上传没有进度，发出去的附件去不掉；搜索没有过滤，也只在当前频道；农场的窗口里只能看不能动；只能和管家私聊，不能和帮工档案私聊。

## Proposal

### 1. 跳到消息

- 一条消息的地址是 `/chat/<channel>?m=<号>`：列表读到那一页（`channel.message.list` 的 `before`），滚过去并高亮。搜索结果、置顶、回复的引用点了都去那里；消息的工具里多一个「复制链接」。
- 「标成未读」：`channel.markUnread { id, number }` 把主人在那里的已读退到这一条之前。

### 2. 频道和串

- `channel.update` 收 `name`（频道照旧不重名、能写进地址；串可以起一个标题）、`category`（分组，空是不分组）和 `before`（排在哪个频道前面）。侧栏按分组列频道，拖一个频道换位置。
- 归档：`channel.archive.toggle`。归档的频道和串不在侧栏和串列表里（侧栏底下一个「已归档」能看），消息和地址照旧在；默认频道不能归档。
- 删除：`channel.delete`（和试跑）。只删没人用的：默认频道、还有帮工在干活、有定时、接着连接器、有排队的工单的都拒绝，说是哪一样；删频道连它的串和消息一起删。
- 串列表：频道头上一个按钮打开这个频道的全部串（标题、回复数、最后一条），能改名、归档。

### 3. 通知

- 每个频道和串有一个提醒级别 `notify`：`all`（默认）、`mentions`（只在 @主人 时算）、`none`。`channel.notify.set { id, notify }`。`none` 的不算未读角标、不进 Inbox 的 @ 提醒、不转到连接器；`mentions` 只有 @主人 的算。

### 4. 输入

- 完整一点的表情选择（常用的几组），拖文件到聊天区上传，上传显示进度。
- 输入框是空的时按 ↑ 改自己上一条，Esc 取消回复；草稿（字、回复哪条、附件）记在这台设备上，刷新还在。

### 5. 媒体

- 视频、音频直接在消息里播；PDF 在新标签页里看（附件按它的类型给 `inline`）。
- 链接预览：消息里的 http(s) 链接，服务端在发出以后去读那一页的标题、说明、站名和图（只连公网地址，3 秒、512 KB 为限），读到了把预览记在消息上（修订号加一）；读不到就不显示。主人改消息时也能去掉附件（`channel.message.update` 的 `attachments`）。

### 6. 搜索

- 搜索的字里认几个过滤：`from:`（主人、管家、帮工编号或名字）、`in:#频道`、`has:file`、`has:image`、`has:link`、`before:`、`after:`（日期）。服务端读这些（`parseSearch`），页面原样交给它。
- 侧栏有「搜全农场」，结果按频道和串标出地址，点了跳过去。

### 7. 农场窗口

田头窗口里每条消息多一个「⋯」：回应、回复、复制链接、改（自己的）、删，和工作台用同一套请求。

### 8. 和帮工档案的私聊

- 每个帮工档案能有一个私聊（`peer` 是档案）：在档案页、成员栏点「私聊」打开，没有就建一个。
- 主人在里面说话：这个档案有私聊的执行在场就交给它，没有就派一个（`Sessions` 的私聊执行：不挂工单、不开串、不进看板，在档案的工作目录或全部项目的目录里，只读，交回来就清掉它改的东西）。它说的话、交回的汇报都写在私聊里。
- 它占一个同时干活的名额，闲 10 分钟就收工；下次再说就派新的一个，交给它时附上私聊里最近的几条。要改代码，它或主人把这件事记成工单，照常派、看、合。
- 群私聊不做：几个人一起说话就是开一个频道，帮工在哪个频道派的活就在哪个频道。

## Alternatives considered

- **私聊的帮工能改代码**：私聊不挂工单就没有分支和改动清单，改了绕过「主人看过才合」。
- **私聊的执行不占名额**：一直歇着的执行也占着 runtime 的额度和这台电脑的资源。
- **链接预览在页面里读**：浏览器跨域读不了别的网站；放在服务端读，限住地址、时间和大小。
- **静音是一个开关**：Discord 分「全部、只 @、不提醒」三档，开关说不清「只 @」。

## Acceptance criteria

- 搜索、置顶、回复引用点了跳到那条并高亮；复制的链接打开同一处。
- 频道能改名、分组、排序、归档、删（拒绝时说为什么）；串有列表、能改名和归档。
- `none` 的频道没有角标、没有 Inbox 的 @、不转微信。
- 拖文件能传、有进度；↑ 改上一条，Esc 取消回复，刷新后草稿还在；视频能播；链接有预览。
- `from:` `in:` `has:` `before:` `after:` 能用，全农场能搜。
- 农场窗口里能回应、回复、改、删。
- 和帮工档案私聊：派一个只读的执行，答在私聊里，闲了收工，再说话接着。
- 测试：每一块在能看见它的最低一层测（规则的纯函数、频道模块、流程、页面的 Playwright）。

## Risks

- 老的库作废（照「内部不留兼容」）：频道表加列。
- 读外面的网页是服务端第一次主动连一个主人给的地址：限住公网、http(s)、时间和大小，不带任何凭据。
- 管家和帮工的提示变了，管家的评测要重跑（花钱，先问主人）。
