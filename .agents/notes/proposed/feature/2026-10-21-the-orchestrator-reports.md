# Agent Note: 管家给用户报告：早报、仓库健康度、工单之间的关系和分拣建议

Status: proposed

## Problem

管家目前已支持按等待时长查询待用户处理的工单（`issue_list` 的 `wantsOwner`），但在仓库级汇报错落上还缺四项能力：
- 问「某仓库怎么样了」时，缺少确定性的仓库健康度判定规则。
- 缺少固定结构的每日早报格式。
- 无法在工单之间标记「重复」或「相关」（仅支持前置阻塞 `blockedBy` 与父子 `parent`）。
- 新记入 `backlog` 的工单缺少优先级、所属仓库与推荐档案的分拣建议。

## Proposal

### 1. 纯函数仓库健康度（`packages/protocol/src/rules/health.ts`）

根据仓库开着的工单与当日花费确定性算出三档健康度及原因工单列表，前后端与管家共用：

| 健康度 | 判定条件（初版阈值，带黄金数据） |
|---|---|
| 顺利（`on_track`） | 无 `stuck` 工单，且等待用户的工单均未超过 24 小时 |
| 有风险（`at_risk`） | 存在 `stuck` 工单、存在等用户超过 24 小时的工单，或当日花费超过预算 80% |
| 卡住了（`off_track`） | `stuck` 工单超过在办工单半数，或存在等用户超过 72 小时的工单 |

### 2. 早报、非阻塞关系与分拣建议

- **三段式早报**：定时任务触发早报时，管家固定按「昨日完成交付 → 当前受阻与风险仓库 → 今日等用户拍板事项」三段汇报，数据全部取自 `issue_list` 与仓库健康度。
- **工单关联（`issue_link`）**：`Issue` 增加 `relations: { kind: "duplicate" | "related"; issue: IssueId }[]`（存 `issue` 表 JSON 列），只做双向展示标记，不阻塞调度。
- **分拣建议（Triage）**：管家对新记下的未分派工单给出优先级、仓库与档案建议，界面显示为待确认建议，用户点击接受后才写入工单字段。

## Alternatives considered

- **由大模型自由判断仓库健康度**：每次口径不一且无法与仓库页 UI 对齐；用纯函数算好并附上触发工单号，管家只负责转述。
- **照搬 Linear 的周期（Cycle）、估点与 SLA**：帮工随派随做，真正约束是并发槽位与每日花费（已记在 `session_run` 上），等待时长也已在 `stage.since` 中实时计算，无需另建周期与估点。
- **新增独立工单标签体系**：档案的 `Agent.tags` 与仓库分类已够分派和筛选，不增加额外维护负担。

## Acceptance criteria

- 询问仓库状态时，管家回答的健康度及原因工单与工作台仓库页展示完全一致。
- 调用 `issue_link` 可为两张工单标记 `duplicate` 或 `related` 并在看板详情展示，不影响 `blockedBy` 调度。
- 管家对新工单提交的分拣建议在用户点击接受前不覆盖原工单字段。

## Risks

- 健康度时间与花费阈值需在实机使用后按用户体感微调，统一收敛在 `rules/health.ts` 中维护。
