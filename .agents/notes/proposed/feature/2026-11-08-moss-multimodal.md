# Agent Note: MOSS 多模态能力与生成资产

Status: proposed

## Problem

[AI 服务](docs/subsystems/provider.md)已有共享连接、模型目录与听写、MOSS Live 的用途绑定，但尚未提供生图、图片与视频理解、单人语音生成的使用流程。模型列表可见不等于能力可调用，绑定成功不等于厂商验收通过。

2026-11-08 核对的[官方模型列表](https://platform.moss.cn/docs/models/)包含 11 个稳定模型 ID、5 大类能力。不同模型共用协议，不按模型数量建模块；快照 ID 只是版本选择。

## Proposal

在现有 `feat/moss-provider` worktree 中按 P1–P8 实施；不读取主人的凭据，不自动调用真实厂商，不提交或推送。真实调用需主人确认使用的账号、输入与费用，即使厂商当前标为免费也不自动发送媒体。

### 交付范围

| 阶段 | 能力 | 完成边界 |
|---|---|---|
| P2 | 文生图、布局生图 | 两个图像模型共用接口；创建任务、查看状态、预览、本地保存；主人和 agent 走同一服务 |
| P3 | 图片与视频理解 | 上传本地媒体，取得文本；同次最多 5 张图或 1 个视频，不混传；明确输出被截断 |
| P4 | 单人 TTS | Flash 与 Pro 共用协议；选择音色、生成、播放、保存；Flash 流式播放单独验收 |
| P5 | 完整音频 | 多人 TTS、音色设计与克隆、音色管理、长音频异步转写、说话人和时间轴 |
| P6 | 现有语音与实时视觉 | 核对 Live 协议、采集连续帧、实时理解和增量文本，再与音频结合；设备权限、带宽和资源释放分别验收 |
| P7 | 真实厂商 | 逐项覆盖模型与能力，不用目录查询或替身成功代替真实结果 |

P1 核对边界后从生图开始，先实现可离线验证的请求与响应协议，再实现任务、资产和页面。完成一个切片应记录证据，不以适配器完成代替产品完成。

### 官方契约

- [文生图](https://platform.moss.cn/docs/reference/images-generations)：`POST /v1/images/generations`，`moss-image-base-1.0`、`moss-image-sft-1.0` 及文档列出的快照。一次一张 PNG，只返回 URL，无流式和 Base64 结果。
- [布局生图](https://platform.moss.cn/docs/reference/layout-image-generation)：同一个接口，把布局 JSON 序列化进 `prompt`；使用以画布中心为原点的 `abs_centralized` 坐标、`yxyx` 顺序。先支持结构化输入，不做拖拽设计器。
- 图像参数：提示词非空、最多 4000 字符；宽高 256–2048 且为 16 的倍数，总像素不超过 2097152；种子为非负安全整数，推理步数 1–100、引导系数 0–10；显式的 0、false 不应丢失。提示词增强默认关闭，可见水印默认开启。
- 图像 API 尚未公布参考图编辑、局部重绘和视频生成能力，不创建这些产品选项。
- [图片与视频理解](https://platform.moss.cn/docs/reference/responses)：文本与媒体必须同时存在，只接受一条 user 消息；URL 或 file_id 二选一，不接受内联 Base64。图像最多 30 MB、视频最多 200 MB；返回 `incomplete` 时保留已有文本并明确截断。
- [任务查询](https://platform.moss.cn/docs/reference/audio-task)只适用于异步音频任务，不用于查询图像任务。

### 模块边界

| 位置 | 负责 | 不负责 |
|---|---|---|
| `packages/provider/src/moss/` | 固定官方端点、模型与参数校验、请求编码、响应解码、安全错误、音频任务与文件协议 | 应用配置、页面状态、数据库、本地资产归属 |
| `packages/ai` | 能力调用、无框架输入与输出、取消与用量；按实际 SDK 契约选择适配方式 | 供应商凭据持久化、频道、任务表 |
| 服务端 `Provider` | 从共享连接解析每种用途的模型与凭据，返回一次调用使用的配置快照 | 生成任务和媒体文件 |
| 服务端 `Media` | 生成任务与媒体资产、有限并发、恢复、下载；在 Collaboration 内、频道之后组装 | 另存连接 Key、录音和通话设备 |
| `Channel`、`Artifact` | 发布结果到频道、在稿子中引用结果；沿用既有附件和稿子权限 | 各写一套生图协议或任务状态 |
| `Tool` 与 HTTP handler | 鉴权并转发到相同的 Media 方法 | 模型调用与业务规则 |
| 页面 | 选用途、输入、观察任务、预览、保存、明确重新生成 | 用浏览器保存长期 Key、折任务事实或直连供应商 |

图像返回 URL，而已安装 SDK 的 `ImageModelV4Result.images` 只收图片字节或 Base64。实现前应保留「生成完成、下载尚未完成」的边界，不能为了塞进 Core 把生成与下载粘成一个可重试步骤。先提供 Provider 的窄 Effect 协议函数；AI 的调用契约应保留 URL 与用量，再由 Media 持久化结果并下载。单人 TTS 等适合现有 Core 契约的能力继续通过 Core，不重复实现 Core 已有的能力。

### 任务与保存

生图是一个应用任务，即使厂商只提供同步 HTTP，也不让浏览器请求一直等到图片下载完。

- 拟用 `media_generation` 保存任务：本地 ID、创建者与目标频道、请求去重 ID、连接 ID 和 revision、模型、冻结后的参数、状态、时间、有限的错误分类、结果资产引用与用量。密钥不入任务表、帧或日志。
- 图像资产复用 `Channel.attach`、附件表与 `attachments/<sha256>`，不另建 `media_asset` 或重复存储目录。附件 25 MiB 上限覆盖当前生图需求；完整临时文件以硬链接原子发布。对外只给本机附件 ID，不把厂商签名 URL 推给帧或日志；下载恢复需要的 URL 仅存服务端私有记录。
- 状态至少区分待发出、生成中、结果待下载、可用、明确失败、结果未知、本地取消。只有文件落盘并记录资产后才能显示可用。
- 创建任务使用调用者提供的去重 ID，同一 ID 与同一参数返回原任务，不再提交厂商；同一 ID 改参数拒绝。每连接先限制 1 个在途生图，队列有上限。
- 请求超时、传输断开、进程退出可能已经产生厂商任务；应标记结果未知，不自动重新生成。取消只停止本地等待，不承诺取消厂商计算或费用。重新生成需要明确的新请求。
- 取得 URL 后先持久化，再下载。下载失败可单独重试；重启后恢复下载，不重新提交生成。重启遇到生成中的任务标记结果未知。
- 下载不携带供应商 Key，不跟随未校验重定向。应校验 HTTPS、公网目标、DNS 解析结果与实际连接目标，拒绝本机、私网、链路本地和云元数据地址；设置时间、字节、PNG 类型与尺寸上限。不能只检查 URL 字符串后交给另一次不受约束的解析。
- 本地资产路由沿用频道或拥有者权限。发布到频道复用 `Channel.attach` 路径，不重写附件权限；若附件接口的大小或复制成本不满足要求，应先明确共用存储边界，再实施，不跨模块直接写频道表。
- 新任务状态经协议事实与 `Core.apply` 折进帧，数据库保留历史，帧只投影有界的近期任务；不在页面或 Provider 另存真相。

### 共用边界的实施决定

以下是 P1.3–P1.4 的设计结论，不代表后续能力已经实现。

| 能力 | 并发与失败边界 | 取消与恢复 | 输入、权限与证据 |
|---|---|---|---|
| 同步生图、理解 | 先持久化再调用；生成未知不重试；生成结果与本机保存分开 | 中断只停本机等待；有结果 URL 才可独立恢复下载 | 主人或有主人委托的管家；来源不由模型参数填写；保留厂商实际报告的用量，未知不写零 |
| 异步 TTS、音色预览、长转写 | 提交和查询分开；任务 ID 先落库；查询暂态失败可有界退避，不重新提交 | 重启只查询已知远端任务；没有任务 ID 的模糊提交标未知；没有官方取消接口就不声称取消远端 | 账号、模型、参数、输入和调用来源在接收时冻结；查询使用对应账号，不回退到当前默认连接 |
| 流式语音、实时音视频 | 限制输入帧率、字节与输出缓冲；断流记录已收到的部分 | 停止、断线、页面离开均释放设备和连接；重启不自动打开麦克风或摄像头 | 开始采集和第三方发送可见；不把非流式下载包装成流式；部分输出明确标记 |
| 文件上传、音色克隆与管理 | 上传、推理、保存音色是不同动作；各有结果 ID 和失败记录 | 远端 ID 已知才管理或删除；不能因为推理未知就删仍可能被读取的远端文件；未知上传不自动重复 | 模型不能传任意服务器路径；克隆需明确样本授权；账号切换不串用音色或文件 ID |

补齐生成权限时，管家的自主巡查不应自行提交可能计费的生成请求；来源档案和频道来自服务端调用上下文，不能信任工具参数。去重包含输入和来源，不允许另一个档案借同一 ID 改写来源。结果可供主人查询，但调用来源在历史中不随档案改名或页面切换被覆盖。

现有 `Channel.attach` 接受 Base64 且限制 25 MiB，适合生图输出，不适合 200 MB 视频或 512 MB 上传。后续大文件由 Media 管输入暂存与大结果资产：独立流式上传/读取接口、服务器生成的资产 ID、哈希落盘，不扩大全部频道 JSON 请求的上限。图片按 30 MB、视频按 200 MB、通用上传按 512 MB 检查，具体模型若更严格取更小值；编码和 MIME 均校验，不凭后缀放行。未被任务引用的暂存文件最长保留 24 小时，暂存总额初始限制 2 GiB；任务引用中的输入与已保存结果不按暂存规则删除。最终产品限制与拒绝文案应在 P3/P5 实现时进入代码和测试。

频道继续拥有附件及消息，Artifact 继续拥有稿子及引用。小结果复用附件；大结果只通过拥有者授权的 Media 读取接口引用，不能直接写 Channel 表、伪造小附件或复制到第二份目录。浏览器播放器只宣称支持实际可播放的格式，其余保留下载，不假设厂商接受的每种输入格式都能在所有宿主播放。

厂商协议在 Provider；可复用的无框架 AI 能力保留原始结果与用量边界，不为一次转手增加包装。任务、账号快照、文件引用和恢复在 Media；设备归 Voice 与各宿主。HTTP 传输应在最外层组装，可在隔离程序中注入协议替身而不改固定厂商地址、不绕过公网下载检查、不新增生产测试开关。这样浏览器成功路径跑真实服务和数据库，不手工拼帧。

尚需实现的缺口对应 P3–P6；尤其异步任务在重启后取得原账号凭据的策略，应保留账号引用及版本并明确拒绝已删除或换 Key 的配置，不能持久化第二份明文 Key 或静默换账号。官方没有确认的删除、取消、重连语义仍应在对应阶段核对。

### 共享配置与权限

为生图、媒体理解和单人语音新增用途绑定，与已有听写同样做 revision 检查；请求开始时冻结连接配置，不在运行途中换账号。绑定引用约束与密钥保留、替换、清除语义继续由 Provider 的一套规则维护。能力选择使用显式已适配模型目录，不依据 ID 前缀推断；快照作为同能力的显式版本选择。

配置管理仍只允许 owner。模型调用的 owner、remote、orchestrator 权限分别声明；帮工通过已有受限工具入口调用，不得到 Key、任意服务器文件路径或任意结果下载代理。媒体上传到第三方的动作应在入口可见，不能把主人本地文件自动批量上传。

## Alternatives considered

**按 11 个模型各造一个入口。** 不采用。同协议只需选择模型与版本，页面和错误处理不应复制。

**直接使用通用图片 SDK，把生成和下载放在一次可重试调用里。** 不采用。MOSS 只返回 URL，下载失败不意味着生成失败；应先保存生成结果，再独立恢复下载。

**先接通一个 HTTP 接口就宣布完成。** 不采用。主人需要结果可看、可保存，agent 需要可引用资产；只有远端 URL 会丢失结果与失败恢复边界。

**先做布局拖拽器或完整音视频编辑器。** 不采用。第一批先交付能力与结果使用，编辑器不是厂商接入的前提。

## Risks

- Beta 模型与当前免费价格会变；不把免费或快照恒定可用写进产品保证。
- 官方生图例子等待 900 秒，长请求与断线可能产生费用和结果未知；必须先完成无自动重试与恢复设计。
- 旧 MOSS Live 协议与当前官方文档可能不同；新增用途不应隐式改掉正在用的通话协议。
- 私有结果 URL、媒体内容与提示词可能包含敏感信息；服务端文件权限、日志脱敏、下载防 SSRF 与访问授权必须一起验收。
- 现有频道附件有自己的大小、格式和存储约束；媒体资产不应靠绕过这些约束发布。
