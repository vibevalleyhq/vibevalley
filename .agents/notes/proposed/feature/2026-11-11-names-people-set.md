# Agent Note: 用户和帮工的名字由人定

Status: proposed

## Problem

用户定过三条（2026-11-10）：人可以设自己的名字；助手叫助手，名字能改；帮工也能改名字。第二条做完了（内置助手默认叫「管家」，在档案页改）。另两条没做：

- **用户的名字只存在账号里。** 设置「设备」页能改名字（`user.update`），但频道里用户这个参与者的名字是死的：`channel/hub.ts` 建用户的参与者时写的是 `t("server.channel.name.user")`。助手的提示词也不知道用户叫什么。
- **帮工不能单独改名。** 帮工的名字来自它的档案；同一份档案派出去的几个帮工名字一样，用户没法给某一个起名。

## Proposal

**用户的名字跟着账号走。**

- `User` 往上给一个名字的流（`names`，改名时发），`Channel` 订阅它，更新用户参与者的名字；历史消息照旧按参与者显示，所以改名后旧消息也显示新名字。没设名字时照旧用词典里的默认叫法。
- 助手的系统提示写上「用户叫 X」（`orchestrator/prompts.ts`），帮工的提示里提到用户的地方也用这个名字；没设名字就不写。
- 页面上用户自己的头像写名字的第一个字（`ui/Face.tsx` 的 `UserFace`，今天是「你」）。

**帮工能改名。**

- 新接口 `session.update`（`can: user`）改一个帮工的 `Session.name`；只改这一个帮工，不改档案，也不改同一档案的别的帮工。名字经 `Core.apply` 折进核心状态，频道里这个帮工的参与者跟着改。
- 页面上在帮工的卡片、轨迹页的标题上能改（点名字就地编辑）。
- 档案改名不覆盖已经单独改过名的帮工。

## Alternatives considered

- **用户的名字由页面在显示时替换。** 页面里另存一份「谁叫什么」，违背核心状态只有一份；命令行、连接器、提示词也都拿不到。
- **帮工改名就是改档案。** 同一份档案的几个帮工会一起改名，用户要的是给某一个起名。

## Acceptance criteria

- 在设置里改名字：频道里用户发过的、新发的消息都显示新名字；助手下一轮的提示里有这个名字（测试读提示）；没设名字时照旧。
- 改一个帮工的名字：频道、帮工列表、轨迹页都显示新名字；同档案的别的帮工不变；重启后还在。
- 测试：`user.test.ts`（名字的流）、`channel.test.ts`（参与者跟着改）、`session.test.ts`（`session.update` 只改一个）、页面的 Playwright 走一遍改名。
- 文档：`user.md`、`session.md`、`channel.md`。

## Risks

- **改名以后，旧消息里的 `@旧名字` 对不上。** `@` 认的是参与者的 id 和别名，不按显示的名字解析；在测试里写明。
