# Agent Note: 聊天照 Discord 补全：回复、改删、回应、附件、置顶、搜索、成员

Status: proposed

## Problem

说话的地方已经照 Discord 分好了（频道、私聊、串，默认频道，按频道订阅，@ 和未读），可一条消息写下就不能动：说错了改不了、删不掉；不能回复某一条；不能贴图、贴文件；没有表情回应，帮工收没收到也看不见（投递的状态只在库里）；找一句话只能在已经读进页面的那几页里过滤；重要的话没法置顶；看不出这个频道里都有谁。

## Proposal

### 1. 消息会变，订阅按修订号续上

- 每个频道有一个修订号（`channel.revision`），频道里的消息每写下或改动一次（改、删、回应、置顶）就把它加一，记在那条消息上（`channel_message.revision`）。`ChatMessage.revision` 跟着发给页面。
- `channel.follow({ id, after })` 的 `after` 改成修订号：先从库里补 `after` 以后变过的消息（按修订号），再推之后的每一次变化；落后超过 `catchUpMax`（200）次就回 `Reset`。推出来的都是消息的整份现状（`Message`），页面按 id 留修订号大的那份，不另设「改了」「删了」的事件。
- 改动不是新消息：不施加 `message` 事实、不投递、不叫醒、不算未读。

### 2. 回复、改、删

- **回复**：`channel.message.send` 带 `replyTo`（同一处的消息号），存在 `channel_message.reply_number`。页面在上面引一行被回复的那条（按号去取）；给 agent 的那一行带上「回复 msg=12」。帮工的 `channel_say` 也能带 `reply`。
- **改**：`channel.message.update { id, text }`，只能改主人自己的聊天消息（不改派活、汇报、提示）；记下 `edited_at`，页面写「（已编辑）」。不重新投递，@ 不重算。
- **删**：`channel.message.delete { id }`（和试跑 `previewDelete`）：主人能删任何一条；正文清空、记下 `deleted_at`，号留着，页面写「这条消息已删除」；还没交出去的投递丢掉（`dropped_why: deleted`）。挂在它下面的串留着。

### 3. 回应和送达

- `channel.reaction.toggle { id, emoji }`：主人点一次加上、再点一次去掉。回应存在消息上（`channel_message.reactions`，`{ 表情: [谁…] }`），页面在消息下面列出每个表情和人数。
- **送达看得见**：一条要叫醒帮工或管家的话交到它手上时（投递变成 `handed`，管家是交出去当即），服务端以它的名义加一个 👀。

### 4. 附件

- `channel.attachment.create { name, type, data }`（base64，至多 25 MB）：存到家目录的 `attachments/<sha256>`，同样的内容只存一份，回 `Attachment { id, name, type, size }`；`channel_attachment` 一行记名字、类型和大小。发消息时 `attachments` 带这些 id，消息上存它们的说明。
- 页面读一个附件是 `GET /api/v1/attachment/<id>`：`<img src>` 发不了 POST，这是除了三条流以外唯一的 GET；「连接到本机」也放它。
- 给 agent 的那一行写附件的名字和它在这台电脑上的完整路径，帮工直接读文件。
- 页面：输入框的回形针和粘贴图片；图片在消息里直接显示，别的是一个文件条。

### 5. 置顶、搜索、成员

- **置顶**：`channel.pin.toggle { id }`，消息记下 `pinned_at`；`channel.pin.list { id }` 列出一个频道的置顶，频道头上一个按钮打开。
- **搜索**：`channel.message.search { text, id? }`：在全农场（或一个频道和它的串）里找含这些字的消息，新的在前，至多 50 条，每条带它的地址；不再只过滤读进来的几页。
- **成员**：聊天页右边一栏：主人、管家和这个频道里的帮工（带阶段）；私聊只有两边。

### 6. 页面照 Discord 排

- 悬停一条消息出一排操作：回应、回复、开串（`channel.thread.create { id }`，在这条下面开一个串）、置顶、改（自己的）、删。
- 输入框上方显示「回复 某某」，可以取消；改的时候消息原地变成输入框，回车存、Esc 放弃。
- 进一个频道时，主人上次读到的地方画一条「新消息」线。
- 农场的田头窗口照同一份规则画：回复的引用、已编辑、已删除、回应、附件；操作只在工作台的聊天页里。

## Alternatives considered

- **先把状态帧和窄流并进同一条 WebSocket（Discord 的 gateway）**：聊天的每种变化都能经按频道的订阅续上，用不着它；搬状态帧要重写 e2e 里所有拦截 `/api/v1/state` 的测试。并成一条连接归 [页面的连接接着带上在线状态和工单的增量](.agents/notes/proposed/architecture/2026-10-27-presence-and-entity-deltas.md)。
- **改、删、回应各一种事件**：页面要分别合并、补齐时要分别补；推消息的整份现状、按修订号补，一种就够。
- **回应单独一张表**：一个写入方、消息本来就要整份推，存在消息上读的时候不用再查一次。
- **正在输入**：只有一个主人，没有别人看他打字；管家在想、在写已经在核心状态里（`orchestratorChannel`）。
- **和帮工档案的私聊、语音频道**：帮工是一次派活，和档案私聊要先定由哪一次执行接话；语音频道接在电话那条线上，等电话的接法定下来再说。都不在本篇。

## Acceptance criteria

- 主人能回复、改、删自己的话，删别人的；页面在别的标签页里同时看到变化，断线回来补齐。
- 回应能加能去；叫醒帮工的话交出去以后带一个 👀。
- 贴一张图，消息里显示出来；帮工读到的那一行有文件的路径。
- 置顶能看、能取消；搜索能找到没读进页面的话；聊天页列出频道里的成员。
- 测试：修订号的补齐和 `Reset`（真的库）；改、删、回应的规则和权限；附件的存取和大小上限；页面的 Playwright 走一遍回复、改、删、回应、贴图、置顶、搜索。

## Risks

- 老的库作废（照「内部不留兼容」）：消息表加列，频道加修订号。
- 管家和帮工的提示、工具描述变了（回复、附件），管家的评测要重跑（花钱，先问主人）。
