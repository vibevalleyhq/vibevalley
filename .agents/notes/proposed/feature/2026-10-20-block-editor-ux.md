# Agent Note: 几个帮工同时写一篇文章：在屏幕上看起来怎样

Status: proposed

## Problem

多个帮工同时协作撰写同一篇 `blocks` 稿子（[稿子](docs/subsystems/artifact.md)）时，块级同步与改写建议 `Suggestion` 已就绪，但还缺少三项章节级组织与审阅交互：
- **分节与子工单未打通**：管家拆出多张子工单合写一篇文章时，稿子左栏没有按子工单展示「哪一节由谁负责、哪一节已写完待看」。
- **缺少按节确认状态**：帮工写完或改过的章节没有「未看 / 已确认」标记，用户无法逐节勾完再完成父工单。
- **缺少按节管控快捷入口**：无法在文档大纲行直接叫停、换人或要求重写某一节。

## Proposal

1. **一篇文章绑定一张父工单**：每个章节标题块关联一张子工单（按 `parent` 与 `blockedBy` 排先后）；帮工在负责章节内直接写块，跨章节或改用户块一律生成 `Suggestion`。
2. **左侧章节大纲状态**：每节一行，展示标题、负责帮工头像与状态点（待写 / 在写 / 写完待看 / 已确认）；顶部显示「已确认 M / N 节」进度与「只看未确认」过滤开关。
3. **逐节确认与管控**：用户读完一节点击「确认这一节」清除未看圆点；章节标题旁提供叫停、带话重写与换人按钮（全部章节确认后完成父工单）。

## Alternatives considered

- **显示逐字实时光标**：块协同以块为单位定序，多个帮工并发流式输出时逐字光标会满屏跳动；按块显示作者头像与呼吸条更清晰。
- **每个帮工各写独立草稿最后合并**：用户无法边写边看全貌，且最终合并冲突仍落回用户身上。

## Acceptance criteria

- 父工单拆出三张子工单合写一篇稿子时，大纲栏实时显示各节负责帮工与「在写 / 写完待看 / 已确认」状态。
- 打开「只看未确认」可淡化已确认段落；点击「确认这一节」更新状态，可直接在大纲行叫停或让帮工重写该节。

## Risks

- 多个帮工同时流式写块时界面变化密集，需支持折叠在写章节或等单节写完再展开。
