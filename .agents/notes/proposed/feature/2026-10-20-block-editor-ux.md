# Agent Note: 几个帮工同时写一篇文章：在屏幕上看起来怎样

Status: proposed

## Problem

[块编辑器协同](.agents/notes/proposed/feature/2026-10-20-block-editor-collab.md)定了数据和同步：按块存、按 op 改、服务端说了算、presence 只提示不上锁、agent 走同一条 op 管线。那篇没回答主人在屏幕上看到什么：

- 三个帮工同时往一篇文章里写，主人一眼要知道**谁在写哪一段、写到哪了、哪些写完等我看**；不知道就只能一段段翻。
- 字一段段冒出来，主人一边读一边改。要说清楚**人正在改的地方，帮工怎么让开**；帮工改了人写的字，人怎么知道、能不能不要。
- 写完以后，主人要**分得清哪些是帮工写的、还没看过**，像收获前看收成清单一样一段段确认。
- 帮工写偏了，要能**叫停一个、让它重写一段**，而不是整篇推倒。

## Proposal

### 一篇文章就是一个种植计划

不另造一套分工：主人说「写一篇关于 X 的文章」，管家照[种植计划](docs/subsystems/task.md)把它拆开。

- 文章是带 `graph` 的父工单，正文就是这篇文档；**每一节是计划里的一件**（子工单），派给一个帮工。有先后的（比如「结论」要等前面几节写完）照计划的 `blockedBy` 排。
- 计划板上看得到每一节谁在写；文档里看到的是同一件事的另一面。两边的状态是同一份，不各算各的（[核心状态只有一份](AGENTS.md)）。
- 一节对应文档里的一个标题块和它下面的块。帮工的写入范围就是它那一节：在自己那节里直接写，改别的节只能留建议（见下）。

### 页面

三栏，手机上收成一栏：

| 位置 | 放什么 |
|---|---|
| 左：大纲 | 每一节一行：标题、帮工的头像、状态点（待写 · 在写 · 写完待看 · 已确认）；点一行跳到那一节。顶上一条进度：几节写完、几节确认 |
| 中：正文 | 文档本身。每一块左边有一条细的归属条，颜色是写它的人或帮工的颜色 |
| 右：动静 | 按时间的一列：「老周写完了『背景』」「阿郑想改你写的一句」；建议和冲突也在这里排队。默认收起，有要主人处理的才亮 |

手机上只留正文，大纲和动静从顶上拉出来；在写的那一节在顶上挂一条细横幅「老周在写『背景』」，点了跳过去。

### 谁在写哪一段

按块显示，不做逐字光标（协同约定里同一段不逐字协同）：

- **在写的块**：左边的归属条变粗、带一点呼吸的动画，块旁边挂着帮工的头像（档案里的小动物），头像下一行小字「在写」。人进入编辑的块，挂的是主人自己的头像，帮工看到会让开。
- **字怎么出来**：帮工流式写入时，先插一个空块，再按协同约定的节流（1 秒一次）把这一块整段换新，看起来是一段一段长出来，不是一个字一个字跳。正在长的块末尾有一个闪动的小方块，长完消失。
- **写完一节**：大纲里那一行变成「写完待看」，那一节的头像换成完成的姿势；动静里出一条，频道里也说一句（照现在帮工汇报进频道的路子）。

### 人和帮工碰到同一段

协同约定已经定了：有人在编辑的段落，agent 不改，改在后面插新块或等。界面上：

- **帮工想改人写的、或别人那一节的字**：不直接改，变成一条**建议**。建议显示在原块下面：删掉的字划线、加的字底色标出，旁边「接受 / 不要」两个按钮，标着是谁提的。接受时用当时的 `baseRev` 提交，走正常的冲突规则；原块已经被改过、合不上，就提示「这段后来改过，建议过期了」。
- **帮工在自己那一节里**：直接写，不走建议；但主人改过的块，帮工再改也要走建议，不能把主人的字悄悄换掉。
- **人在帮工正写着的块里打字**：这一块马上归人，帮工停在这一块上的流式写入，挪到后面新插一块继续，不和人抢同一块。
- **合并失败**：照协同约定第 3 层，这一块挂一条提示「这段刚被老周改了，你的版本没存」，提供「看我的版本 / 用我的覆盖 / 放弃」。

### 看过和没看过

照收获前要看收成清单的路子，帮工写的东西要主人过目：

- 帮工写的块，归属条是帮工的颜色、带一个小圆点表示「还没看」；主人读过、点「确认这一节」后，整节的圆点消失、大纲里变「已确认」。主人自己写或改过的块不需要确认。
- 「只看没看过的」开关：打开时正文里看过的块变淡，只剩要看的。
- 整篇都确认了，计划才能「收获」：父工单走完，文章定稿。这一步就是种植计划已有的收获，不另做。

### 主人怎么管

都在大纲那一行或那一节标题旁，用像素图标的按钮，不用字符：

- **叫停**：停掉这一节的帮工，已经写出来的留着（就是叫停那件的帮工，走 `session.stop`）。
- **重写这一节**：给它一句话说哪里不对，帮工按这句话重写；旧的那版留在修订历史里，能找回。
- **换个人写**：改这一件写定的档案（计划里的一件本来就能写定用哪个档案，`graph.task.update`，管家用 `graph_task_update`），没开工的下次调度按新档案派；在写的先叫停再改。
- **在一块上 @ 帮工**：在块的评论里说「@老周 这里展开讲讲」，变成给这一节帮工的带话。

### 农场那张皮

工作台里是上面这个页面；农场里只画它对应的事，不另做一套逻辑：写文章的帮工坐在书桌前（干活的姿势换成写字），写完一节冒一张纸，整篇确认后收获冒金币。点帮工打开的是工作台的这篇文档，跳到它那一节。

## Alternatives considered

**像 Google Docs 那样逐字显示每个人的光标。** 看着热闹，可协同约定是按块合并的，不支持同一段逐字协同；几个帮工同时流式写，满屏乱跳的光标也看不清谁在干什么。按块显示「谁在写这一段」够用。

**每个帮工各写一份草稿，最后合并成一篇。** 不会互相干扰，但主人要等全部写完才看得到全貌，也没法边写边改；合并时的冲突又回到了人身上。直接写进同一篇、各占一节更直观。

**帮工改任何地方都直接改，不走建议。** 最省事，但主人的字会被悄悄换掉，主人就不敢放手让帮工改。只在别人的地盘上走建议，自己那一节直接写，兼顾了速度和放心。

**另做一个「写作」的分工系统，不用种植计划。** 要再做一遍派活、先后、叫停、改派、进度；种植计划已经有这些，一篇文章正好是一个计划。

## Acceptance criteria

- 主人说「写一篇关于 X 的文章，分三节」，管家拆出一个三件的计划；文档页左边大纲三行各挂一个帮工，三节同时在长，每节旁边是写它的帮工头像和「在写」。
- 某一节写完，大纲里那一行变「写完待看」，动静和频道各出一条；主人点「确认这一节」后变「已确认」，那一节的未看圆点消失。
- 主人在帮工正写着的块里打字：主人的字留着，帮工的后续内容出现在后面的新块里，没有一个字被盖掉。
- 帮工改主人写过的块：出现一条建议，接受后生效、不要则原样不动；原块后来被改过时显示「建议过期了」。
- 叫停一节：那一节的帮工停下，写出来的留着；重写一节：新版本替换旧版本，旧版本在修订历史里找得回。
- 手机宽度（390×844）下正文可读，在写的那一节有顶部横幅，大纲能拉出来。
- 以上用 `apps/web` 的 Playwright（对着真的服务端）覆盖，并照 vv-acceptance/references/page.md 截图：三节同时在写、一节待看、一条建议、手机宽度各一张。

## Risks

- **太吵。** 三个帮工一起写，正文一直在动，动静一直在刷，主人反而读不下去。靠节流、动静默认收起、「只看没看过的」开关压；真吵还可以加「写完再给我看」：写的过程中正文只显示「老周在写『背景』……」，写完一次性出现。
- **建议太多。** 帮工爱改别人的字，主人要一条条点。要在管家和帮工的提示里说清：先写自己那一节，改别人的要有理由；一节里的建议可以「全部接受 / 全部不要」。
- **确认流于形式。** 主人可能一路点「确认」不看；这和收获前看收成清单是同一个问题，界面只能让没看过的显眼，管不了人看不看。
- **和计划板两处显示同一件事。** 状态必须只算一份、在服务端，两处都只读它；哪边自己推出状态，两边就会对不上。
- **有意放弃的**：逐字光标、离线写作、多个帮工在同一段里同时写。
