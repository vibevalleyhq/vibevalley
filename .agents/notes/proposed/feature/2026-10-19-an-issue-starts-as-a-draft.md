# Agent Note: 写工单是起草：点加号就建好，帮工照格式写

Status: proposed

## Problem

写工单现在是一张表单：主人自己填标题、说明、项目、派给谁，填完「先存着」或「开工」（`workbench/issues/issue_detail.dart` 的 `TodoDetail`、农场的播种袋）。

- **主人不想写格式。** 一句「看板拖卡还在调旧接口」就是他想说的；要做什么、怎么算做完、碰哪些文件，是读过代码的人才写得出来的。
- **工单写得粗，验收就没有依据。** 每张工单都有验收（[工单](docs/subsystems/issue.md)），可验收照什么验，工单上没有；帮工交回来，主人只能凭印象看。
- **「聊清楚」这一段没有人干。** 三段里第一段是聊清楚，现在它只是 `backlog` 这一列，没有谁帮主人把一句话变成一张能派的工单。

## Proposal

**点加号就建一张备选工单；主人写一句想做什么，农场派一个帮工起草，照固定的格式填回工单。主人改、回答它的问题，点「开工」才派活。**

1. **加号直接建**：看板的「写一张待办」、农场的播种袋「自己写」、地图岛上的空位，都直接 `issue.create`（`backlog`，标题先是主人那一句），打开它的详情弹窗。详情第一层是一个输入框「想做什么」和「起草」。
2. **起草**（新接口 `issue.draft`，`POST /api/v1/issues/{id}/draft`，带主人那句话或回答）：
   - 谁起草：工单的 `assignee`；没有就是这个项目上次派活的档案；再没有按 `ChooseAgent`。
   - 在这张工单自己的 worktree 里起草（`project.Workplace` 按工单开，和后面干活是同一个）。Run 的触发是新的 `draft`。
   - 起草的规矩（`session/rules.go`，照规划师 `SplitBrief` 的写法）：只读代码，不改文件、不提交；拿不准的写「要问主人：」；最后用一个 json 代码块交草稿：`title`、`why`、`todo`、`criteria`（逐条）、`notDoing`、`files`。
   - 交回来：服务端解析代码块（照 `parseSplit`），写回工单：`title`、`description`（用固定小标题拼：为什么、要做的、不做的、可能涉及），`criteria`；问题照旧进 `asks`（缺肥）。然后把 worktree 重置回基分支（`git reset --hard`、`git clean -fd`，起草不留下任何改动），帮工离开。解析不出来就在工单串里说一句，工单不变。
   - 工单仍在 `backlog`；`Issue.Drafting`（正在起草）由核心状态里帮工的 Run 触发现算，不另存。
3. **回答问题**：工单在 `backlog` 且有 `asks` 时，主人在同一个框里说的话就是回答，再起草一版（带着上一版草稿和回答）。
4. **字段**：`Issue.Criteria []string`（验收标准），`issue.update` 能改；表里 `issue.criteria`（JSON）。
5. **开工**：照旧挪到待办（`issue.status todo`）。派活的提示里带上验收标准；验收时详情把标准逐条列出来，主人照着勾。
6. **客户端**：加号不再弹表单；详情里备选工单的第一层是草稿（各栏可改）、问题、「起草 / 再起草」和「开工」；正在起草时状态写「<帮工>在起草」。卡片上写「草稿」。

## Alternatives considered

**在项目的主检出里只读起草。** 不用开 worktree，快；可「只读」只能写在提示里，帮工改了文件就改在主人的主分支上。用工单自己的 worktree，起草完重置，改动不出这张工单。

**让管家起草。** 管家已经在了，不用派帮工；但管家只看得到农场的状态，读不了代码，写不出要碰哪些文件、怎么验收。

**草稿交回来以后让主人手动点「填进工单」。** 多一步确认；但主人随时能改每一栏，直接填进去少一步。

**起草要主人点按钮才开始。** 省钱；可主人写了一句话，要的就是一张写好的工单。花费照常记在这张工单上，卡片上看得到。

## Acceptance criteria

- `workspace` 的测试（`oartest`、真的 git 仓库）：建一张工单 → 起草 → 帮工交回草稿代码块 → 工单的标题、说明、`criteria` 填好，`asks` 记下，worktree 干净、分支上没有提交，帮工离开，工单还在 `backlog`；回答问题再起草，第二版覆盖第一版。
- 起草的帮工改了文件、甚至提交了，交回来以后 worktree 回到基分支。
- 解析不出代码块：工单不变，工单串里有一句说明。
- 开工以后派活的提示里有验收标准。
- 客户端：加号直接建、打开详情；备选工单显示草稿各栏和「起草」「开工」；正在起草显示「在起草」。

## Risks

- 每张工单起草都要花钱：用档案默认的模型，花费记在工单上；要省钱可以以后加「不起草，直接写」。
- 起草开了 worktree，取消一张从没开工的工单要清掉它（照取消时的规矩：没有提交的分支和 worktree 删掉）。
