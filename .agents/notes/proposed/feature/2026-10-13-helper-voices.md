# Agent Note: 帮工各自的音色

Status: proposed

## Problem

主人想让每个 agent 的语音设置放在它自己那里。管家页已经有了自己的「声音」页签（[管家页和记性面板](docs/subsystems/orchestrator.md)），可帮工没有。现在只有管家会开口，帮工的汇报只能在频道里看：听不出是谁在说，也不能边干别的边听。

## Proposal

- 在 protocol 的 `Agent`（帮工档案，`packages/protocol/src/shapes.ts`）上加一个可选的 `voice`，只存和默认不一样的：音色（MiniMax 的 `voiceId`、OpenAI 的 `voice`、微软的 `voiceName`），可以再加一句开场白。捏帮工页加一个「声音」页签来配。
- 先让它在**频道朗读**里用上：客户端打开「听汇报」以后，帮工的汇报用各自的音色念出来。在客户端合成，不经过 Agora 的通话。
- 以后再考虑：
  - 管家在通话里转述汇报时换成帮工的声音。要先确认 Agora 的 speak 接口能不能临时换音色，不能就得另开会话。
  - 主人直接给某个帮工打电话。
- 待定：在客户端合成用哪家（系统自带的语音合成还是 MiniMax 的接口）、key 从哪来、要不要花钱，这些决定朗读能不能默认打开。

## Alternatives considered

**马上加字段，以后再接上用的地方。** 没有用处的设置会让人以为改了就有效果。等到第一个会出声的地方做出来再加。

**所有帮工共用管家的音色。** 最省事，但听不出是谁在说话，这个功能就失去了意义。

## Acceptance criteria

- 捏帮工页能给一个帮工选音色，存下来，重启后还在。
- 打开「听汇报」以后，两个音色不同的帮工汇报时，听得出是谁在说。
- 没配音色的帮工用默认音色；没有 key 或合成失败时只是不念，频道照常。

## Risks

- 在客户端合成可能要另一份 key，也会多花钱。
- 好几个帮工同时汇报时会念成一片，要排队，或者只念结论。
