# Agent Note: 素材库：生成的、你上传的、帮工拿回来的文件都在一处

Status: proposed

## Problem

「媒体」页（`/media`）是一排生成工具：生图、理解图片与视频、单人语音、音频工作台，加上最近的任务。用户关心的是东西本身，不是工具：

- **生成的**：生图、语音、对白、音色的结果，今天都已存成频道附件（`media_job.attachment`），但只能在任务列表里一条条翻，或者回聊天里找。
- **你上传的**：在聊天里发的附件散在各频道；在媒体页为理解、克隆、转写上传的文件存在 `media_input`，到期就清掉。
- **帮工拿回来的**：帮工和助手从网上下载的图、从仓库里找出的文件，没有地方放：`attachment.create` 只开给用户和配对的设备（`can: ["user", "remote"]`）。

## Proposal

**一页叫「素材库」，路由 `/library`。** 页面打开就是素材的网格，筛「全部 / 生成的 / 你上传的 / 帮工拿回来的」和种类（图、音频、视频、其它）。一张卡：缩略图或播放条、名字、来路（谁、什么时候、从哪：哪个任务、哪个频道、哪个网址或文件）。卡上能下载、发到一个频道、从库里拿掉；图和视频能「理解」（拿这个文件发起理解，结果挂在这张卡上）。在做的生成任务在网格最前面占一张卡，显示阶段。生成的表单收进「生成」按钮打开的对话框（生图、单人语音、音频工作台照旧）；平时让助手在聊天里生成。

**一份素材是一个附件加它的来路。** 新模块 `library`（在 Channel 和 Media 之后），表 `library_item`：附件（`attachment` 的 id，即内容的 sha256）、名字、种类、来路和加入时间。来路是封闭的联合：

- `generated`：媒体任务的 id 和种类。Media 的任务 `ready` 拿到附件时记一条。
- `uploaded`：用户在聊天里发出带附件的话（记频道和消息），或在素材库页上传。素材库的上传就是 `attachment.create` 再加一条，长期保留，不进 `media_input`。
- `fetched`：哪个档案、哪个帮工（会话）、从哪个网址或工作目录里的哪个文件。

同一个文件只占一张卡，记第一次的来路；以后再来只更新「最近一次」。从库里拿掉只删这一行，附件还被消息用着就留着。

**帮工和助手能往库里放东西。** 新接口 `library.item.add`（`can`：用户、助手、帮工）：给一个 `http(s)` 网址，或自己工作目录里的一个路径。网址经 `publicHttp` 下载（只拨公网，限大小和类型，同媒体的下载）；路径只认它的工作目录下的、解析了符号链接以后仍在里面的文件。答复附件的 id 和名字，帮工可以在消息里带上它。工具描述写明：用户要的、做活时找到的、值得留的图和文件放进来，不要把中间产物都放进来。

**理解从素材发起。** 理解要的 `media_input` 在发起时由附件的字节建出来（照旧限额、保留和远端清理），用户不再为理解单独上传。

不收：通话和听写的录音、摄像头和屏幕的画面、头像、稿子（它们有自己的页面）、帮工改的代码。

## Alternatives considered

- **不建表，直接列所有附件，按发它的消息推来路。** 生成的结果在发到频道前就是附件，没有消息；素材库页的上传也没有消息；拿掉一张卡就得删附件或改消息。来路要单独记。
- **来路记在 `attachment` 上。** 附件按内容去重，同一个文件可以既是生成的又被人发过；附件归它自己的模块（`Attachment`）管存和取，素材是另一件事。
- **让帮工经 `attachment.create` 上传字节。** 帮工在 MCP 里传大段 base64 费 token、容易截断；给网址或工作目录里的路径，由服务端去取，更省也更好查。
- **保留现在的工具页，另加一个「素材」标签。** 用户说只关心生成的和采集的东西，工具不该占着首页。

## Acceptance criteria

- 生图、语音、对白、音色的任务完成后，素材库里出现一张「生成的」卡，点开看得到任务的提示和用量。
- 在聊天里发一张图、在素材库页上传一个音频：各出现一张「你上传的」卡，写着来自哪个频道或这一页。
- 帮工调 `library.item.add` 给一个网址或工作目录里的文件，库里出现一张「帮工拿回来的」卡，写着哪个帮工、从哪；工作目录外的路径、内网地址、超限的文件被拒，拒的话说清原因。
- 同一个文件第二次进来不多一张卡；拿掉一张卡后发过它的消息仍能打开附件。
- 对一张图点「理解」，结果挂在这张卡上。
- 服务端测试：`library` 模块（来路、去重、拿掉）、`library.item.add` 的路径和网址检查、Media 完成后记一条；流程测试：帮工照字眼放一个文件进库。页面：Playwright 走上传、筛选、发到频道，按 `data-testid` 找元素，每页一次 axe。
- 文档：新的 `docs/subsystems/library.md`，`media.md` 只讲任务；用语表加「素材库」（library），「不用」写「媒体（指这一页时）」；`/media` 删掉，不留跳转。

## Risks

- **帮工乱放。** 工具描述说清什么值得留；库里拿掉很容易。真模型的表现用评测看（花钱，先问用户）。
- **下载外面的东西。** 只经 `publicHttp`（公网 IPv4、限大小、类型和时间）；路径防符号链接逃出工作目录。
- **大文件占盘。** 附件已按内容去重；单个文件的上限沿用媒体的下载上限，超了拒绝。
