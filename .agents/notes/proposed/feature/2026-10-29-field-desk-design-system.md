# Agent Note: 田间工作台：VibeValley 的设计体系，先成文、再成令牌、再成检查

Status: proposed

## Problem

VibeValley 有自己的样子，但只散在代码和几篇文档里，没有一处说清楚：

- **审美没有成文**：工作台是暖纸色、像 Linear 的工作界面，像素皮是画出来的农场，两张皮共用一套按用途起名的调色板（`apps/web/src/style.css` 的 `--wb-*`，深色主题换一套值，`vibevalley/no-hex-color` 拦写死的颜色）。这些决定散在 [客户端](docs/subsystems/app.md) 的「为什么这样」、[农场的皮](docs/subsystems/farm.md) 和代码注释里；新加一个界面的 agent 只能照着旁边的代码抄，抄到的往往是例外。
- **调色板之外没有令牌**：圆角有 `rounded-[3px]`、`rounded-[10px]` 这样的散值；三处阴影把颜色写死在 `shadow-[…#2f1f13…]` 里（深色主题下不变，`no-hex-color` 只认 `-[#…]` 拦不到）；字号在 12、13、14 的阶梯外还有 10、11、11.5、12.5px；动效的时长有 75、150、180、200ms 四种，缓动全靠浏览器默认；禁用的透明度有 40、50、60 三种；数字很少用等宽数字。
- **没有一张对得上的总图**：主人给了一份八篇的设计体系大纲（令牌、原子组件、会话流、动效、多媒体、桌面、工程、给 agent 的指南），我们哪些已经有、哪些缺、哪些不适合我们，没人说过。

## Proposal

### 1. 成文：`docs/style/design.md`

和 [code.md](docs/style/code.md)、[writing.md](docs/style/writing.md) 并列，写「界面怎么做」：

- **审美**：叫「田间工作台」。几条原则：两张皮一份调色板；暖而不甜（纸色和墨棕，不用纯黑纯白）；颜色只说状态（叶是好和主操作、麦是在等和在想、莓是坏和危险、水是信息）；安静的密度；层级靠表面的阶梯，阴影只给浮起来的；一个块一圈线；动效说因果、不表演，像素皮走帧；只画真数据。
- **令牌**：表面、颜色、圆角、控件高、边和阴影、字、图标、动效、层，每一类一张表，值以 `style.css` 为准。
- **原子和模式**：按钮的阶梯、分段、状态点、对话框和两次确认、附件和胶囊、消息、在想和在写、输入框、工具步骤、空状态、出错和限流。
- **给 agent 的速查和自检清单**。

主人那份八篇大纲逐章对过：已经有的写进本篇，缺的列进第 4 节的路线，不适合我们的写明为什么不做。

### 2. 成令牌：补齐 `style.css`

- **圆角**：`rounded-xs`（3px：行内的标记、键帽、@ 名）、`sm`（4px）、`md`（6px：控件）、`lg`（8px：卡片、面板、对话框）、`xl`（12px：大的浮层）、`full`（胶囊、头像、点）；散值换成它们。
- **字号**：在 12、13、14、16、20 下面加 `text-2xs`（11px，行高 14px），给角标、计数和键帽；10、11.5、12.5px 收进阶梯。
- **阴影**：`shadow-raise`（贴着表面的一层，分段的滑块、悬停的卡片）和已有的 `shadow-float`（浮层：菜单、对话框、toast），颜色走调色板，深色跟着换。
- **动效**：缓动 `ease-out`（`cubic-bezier(0.2, 0, 0, 1)`，进来和大多数变化）、`ease-in`（`cubic-bezier(0.4, 0, 1, 1)`，离开）、`ease-in-out`（位置和大小来回）、`ease-spring`（`cubic-bezier(0.34, 1.4, 0.64, 1)`，只给弹出来的小东西）；时长三档：120ms（悬停、按下）、180ms（默认）、280ms（面板、对话框进出）；`transition-*` 不写时长就是 180ms 加 `ease-out`。系统要求减少动效时，工作台的过渡和动画一律近乎为零。
- **层**：`z-10` 黏在顶上的、`z-20` 菜单和浮层、`z-30` 抽屉和侧面板、`z-40` toast；对话框走原生的顶层，不排进来。
- **禁用**：一律 `opacity-50`。
- **数字**：计数、时间、金额、百分比用 `tabular-nums`。
- **滚动的边**：`scroll-fade-y` 让能滚的列表在还能滚的那一边淡出 16px，滚到头就不淡（CSS 的滚动时间线，不跑脚本）。

### 3. 成检查

- `vibevalley/no-hex-color` 也拦方括号里任何位置的 `#…`（`shadow-[0_1px_2px_#…]`）。
- 新的 `vibevalley/design-tokens`：工作台里不写 `rounded-[…]`、`text-[Npx]`、`ease-[…]`、不在阶梯上的 `duration-*`；像素皮和头像照旧是画的，不管。
- 根目录 `AGENTS.md` 加一条规矩，链接到 `docs/style/design.md`。

### 4. 顺手提升的体验

- 分段控件的滑块跟着主题、有 `shadow-raise`，选中时滑过去（`ease-out`）。
- 菜单、浮层、对话框进来时从 98% 放大淡入（280ms，`ease-out`），出去更快。
- 按钮按下时有一个像素的下沉（120ms）。
- 侧栏、消息之外的长列表用 `scroll-fade-y`。
- 未读数、时间、额度用等宽数字。

### 5. 大纲里还缺、留到以后的（各自一篇提案）

在 `docs/style/design.md` 的「和大纲对照」一节逐章写；需要另起提案的：思考过程的时间状态机（在想多久、折叠）、斜杠命令、工具调用的批准卡片、消息的流式输出和到底部的跟随、看板和侧栏的拖动物理、双栏的可拖分割线、媒体查看器的转场、代码差异的语法高亮。

## Alternatives considered

- **照搬那份大纲的数值（玻璃材质、渐变光效、着色器、多套弹簧）**：那是一个通用 AI 聊天应用的样子；我们是暖纸色的工作台加像素农场，玻璃和霓虹光会把两张皮拆成三张。只取它的骨架（分类、令牌、检查），值按我们的审美定。
- **把令牌做成 TypeScript 常量**：页面的样式写在 Tailwind 的类里，令牌放在 `@theme` 才能直接写成类，深色主题也只在 CSS 里换。
- **只写文档不加检查**：照「怎么让 agent 做对」的顺序，能写成检查的先写成检查；文档只放要判断的。
- **一次把所有页面重画**：先定令牌和检查，把散值收进阶梯；大的交互（思考时间线、拖动、分割线）各自一篇提案，一个 PR 一件事。

## Acceptance criteria

- `docs/style/design.md` 写清审美、令牌、原子和模式、和大纲逐章的对照、给 agent 的清单；文档地图和根目录 `AGENTS.md` 指向它。
- 工作台里没有 `rounded-[…]`、`text-[Npx]`、写死颜色的阴影、阶梯外的时长；lint 拦得住新的。
- 深色主题下分段的滑块、卡片的阴影跟着换。
- 减少动效时工作台不动。
- e2e 和桌面版的测试照旧过；截图看浅色、深色各一遍。

## Risks

- 收散值会动到好些页面的几个像素：每一处照令牌挑最近的一档，改完浅色、深色各截一遍图对比。
- 滚动时间线（`animation-timeline: scroll()`）只有 Chromium 系的认：桌面壳和手机壳的 WebView（安卓）认，Safari 打开时不淡、照常能滚。
