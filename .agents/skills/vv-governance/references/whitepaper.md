## 研发经济学的逆转

白皮书的出发点：传统软件工程的方法都建立在「写代码贵、改代码贵」上，agent 来了，这个前提没了。八个维度：

| 维度 | 传统（人写） | agent 写 | 维护转向 | 在这里 |
|---|---|---|---|---|
| 稀缺的资源 | 人敲键盘的工时 | 架构一致、契约完备、人审的注意力 | 从提速写代码转向减轻人审 | 已有：[AGENTS.md](AGENTS.md#怎么让-agent-做对) 第 4 层「人看」，人的精力花在设计让 agent 默认做对的环境上 |
| 核心资产 | 实现源码 | 协议 Schema、状态机契约、验收测试 | 实现是廉价产物，契约是资产 | 已有：形状只在 `packages/protocol`，核心状态只由 `reduce` 折，规则有黄金数据。以后做：契约的 diff 进 CI 摘要 |
| 演进偏好 | 修补旧代码（重写太贵） | 300 行以内的模块删光重生成比打补丁便宜 | 细胞化，随时重生成 | 以后做：契约稳定以后（现在契约一个月改几十次） |
| 抽象怎么来 | 人写的时候顺手提炼 | agent 只做局部最小改动，不主动提炼 | 抽象归约是单独的工序 | 改写：重构单独成 `refactor/` PR，靶子来自体检和 [vv-simplify](.agents/skills/vv-simplify/SKILL.md) |
| 目录 | 按技术角色横向分层（MVC） | 横向分层让 agent 跨目录找、丢上下文 | 按特性垂直切、单目录自包含 | 已有：服务端一个概念一个文件夹（`apps/server/src/modules.ts`），页面一个概念一个 `features/<概念>`，经 `index.ts` 用 |
| 测试腐化 | 人写得少，覆盖不足 | agent 写出绑死内部细节的 mock 和重复测试 | 不用零散 mock，用内存假实现和属性测试 | 已有：假的只在端口上（oar 的 `scriptedRuntime`、照脚本回答的 `Llm`），git 用真的；黄金数据是带种子的随机输入 |
| 并发冲突 | 同一行的文本冲突 | 跨文件、没有文本冲突的接口语义和状态假设冲突 | 合并队列组合预演，符号锁 | 以后做：并行的 agent 多起来以后开 GitHub 的 merge queue |
| 文档过期 | 架构文档几个月一更，靠老人口传 | 自然语言文档两周就过期，误导 agent | 不靠手写长文档，用 AST 提取原语词典 | 改写：文档只写现状、和代码同一个改动里改，`docs:verify` 查链接和反引号里的路径；生成的清单（`CATALOG.md`、能力表）不手写。以后做：共用帮手的生成清单 |

## 六种病

白皮书说，用了最好的模型，代码库照样两个月内变坏，原因在模型的工作方式。

**一、局部缝合。** 机理：模型要在有限的上下文里用最少的改动让指令跑通；提炼公共抽象要改没加载的文件，在模型看来风险高。例子：微信通知里有 40 行截断和重试，加飞书、QQ 时原样抄了两份，一个月后改截断规则，只改了微信和飞书，漏了 QQ。
在这里：connector 的重试、退避、暂停已经收在 `apps/server/src/connector/connector.ts`，各聊天软件实现 `connector/adapter.ts` 的 `Adapter`；但 adapter 仍各自写超时（10、20、25 秒）和登录的轮询。以后做：扩展点只填空（先做农场的工具）。评审时照 [SKILL.md](.agents/skills/vv-governance/SKILL.md#2-评审一块代码有没有在变坏) 查。

**二、只加不删。** 机理：agent 不确定一个导出是不是还被反射或外部脚本用，为了编过，只加新的、不删旧的。例子：轮询改成 WebSocket 推送，新写了 streamStatus()，旧的 pollStatus() 连 5 个帮手、12 个测试都留着；半年后 40% 是没人调的僵尸代码，后来的 agent 把它当现行的照抄。
在这里：已有「内部不留兼容」（改名、改形状直接改，不留兼容层）。已做：`vp run deadcode`（knip，零容忍，在 CI 里），接上时清出 130 个没人用的导出、12 个类型、24 处声明、两个整文件、一个依赖。

**三、绕开约束。** 机理：类型检查（复杂的泛型、Effect 的错误通道）或测试挡住任务时，模型找阻力最小的路绕过去，不修根本的错。例子：修并发扣费，编译器说 InsufficientQuotaError 没处理，agent 塞了 Effect.orDie、用 as any 绕过类型；边界测试挂了，就把 expect(balance).toBe(0) 改成 toBe(-10)。
在这里：已有：`typescript/no-explicit-any`、`no-unsafe-*`、`typescript/no-unsafe-type-assertion`，类型逃生口（`x!`、`as`、`as unknown as`、关 lint 的注释）的棘轮。已做：`Effect.orDie`、`Effect.ignore`、吞掉的 `catch` 进棘轮；修复补的测试以 `regression: ` 开头，删改要在 PR 里点名（`scripts/regression.ts`）。帮工那边：验收步骤先红、写好就冻结（[先采样，再验收](.agents/notes/proposed/architecture/2026-10-14-sample-then-verify.md)）。

**四、温室假设。** 机理：训练语料多是教学代码，默认内存无限、网络秒回、磁盘不锁、外部进程输出规整。例子：看板接口在 50 个工单的 .map() 里逐个跑 git diff --numstat（N+1）；收模型的流时每来一个字就把整个历史 JSON.stringify 写一次盘；两个工单时很顺，第三天八十个工单，CPU 和磁盘满了。
在这里：已有：贵的东西归拥有它的模块管，刚写下的不再读回，一条消息的几次写在一个事务里，时间归 `Clock`、测试拨 `TestClock`（[地基](docs/subsystems/foundation.md)）。以后做：热路径的 I/O 次数断言、流按任意切片测（出现第一个这类回归时）。

**五、架构漂移和乱引依赖。** 机理：每个 agent 都是失忆的，看不见早先口头的约定；训练语料里有各个年代的库，各自按偏好引包。例子：约定只用内置的日期和 Schema，1 号 agent 装了 moment，2 号装了 dayjs，3 号在领域层 import 了最外层的飞书 UI 组件，领域层和 UI 层缠死，再也不能单独编译。
在这里：已有：依赖的版本只写在 `pnpm-workspace.yaml` 的 catalog（`catalogMode: strict`，`scripts/catalog.test.ts` 查）；方向由 `apps/server/src/modules.test.ts`、`vibevalley/page-layers`、`import/no-cycle`、各包的 `no-restricted-imports`（`packages/ai` 不认识 agent，agent 不认识农场）守住；规矩写在 `AGENTS.md`，每次会话都在上下文里。

**六、认知赤字，审查破产。** 机理：人一小时读三五百行，六个 agent 一夜改八千行，人读不过来。例子：先坚持逐行审，分支积压；两周后看见 CI 绿就合；第二个月线上死锁，没人看得懂被改了十几遍的三千行异步调度。
在这里：已有：一个 PR 讲一件事，正文写现在的行为和证据（[vv-pr](.agents/skills/vv-pr/SKILL.md)），改了接口和页面照 [acceptance](.agents/skills/acceptance/SKILL.md) 在真的程序上验证并附证据，子系统文档写「为什么这样」。回放（2026-10-30，`main` 最近 100 个 PR）：契约约占改动的 1/22，后来修掉的缺陷只有 1.5% 当初写在契约里：读契约挡不住缺陷，挡缺陷靠测试和验收。以后做：契约的 diff 进 CI 摘要。

## 十条铁律

| 铁律 | 在这里 |
|---|---|
| 1. 机器能拦住的错，不花一个 token：架构规范写成毫秒级的类型检查和 AST 静态门禁，用退出码 1 代替说教 | 已有：四层手段的第 1、2 层；`vp check` 带类型的 lint、仓库自己的 oxlint 插件、结构测试、CI |
| 2. 报错就是提示词：报错不只说不许做什么，印出标准写法的模板和参考文件的行号 | 已做：每个检查的话写错在哪、`Fix:`、`See`（`scripts/oxlint-plugin.ts` 的 `says`，测试查 `See` 的文件在不在）；改写：写文件不写行号（行号一改就错，文件挪了测试会报） |
| 3. 收回公共控制流，只让 AI 填空：超时、重试、配额、事务回滚、子进程回收焊死在高阶函数里，AI 只写 50 行以内的业务插件 | 已有：帮工经 oar 驱动，核心状态只由 `Core.apply` 改，git 子进程在 `project/git.ts` 杀整个进程组。以后做：扩展点只填空 |
| 4. 物理锁死契约和验收测试：协议 Schema、核心接口签名、验收测试目录只读；修 bug 先锁定必败的红灯测试 | 改写：不锁目录（主人和 agent 是同一个用户，锁不住），让改动被看见：`regression: ` 测试删改要点名，生成的文件不手改（`docs:verify`、`server:check` 查），黄金数据改了看 diff。帮工那边已有：验收先红、写好冻结 |
| 5. 写新功能和做抽象拆成两张单：每合入 3 个功能单，插 1 个「不改行为、只减行数」的纯重构单 | 改写：功能和重构分成不同的 PR（`feat/`、`refactor/`），清哪里由体检的热点和 deadcode 决定，不按 3:1 的固定比例 |
| 6. 跨 5 个以上文件的修改不许 AI 手改，必须写 AST 转换脚本（codemod）一次批量做 | 改写：写不成检查（分不出机械的和逐处判断的），写成做法：[SKILL.md](.agents/skills/vv-governance/SKILL.md#5-一次改很多文件)；漏改由 `tsc` 和 `stale-names.ts` 兜底 |
| 7. 不测波动的毫秒，测确定的 I/O 次数：内存假库带计数器，断言单次操作的读写次数上限 | 以后做：出现第一个 N+1 回归时。已有：测试分层的预算只报不挡（各机器快慢不同） |
| 8. 编译器穷尽检查当导航：不用布尔标志拼状态，全仓用带标签的联合并禁用 default 分支 | 已有：`typescript/switch-exhaustiveness-check`；改写：`default` 允许，要说明其余的有意不管（`AGENTS.md`「封闭的联合穷尽处理」）；成员表要每种都处理时用 `Record<X, …>` |
| 9. 需求不明确时挂起提问：计划阶段缺边界定义，就挂起工单、给人推选择题，不带着猜测写代码 | 改写：写计划前问清四类边界，用选择题（[SKILL.md](.agents/skills/vv-governance/SKILL.md#3-写计划前问清边界)）；帮工那边已有：工单里的「先问清楚」，帮工问主人 |

## 五层金字塔

白皮书主张放弃「靠人盯 AI」，从下往上建五层：

| 层 | 名字 | 要做的事 | 成本 | 手段 |
|---|---|---|---|---|
| 5 | 认知主权与演进经济 | 管住需求的源头、定模块的报废标准、保住人的最终控制 | 人做决定，加 5% 的旗舰模型 | 需求歧义挂起、300 行模块重生成、三级模型成本路由、月度人工盲降演练 |
| 4 | 发散和收敛的双循环流程 | 功能实现和抽象提炼分开，防并发互踩 | 15% 的轻量模型加自动流水线 | 3+1 播种除草、代数归约重构指令、跨文件 codemod 铁律、合并队列的语义防撞 |
| 3 | 语义契约与确定性验证 | 锁死验收标准和持久化格式，用仿真底座消灭脆弱测试和慢代码 | 零 token（毫秒级确定性测试） | 三层只读契约墙、内存假实现、I/O 次数断言、历史存档快照升级测试、故障胶囊自愈 |
| 2 | 代码拓扑与架构骨架 | 消除跨目录散落的逻辑，收回公共控制流，只让 AI 填空 | 零 token（编译期约束） | 垂直特性切片、高阶组合子骨架、有限状态机加事件总线、AST 提取的原语词典 |
| 1 | 物理环境与编译器铁笼 | 用零信任沙箱和编译器规则拦一切越权、逃逸和死代码 | 零 token（毫秒级静态检查） | worktree 容器沙箱、确定性命令防火墙、自举双核隔离、联合类型穷尽检查、处方式 AST 报错、死代码断头台 |

在这里：四层手段（代码、检查、文字、人看）按同一个成本顺序排，五层的内容分在下面各节。

### 第 1 层：物理环境与编译器铁笼

**1.1 沙箱和命令防火墙。** 白皮书：每张编码工单在独立的 git worktree 和容器沙箱（Docker、MicroVM、macOS sandbox-exec）里开工；执行任何 shell 命令前，过一层用正则和语法树的确定性拦截（不让模型判断安全）：文件系统围栏（拒绝 worktree 之外的写，拦 .. 穿越、改 ~/.ssh、~/.zshrc）；特权文件写保护（普通功能单里 package.json、lockfile、go.mod、tsconfig.json、.eslintrc 只读，防私自装库、调低严格度）；进程组连坐回收（外部 CLI 子进程经绑定生命周期的受管服务起，超时或取消时向整个进程组发 SIGKILL，并 git worktree unlock）。
在这里：已有：工单按档案在项目目录或自己的 worktree 里干活；git 子进程超时杀整个进程组（`apps/server/src/project/git.ts`）。不做：命令防火墙和特权文件只读：帮工没有权限确认是常驻规矩，边界是本机、工作目录和「连接到本机」（[否决过的权限请求](.agents/notes/rejected/feature/2026-10-10-permission-requests-as-weeds.md)）；依赖和配置的变化在 PR 的 diff 里看得见，放松检查的写法在逃生口的棘轮里。

**1.2 自举的双核隔离。** 白皮书：用调度工具改它自己时，运行中的宿主（控制面）总从只读目录加载签过名的稳定版二进制；被改的源码只是工作区（目标面）。合入前在隔离端口起金丝雀版本，跑通「启动、建分支、跑假任务、存盘自检、零退出码关停」的自举冒烟，防止把自己改到脑死亡。
在这里：以后做：[用 VibeValley 开发 VibeValley](.agents/notes/proposed/process/2026-10-18-build-vibevalley-with-vibevalley.md)：干活的农场和正在改的代码分开（渠道）、合并前跑检查。已有：验收起一个和主人数据隔开的服务端（`scripts/verify-server.ts`）。

**1.3 联合类型和名义类型。** 白皮书：接口或状态对象里不许有两个以上表示状态的布尔值，改成带 `_tag` 的联合，全仓开 switch 穷尽检查、禁用 default；跨模块不传裸 string 的 id、裸 number 的单位，用名义类型（TicketId、VerifiedWorktreePath、Millicents、Milliseconds）；模板里还有一个 assertNever，加一种状态时编译期报出要改的地方。
在这里：已有：id 带 `Brand`（`packages/protocol/src/shapes.ts` 的 `IssueId`、`SessionId`）；时间和单位写进名字（`…Ms`，[命名](docs/style/naming.md)）；穷尽检查的 lint。改写：`default` 允许并说明。以后做：两个以上布尔字段的形状进体检的报告，作为「没写出来的状态」的候选（`shapes.ts` 现有 60 个布尔字段，很多是独立的开关）。

**1.4 处方式报错。** 白皮书：用 ast-grep 写规则，每条的 message 写三样：为什么拦（危害）、正确写法的模板（能照抄）、仓库里标准范例的路径和行号。给了三条示例：拦裸调子进程（Bun.spawn、child_process.spawn/exec，导向受管进程原语）、拦常驻服务里的无界 new Map（导向带淘汰的有界容器）、拦没有删除日期的 @deprecated（要求 removeBy 日期）。
在这里：已做：三样的格式（`says`、`refused`，测试查）；规则算得出改法的算出来（`no-cjk-literal` 给出词典文件和 `t()` 的键，`parent-import` 给出 `@/…` 并自动修复）；结构测试和体检的报错同一个格式。改写：用 oxlint 插件，不另加 ast-grep（已经在 `vp check` 里、带类型）。三条示例：子进程只在拥有它的模块里起，现在是约定（`project/git.ts`、`runtime/dsh.ts`、`voice/voice.ts`），以后做成 import 限制；常驻集合由谁删，以后逐处清点（服务端 7 处 `new Map(`）；`@deprecated` 不做 removeBy，内部不留兼容，旧的直接删（`typescript/no-deprecated` 拦用到已弃用的 API）。

**1.5 死代码断头台。** 白皮书：CI 里接 knip（TypeScript）或 deadcode（Go），零容忍；没人引用的导出、没用的类型、过了 removeBy 的废弃函数，直接挡住合并。
在这里：已做：`vp run deadcode`（`knip.ts`、`scripts/deadcode.ts`），在 CI 的 check 里，零容忍。

**第 1 层的要点。** 心法：不在评审里跟 AI 讲道理，它只听得懂退出码 1 和 stderr 里的模板。周一能做的：装上 ast-grep 和 knip，把三条规则塞进 pre-commit，半小时消灭八成低级破坏。自检：CI 放 `as any`、超过 60 行的函数、没人引用的导出进主干，代码库就在失控倒计时。
在这里：已有：pre-commit 跑 `vp check --fix`；`as any` 由 lint 拦，全仓只剩 1 处。已做：knip。不做：函数行数上限（会被切开凑数；体检的函数级热点以后做）。

### 第 2 层：代码拓扑与架构骨架

**2.1 垂直特性切片。** 白皮书：不要按技术角色分 controllers/、services/、models/、utils/（改一个功能要跨五个目录找，漏看约束、重复造轮子）；按业务特性切，每片一个文件夹，只经唯一的 index.ts 暴露最小的契约；示例目录有 contracts/（只读）、infra/（受管进程、有界集合、事件总线、假实现）、features/<切片>/（index.ts、state-machine.ts、harness-adapter.ts、就近的测试、30 行的 RULES.md）和生成的 PRIMITIVES.md。依赖硬锁：dependency-cruiser 拦绕过 index.ts 的引用和反向引用。
在这里：已有：服务端一个概念一个文件夹、名字单数，模块的分层以 `apps/server/src/modules.ts` 为准，`modules.test.ts` 查只 import 前面的、只读自己那份核心状态；页面 `features/<概念>` 只经 `index.ts` 用（`vibevalley/page-layers`）；`rules`、`utils`、`helpers` 这类名字由 `scripts/file-names.test.ts` 拦；测试跟着模块走。不做：contracts/ 单独一个目录：契约在 `packages/protocol`，服务接口和实现在同一个模块里。

**2.2 高阶骨架。** 白皮书：资源获取和释放、超时熔断、重试退避、配额检查、异常包装，由架构师写成不可改的高阶函数；AI 加适配器时只实现纯数据映射。示例是 NarrowAgentPlugin（buildCliArgs、parseStdoutLine 两个纯函数）和 runWithAgentHarness（统一配额预检、申请带自动回收锁的 worktree、受管流绑定超时和计费）。收益：加第 5 种编码农机、第 4 种聊天机器人，AI 只写 30 行。
在这里：已有：编码 agent 经 oar 驱动，农场不自己起它们的进程；connector 的重试和退避在 `connector.ts`，`Adapter` 是窄接口的雏形。以后做：扩展点只填空，先做农场的工具（和[工具集和技能](.agents/notes/proposed/architecture/2026-10-28-toolsets-and-skills.md)一起），connector 的超时和轮询等出问题时收。

**2.3 单一状态机和事件总线。** 白皮书：核心业务状态只能由纯函数改：transition(state, cmd) 返回新状态和要发的领域事件，不做 I/O；外层执行器把新状态落盘，再把事件推进总线；通知、卡片、庄稼动画、成就统计都是订阅者。
在这里：已有：oar 的会话事件经 `apps/server/src/session/facts.ts`（纯函数）读成事实，`Core.apply` 用 `projection/reduce.ts` 的 `reduce` 折进核心状态，页面读折好的帧；农场的游戏规则只读事件、算画面，业务不调它（[概念先行](.agents/notes/proposed/architecture/2026-10-15-concepts-first.md)）；下层经 `Stream` 往上报。以后做：[状态先提交，副作用由 worker 在提交之后做](.agents/notes/proposed/architecture/2026-10-22-commit-then-effects.md)。

**2.4 三级上下文和原语词典。** 白皮书：根级宪章（CLAUDE.md，150 行内，只写红线和命令入口）；目录级 RULES.md（50 行内，就近、按需加载）；代码里关键的防死锁、顺序敏感处标 // @invariant ADR-xxx，没在提交说明里写原因就删改的由 lint 拦；公共工具标 @primitive，CI 扫描生成 PRIMITIVES.md，不手写。
在这里：已有：`CLAUDE.md` 只有一行 `@AGENTS.md`，`AGENTS.md` 写目录、命令和常驻规矩，每条链到它的家；子目录的规矩在子目录的 `AGENTS.md`（`docs/AGENTS.md`、`.agents/notes/README.md`）和各包的 README；注释只写为什么、顺序和锁、安全边界（[注释](docs/style/code.md#注释)）。不做：`@invariant` 的 lint（写成注释已经够，删改由评审看）、`@primitive` 标记（每个导出多一件要记得的事）。以后做：共用帮手的清单，按位置收、从 JSDoc 生成，配一条认得出原样重复的 lint。

**第 2 层的要点。** 心法：AI 写不出好抽象，是因为给了它操作全局流程的自由；把骨架和状态机焊死，它就只能在 50 行的纯函数里写。周一能做的：找出最常一起改的三个适配器，把重试、日志、异常处理抽成 withHarness()，三个文件砍成纯配置映射。自检：加一个通知渠道或统计维度要改核心主流程哪怕一行，状态机和事件总线的解耦就失败了。
在这里：同 2.2、2.3。自检那条可以用体检的「跨区一起改」量（[体检](.agents/notes/proposed/process/2026-10-29-repo-health-readings.md)）。

### 第 3 层：语义契约与确定性验证

**3.1 三层只读契约墙。** 白皮书：仓库分契约区（编码时只读）和实现区。三道墙：协议和存盘的契约（前后端的结构、带版本号的表结构）、领域服务接口（函数签名、名义类型、错误联合）、不可变的验收测试。两阶段：先由架构师或「测试契约 agent」写出复现缺陷的验收测试，CI 确认它红，算契约区和验收区的 SHA-256 写进锁文件；再让编码 agent 在 worktree 里只改实现，pre-commit 和 CI 每次 git diff --exit-code 契约区和验收区，改了测试断言或放宽接口就拒绝提交、终止任务。
在这里：已有：线上的形状只在 `packages/protocol`（`shapes.ts`、`schema.ts` 的 `Codec<T.X>` 对不上就编不过，`api.ts`）；表结构只有 `0001_schema.up.sql` 一个文件（`schema.test.ts` 查）；生成的文件不手改；帮工的验收先红、写好就冻结（[先采样，再验收](.agents/notes/proposed/architecture/2026-10-14-sample-then-verify.md)）。改写：仓库自己的开发不锁目录：`regression: ` 测试删改要点名（`scripts/regression.ts`）。以后做：契约的 diff 进 CI 摘要；`refactor/` 不许动契约（契约稳定以后）。

**3.2 内存假实现和属性测试。** 白皮书：不用 vi.fn().mockReturnValue、jest.spyOn 绑死内部私有函数的调用次数和返回值（一重构就大片误报）；数据库、git 工作树、外部 CLI、时钟各有唯一一套带计数器的高保真内存实现；用属性测试生成 100 步乱序的并发操作，查状态机在任何交错下都不违反不变量（示例：同时跑的工作树不超过 6 个，已关闭的工单没有存活的进程）。
在这里：已有：测试金字塔一层一个接缝，接缝以内是真的，外面的世界只在端口上换成假的（oar 的 `scriptedRuntime`、照脚本回答的 `Llm`），git 和库用真的（[地基](docs/subsystems/foundation.md)）；时间用 `TestClock`；规则的黄金数据是几千条带种子的随机输入。以后做：I/O 次数的计数器和断言；在黄金数据的输入上查 `reduce` 的不变量（一个工单最多一个在干活的执行、完成的工单没有在跑的帮工）。

**3.3 确定性混沌和启动对账。** 白皮书：测试底座把外部 CLI 的 stdout 随机切成残缺的半包异步吐出，查解析器有没有行缓冲；模拟进程挂住不输出，用 TestClock.adjust("15 minutes") 查超时回收。系统每次启动先做三方对账：磁盘上的 worktree、活着的子进程、库里 Running 的工单；孤儿进程杀掉、残留目录回收、中断的任务置回可安全重试。
在这里：已有：有时间窗口的（超时、冷却、重试的退避）用 `TestClock` 拨过去断言；开机接回帮工（`apps/server/src/runtime/runtime.ts`），`src/flows` 的流程测试覆盖重启。以后做：流按任意切片测（`packages/ai` 读 SSE、git 的输出），出现第一个这类问题时。

**3.4 历史存档的黄金快照。** 白皮书：不把内存里的领域对象直接序列化，经带版本号的存储 DTO 和双向转换器读写；每个发布版本的真实存档永久留在 tests/fixtures/storage-snapshots/，CI 逐个升级到最新，失败或丢字段就挡住合并。
在这里：不做：内部不留兼容，表结构直接改，旧库在开机时挪到一边、新建一个，不写数据搬运（`AGENTS.md`「内部不留兼容」）；对外 HTTP 的 v1 是唯一例外。存盘的格式仍是契约：改表结构走 `db:generate`，`schema.test.ts` 查。

**3.5 故障胶囊和自愈飞轮。** 白皮书：未捕获的错误由外层骨架记成一份 JSON 胶囊（脱敏的入参、当时的状态、最近 20 条领域事件、报错行号）；诊断 agent 把它翻成 tests/regression/ 下稳定复现的红灯测试，锁定后再派给编码 agent 修。
在这里：已有：每个会话和管家的每一步由 `session/journal.ts` 记成轨迹。已做：修复补的测试以 `regression: ` 开头、受 CI 保护。以后做：故障回流成样本（[先采样，再验收](.agents/notes/proposed/architecture/2026-10-14-sample-then-verify.md) 第 2 步）。

**第 3 层的要点。** 心法：测试不是凑覆盖率，是锁死业务真值和性能底线；验收测试和存档快照锁死了，AI 怎么折腾都伤不到根基。周一能做的：在读写的测试封装里加 readCount、writeCount，核心列表接口的测试末尾断言读不超过 2 次。自检：只拆了一个模块的私有函数（接口和行为没动），测试却挂一大片，就是测试绑死了实现细节，该换成内存假实现。
在这里：已有：一个行为在能看见它的最低一层测，模块测试从服务接口进，页面测试只测接线不测文案；没有覆盖率门槛。以后做：I/O 计数（同 3.2）。

### 第 4 层：发散和收敛的双循环

**4.1 3+1 播种除草。** 白皮书：实现新功能（发散）和提炼抽象（收敛）在模型的注意力里互斥；工单分两类按 3:1 交替：播种单（连续 3 张，只求最短路跑通新的验收测试，不许顺手重构无关文件）；除草单（每合 3 张功能单，调度器冻结新功能，扫出坏味道清单：jscpd 重复超过 15 行的块、最近 50 次提交里常一起改的跨目录文件对、超过 45 行的函数，自动派一张纯重构单）。
在这里：改写：功能和重构分成不同的 PR，不按固定比例；清哪里由读数决定：体检的热点（`vp run health`）、`vp run deadcode`、[vv-simplify](.agents/skills/vv-simplify/SKILL.md)。以后做：jscpd 的重复块和跨区一起改的文件对进体检的报告（[体检](.agents/notes/proposed/process/2026-10-29-repo-health-readings.md)）。

**4.2 代数归约的重构指令。** 白皮书：不给重构 agent 发「优化代码、提高抽象」这类空话，用固定的模板：靶向输入（两个文件和行号区间）；分离不变量（截断、退避重试、失败告警这类一样的控制流下沉到一个高阶函数）和可变量（各自的报文拼装、签名，作为纯函数插件传进去），给新函数加 @primitive；硬门槛：tests/ 零行修改、全部测试通过、受影响模块的行数净减 15% 以上且平均圈复杂度下降。
在这里：改写：[SKILL.md](.agents/skills/vv-governance/SKILL.md#4-做一张纯重构的单)：分开不变的和变的；测试只因改名、挪地方而变，断言不减，`regression: ` 测试不动；行数不设门槛（会被刷），但没变少或变简单就不合。

**4.3 跨文件重构用 codemod。** 白皮书：接口签名、命名、模式升级涉及 5 个以上文件时，禁止 agent 用编辑工具逐个改；写一次性的 ast-grep 规则或 ts-morph 脚本，先在一个样本上验证语义等价，再一次全仓转换，用完删掉脚本。
在这里：改写：[SKILL.md](.agents/skills/vv-governance/SKILL.md#5-一次改很多文件)。吸收时的一次教训：一个删死代码的一次性脚本在错误的偏移上写了文件，处理办法是把碰过的文件从 `origin/main` 恢复重来；每处要逐处判断的，文件再多也逐处看。

**4.4 合并队列和符号级乐观锁。** 白皮书：待合并的分支不直接进 main，进自动合并队列：守护进程在临时工作树里把它 rebase 到最新的 main，在组合后的代码上重跑编译、门禁和全部测试，全绿才推进 main；分支创建时记下它引用的跨模块符号，期间 main 合进来的分支改了这些函数的实现（AST 哈希变了），即使没有文本冲突也挂起、全量回归。
在这里：已有：`main` 只经 PR、squash 合并、CI 全过才能合。以后做：并行的 agent 多起来以后开 GitHub 自带的 merge queue（要改仓库设置，主人定）；不做：符号级的锁（GitHub 的队列已经在组合后的代码上重跑全部检查）。

**第 4 层的要点。** 心法：抽象是一道专门做减法的工序；规定每 3 单功能跟 1 单不许改测试、只许删减 15% 的纯重构，代码库就不会发胖。周一能做的：跑 npx jscpd src/ --min-lines 15，把报告贴给 AI，用「分离不变量和可变量」的模板做一次减法。自检：让 AI 用编辑工具手改 20 个文件里同一个调用，第 15 个以后必漏改；超过 5 个文件只许写 codemod。
在这里：同 4.1–4.3。

### 第 5 层：认知主权与演进经济

**5.1 需求歧义挂起。** 白皮书：派单后的计划阶段，调度 agent 先对照边界完整性清单预检；四类没定义的（异常和边界、并发和幂等、数据规模和分页、存量数据兼容），把工单置为 WaitingForClarification，给人推带默认推荐项的选择题卡片。
在这里：改写：[SKILL.md](.agents/skills/vv-governance/SKILL.md#3-写计划前问清边界)；存量数据一类在这里的答案固定是不兼容。已有（产品里）：帮工照工单的「先问清楚」问主人，主人在田头回答；管家起草工单时问主人。

**5.2 重生成优于打补丁。** 白皮书：每个切片的内部实现（不含契约和测试）严格在 300 行内；三振出局：连续 3 次修补后仍有关联回归，或圈复杂度逼近上限，或 AI 改它的平均耗时、token 超过基线两倍，就不再派修补单；保留接口签名和全部验收测试，物理删光内部实现，派一张新单让 agent 照只读契约和红灯测试 3 分钟内从零生成。
在这里：不做（现在）：行数上限会被切文件凑数；模块的测试还不都是只经接口。以后做：体检加「模块的测试只经接口的比例」；一个模块在热点前列、30 天里被多个 `fix/` PR 修过、测试只经接口时，派重写而不是修补（契约稳定以后）。

**5.3 三级模型成本路由。** 白皮书：治理自己的算力按 80/15/5 分：80% 给零成本的确定性工具（穷尽检查、处方报错、knip、I/O 计数器、快照升级测试，2 秒内、0 token）；15% 给轻量模型（日志摘要、原语检索、单模块的常规填充和格式化）；5% 给旗舰模型做异构的交叉对抗审计（只在需求拆解、契约设计、合并前的架构审计时用，写和审不能是同一个模型，比如 Codex 写的由挂着安全和架构清单的 Claude 审）。
在这里：已有：检查都是确定性的、带缓存（`vp run` 的任务）；注释的初审交给另一个模型（`scripts/comment-review.ts` 用 DeepSeek），只报不改、提 PR 前在本机跑，不进 CI（模型的回答每次不一样，不该挡合并）。以后做：PR 评审的打分和合并门槛（提案还没进仓库）。

**5.4 月度人工盲降和四个北极星指标。** 白皮书：每月最后一个周五，在测试环境往一个核心模块注入隐蔽故障、暂时停掉编码 agent，值班工程师只凭原语词典、状态机转换图和故障胶囊，15 分钟内定位并修好，检验系统的可理解性有没有腐化。每周自动统计四个指标：

| 指标 | 怎么算 | 白皮书的动作 | 在这里 |
|---|---|---|---|
| 功能代码膨胀比 | 净增业务代码行 ÷ 新增通过的验收测试数 | 连涨两周就冻结功能开发、全员除草 | 不做：分母能刷（多写几个小测试比值就好看） |
| 修改爆炸半径 | 一张功能单碰的文件数 | 健康值 ≤ 3 个同切片文件；均值过 6 就做解耦改造 | 以后做：体检的「改动放大」（一个提交平均动几个区），和自己的过去比，不设固定阈值 |
| 静态防线自愈率 | AI 看了报错一次改对的次数 ÷ 触发次数 | 低于 90% 的规则重写报错和模板 | 以后做：从帮工的轨迹（`session/journal.ts`）算，等[用 VibeValley 开发 VibeValley](.agents/notes/proposed/process/2026-10-18-build-vibevalley-with-vibevalley.md)接上 |
| 认知审查压缩比 | 总改动行 ÷ 人要精读的契约和状态机行 | 至少 10:1 | 回放量过约 22:1；以后做：契约的 diff 和压缩比进 CI 摘要 |

盲降演练：不做：只有一位主人；子系统文档的「为什么这样」和[概念](docs/concepts.md)是日常版本。

**第 5 层的要点。** 心法：契约是钻石，实现是厕纸；接口和验收测试锁成铁桶，300 行以内的实现随时删光、花 5 美分 2 分钟重生成，别让人去给 AI 的烂补丁做考古。周一能做的：找积压缺陷最多、改了三四次还出问题的模块，补齐外层验收测试锁死，清空内部实现让 AI 照测试重写。自检：关掉 AI 工具，人看着报错栈 15 分钟内说不清系统的状态怎么流转，就是「自动驾驶失能」。
在这里：同 5.2；状态怎么流转写在 `AGENTS.md` 的「一件事的主线」和 [architecture.md](docs/architecture.md)。

## 附录 A：根级宪章

白皮书给了一份 100 行的 CLAUDE.md、AGENTS.md 模板。在这里，根级的规矩就是 `AGENTS.md`（`CLAUDE.md` 只引用它），逐条对照：

**1. 铁笼红线：**

- 禁止类型和错误逃逸：业务代码不许 `as any`、`@ts-ignore`、`Effect.orDie`、空的 `catch {}`，可预期的错误显式声明在错误联合里。在这里：`as any` 由 lint 拦；关 lint、`as`、`!`、`orDie`、`ignore`、空 `catch` 进棘轮（有理由的旧用法留着，新增要说明）。
- 禁止越权改只读契约：功能和修复时，契约和验收测试目录只读，不许改断言迎合错误的实现。在这里：改写为改动要被看见（`regression: ` 测试、生成的文件、黄金数据的 diff）。
- 禁止裸调系统副作用：不许直接用 `Bun.spawn`、`child_process`、`node:fs`、无界 `new Map()`，统一调原语词典里的受管服务。在这里：以后做：子进程的 import 限制、常驻集合的清点；`node:fs` 不限（服务端的存盘归拥有它的模块）。
- 禁止手改多文件重构：5 个以上文件的机械改动写 codemod。在这里：做法，见 SKILL.md 第 5 节。
- 禁止私自引入第三方包：`package.json` 锁写权限，校验用内置 Schema，日期用内置 DateTime。在这里：版本只在 catalog，`catalog.test.ts` 查；新依赖在 PR 的 diff 里看得见；校验用 Effect 的 `Schema`。

**2. 架构和目录：**

- 垂直切片自包含，只经 `index.ts` 用。在这里：已有（2.1）。
- 状态机是唯一的写入口，副作用经事件总线异步做。在这里：已有（2.3）。
- 高阶骨架填空，适配器不超过 50 行、单函数不超过 60 行（圈复杂度 ≤ 10）。在这里：以后做骨架；不设行数和复杂度上限。

**3. 标准作业流程：**

- 不懂先问。在这里：SKILL.md 第 3 节。
- 先查原语词典，新的通用原语标 `@primitive`。在这里：以后做共用帮手的清单（不加标记）。
- 提交前本地自检：类型和穷尽检查、处方式 AST 和死代码门禁、确定性仿真和快照测试。在这里：`vp check`、`vp run deadcode`、`vp run server:check`、`vp run web:check`（`AGENTS.md`「命令」）；pre-commit 跑 `vp check --fix`。
