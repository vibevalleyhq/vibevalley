# 批量迁移到 StyleX

保留外观、行为、内容和资源，改变样式的表达方式。阶段和完成条件以 [迁移 Note](.agents/notes/proposed/architecture/2026-11-08-tailwind-to-stylex.md) 为准；本篇只规定实施方法，不保存临时路径、库存数字或已通过场景数。

## 1. 划定本轮范围

1. 运行 `vp run migration:inventory`，记录类 token 使用量、涉及文件、样式接口和各类例外。
2. 按语法模式分组：静态字面量、常量／映射、条件组合、组件接口、关系选择器、动画与定位。
3. 保存本轮改动前的源码、CSS 基准及其身份信息，标出工作区已有的其他改动。

统计类别有重叠，不相加成任务总数。token 数只衡量类使用量，不代表整个迁移的完成率；动态样式和语义类不一定需要删除，但应有明确所有者与分类。

## 2. 先试一种规则，再全仓应用

临时转换脚本不进入生产代码；机械改写按 [治理 skill](.agents/skills/vv-governance/SKILL.md) 执行。

1. 从实际基准 CSS 推导声明、默认值、选择器与顺序，不用工具类名字猜样式。
2. 先在一个代表文件上运行，查看 diff、条件分支和生成的样式，再批量应用同一种规则。
3. 收集无法证明安全的表达式及原因，继续本轮其他文件，不被一个例外打断。
4. 全仓批次落下后统一跑类型／lint、所属宿主生产编译、AST 对比和库存扫描。

转换器应守住这些边界：

- 只解析可证明静态的常量、模板片段和映射。应跟踪作用域、导入和重导出；会逃逸、可变或有副作用的值不做快照替换。
- 条件和映射的组合应有枚举上限。属性只依赖一个条件时可拆成独立样式；依赖多个条件时应整体保留语义或进入例外清单，不能按类字符串的左右顺序猜覆盖关系。
- 不把任意函数内联到调用处：闭包作用域、调用次数、短路求值和 Solid 响应式追踪可能改变。
- 应核实简写、长属性、逻辑边、继承、伪类优先级和 CSS 变量依赖。源码里写在后的类不一定在 CSS 中胜出。
- 颜色替换应匹配完整值，不能把 `#rrggbbaa` 的前六位单独换成 `var(--color-...)`，留下无效的 alpha 后缀。旧浏览器的透明色回退用有所有者的完整颜色令牌，保留原始 8 位 alpha；`@supports` 分支仍用原来的条件和表达式。库存的 `invalid-color-variable-suffix` 拦这种损坏。
- 原生 DOM、Base UI、应用组件和自定义 render 函数分开识别，不把组件 `class` 参数当成原生属性随意展开。
- 生产结果应是 StyleX 定义、语义变体和类型化映射，不引入 class 字符串解析器、工具类兼容层或重复色板。

## 3. 整批改接口

1. 把组件的样式入口改成 `styles?: StyleXStyles`，明确调用方可覆盖的属性与固定不变量。
2. 一次迁移所有调用方，包括多行 JSX、别名、属性展开和已经生成 StyleX class 的字符串转传。
3. 将动态变量及外部定位通过对象样式传到底层 DOM，复用宿主适配器。
4. 用类型检查补漏，并单独审查展开属性：结构类型允许额外字段，仅靠类型检查不一定能发现隐藏的 `class`。

CSS 层和样式所有者应保持清楚：

- 自有组件样式归 StyleX；令牌、reset、字体、富文本、接管前规则、外部定位或动画边界可保留有明确范围的 CSS。
- 不应把所有旧工具类搬进一张全局 CSS 表，或以整目录豁免掩盖未迁移项。
- 检查**生产 CSS 中首次遇到各层的顺序**。组件直接导入 CSS 可能让 `components` 先于 `base` 出现；只看源码开头的层列表不够。压缩器可能删掉冗余声明，应读实际层顺序，包括 StyleX 子层，而非只匹配一个文本前缀。
- 保留基准中真实生效的行为，即使某个类名看起来表达另一种意图。修交互缺陷另立决定，不混进样式迁移。

## 4. 合并验证批次

| 时机 | 执行 |
|---|---|
| 新的转换规则、编译器机制或样式边界 | 一个最小代表探针，确认规则后复用 |
| 一轮实质批量改动之后 | 类型／lint、相关生产编译、非样式 AST 对比、库存与例外清单 |
| 某个检查失败 | 最小复现与修复；不反复跑无关套件 |
| 实施结束、最终验收阶段 | 完整行为测试、精确视觉对照、真实程序和宿主验收，全部针对最终源码 |

常用入口：

```bash
vp check --fix
vp run --filter @vibevalley/web build:stories
vp run site:build
vp run migration:inventory
```

只执行本轮涉及的宿主构建；改了包的导出或类型时，按仓库约定先构建声明。故事和回归用例按组件边界、键盘、动态变量、定位和主题风险集中补，不给每个静态声明单独配一套浏览器检查。每轮更新一次台账，不每改几个文件就停下来汇报。

非样式 AST 对比只排除确认过的样式定义、属性、样式专用导入与常量。应保留文本、结构、事件、业务条件及其余代码；不应为了让对比通过扩大忽略范围。AST 相同不证明像素相同，也不证明 class 求值中的副作用没有变化。

## 5. 完成和失败

最终验收应由 [vv-acceptance](.agents/skills/vv-acceptance/SKILL.md) 和迁移 Note 规定的矩阵完成。精确视觉比较应先证明基准 A/A 稳定，再比较候选；保留零像素差异和文本一致要求，不用遮罩、放宽阈值或删场景来通过。

- 未知表达式、扫描缺口、旧构建图和缺失场景仍是失败，不因其他场景通过而忽略。
- 部分跑完、超时或中止的结果不是完整通过；源码改变后旧 receipt 不代表当前版本。
- 可提交「实施检查点」，但应写明尚未验证的内容。移除 Tailwind 和最终验收通过之前，不宣称迁移完成。
- 转换脚本写错时，应恢复它本轮改动前的快照，修脚本后重跑；不从主分支覆盖整个工作区，不撤销别人的改动，也不在未知范围的坏输出上逐处补丁。
