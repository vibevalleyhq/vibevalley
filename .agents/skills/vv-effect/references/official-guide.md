# 官方指南的每一节在这里

分两张表：一张对包自带的 `node_modules/effect/AGENTS.md`（effect 4.1.2），一张对官网 [Effect v4 Getting Started](https://effect.website/docs/v4/getting-started) 导航树的全部模块。指南本身不复制：先读它，再看这里它落在哪、有什么隐式边界。入口见 [SKILL.md](.agents/skills/vv-effect/SKILL.md)，成对写法见 [cases.md](.agents/skills/vv-effect/references/cases.md)。

## 1. 包内 `AGENTS.md` 对照

| 指南的一节 | 在这里 |
|---|---|
| Writing `Effect` code（`Effect.gen`、`Effect.fn`、`Effect.fnUntraced`，不写只包一层 `Effect.gen` 的函数） | 照做。服务的方法用 `Effect.fn("X.m")`，热路径和薄的取值用 `Effect.fnUntraced`；lint `vibevalley/service-method-names` 查 |
| Defining schemas and domain models（一切校验用 `Schema`，不手写判断） | 照做。线上的形状在 `packages/protocol/src/schema.ts`，库里的 JSON 和工具入参照 Schema 读（[地基](docs/subsystems/foundation.md)、[类型驱动与进门解码](docs/style/module-design.md#类型驱动与进门解码)） |
| Writing Effect services（`Context.Service` 的类、`static layer`、`X.of`、`X["Service"]`） | 照做，服务都是这个写法（[AGENTS.md](AGENTS.md#规矩)「服务端的服务」）；layer 按 `apps/server/src/services.ts` 的次序叠 |
| Error handling（`Schema.TaggedError`，`catchTag`、`catchTags`、`catchReason`） | 照做，错误都是 `Schema.TaggedError`（`preferSchemaTaggedError`、`extendsNativeError` 查）；按标签接，不用 `instanceof` |
| Managing resources and Scopes（`acquireRelease`、`Layer.effectDiscard`、`LayerMap`） | 照做；后台的 fiber 归服务的作用域，外面回调用 `FiberSet.makeRuntime*`（[地基](docs/subsystems/foundation.md)） |
| Running Effect programs（`NodeRuntime.runMain`、`Layer.launch`） | 服务端的入口 `apps/server/src/main.ts`；命令行 `apps/cli/src/main.ts` |
| Broadcasting messages with PubSub | 用在核心状态和事件往上走的流（下层经 `Stream` 告诉上层） |
| Working with Streams | 用：SSE 的帧、帮工的事件、频道的消息；有界的 relay 见 [architecture.md](docs/architecture.md) |
| Integrating Effect into existing applications（`ManagedRuntime`） | 少用：Promise 一侧只剩外面库的一次调用；桌面壳不是 Effect，页面只有中间层用 Effect（见下一行） |
| （不在指南里）`effect/reactivity` 的 Atom、`AtomRegistry` | 页面的中间层（`apps/web/src/state/`）：自己写的 Solid 2 绑定、意图、存下来的选择、地址里的选择；只有 `state/` import 它；不用 `Atom.optimistic`（理由见 [SKILL.md](.agents/skills/vv-effect/SKILL.md#2b-页面里的-effect中间层)） |
| Batching external requests（`RequestResolver`） | 不用：外面的请求没有批量的需要 |
| Working with Schedules（`Effect.retry`、`Effect.repeat`） | 照做：语音的重试、隧道的探问是 `Schedule`；连接器收消息的循环按分支（暂停到某一刻、换代、失败的节奏）各等各的，留着手写 |
| Working with DateTime | 时间经 `Clock`；格式化在需要的地方用 |
| Observability（日志、OTLP 追踪） | 用：日志经 Effect（`apps/server/src/infra/log.ts`），OTLP 在 `apps/server/src/main.ts` 接上 |
| Testing Effect programs（`@effect/vitest`、共享 layer） | 照做：`it.effect`、`TestClock`；服务端用 `apps/server/src/testing/world.ts` 搭农场，`packages/agent` 用 `packages/agent/src/testing/testing.ts` 的 `withAgent` |
| Runtime type guards（`Predicate`） | 照做：对象用 `Predicate.isObject`、`Predicate.hasProperty`，不手写 |
| Working with SQL databases（`effect/sql`） | 用，经 `Db` 服务和 `apps/server/scripts/pg-generate.ts` 生成的查询（`apps/server/db/`） |
| Effect HttpClient | 外面的 HTTP 经 `HttpClient`（[地基](docs/subsystems/foundation.md)）；Promise 一侧还有几处直接 `fetch` |
| Building HttpApi servers | 不用：接口表是 `packages/protocol/src/api.ts` 自己的，处理在 `apps/server/src/gateway/http/handlers.ts` |
| Typed GraphQL clients | 不用 |
| Working with child processes（`ChildProcessSpawner`） | 用：git 和外部命令（`apps/server/src/modules/repo/git.ts`） |
| Building CLI applications（`effect/cli`） | 用：`apps/cli/src/main.ts` |
| Working with AI modules | 不用：模型在 `packages/ai`，大脑在 `packages/agent`，都是自己的 |
| Building distributed applications with cluster | 不用：服务端只有一个进程 |

## 2. 官网 v4 指南分节总览

对照 [Getting Started](https://effect.website/docs/v4/getting-started) 左侧目录，提炼每节容易漏掉的语义边界与本仓库落点。

| 官网分节 | 关键机制与易错边界 | 本仓库落点 |
|---|---|---|
| [Getting Started](https://effect.website/docs/v4/getting-started)（含 [Coding with LLMs](https://effect.website/blog/the-one-weird-git-trick-that-makes-coding-agents-more-effect-ive/)） | 靠 `@effect/tsgo`、仓库自定 lint 与本地对应版本源码构成紧反馈环，不凭训练记忆猜 API | `vp run effect:check`、`scripts/audit/oxlint-plugin.ts`、[tools.md](.agents/skills/vv-effect/references/tools.md) |
| Error Management（[Expected](https://effect.website/docs/v4/error-management/expected-errors) · [Unexpected](https://effect.website/docs/v4/error-management/unexpected-errors) · [Yieldable](https://effect.website/docs/v4/error-management/yieldable-errors) · [Matching](https://effect.website/docs/v4/error-management/matching) · [Accumulation](https://effect.website/docs/v4/error-management/error-accumulation) · [Sandboxing](https://effect.website/docs/v4/error-management/sandboxing) · [Parallel/Sequential](https://effect.website/docs/v4/error-management/parallel-and-sequential-errors) · [Timing Out](https://effect.website/docs/v4/error-management/timing-out)） | 预期错误直接 `return yield*`，缺陷留给边界；`_tag` 重名编译器和运行时都不报错，`catchTag` 会串接；`Effect.all` / `forEach` 默认短路，攒齐全部错误用 `Effect.validate`；`Effect.match` 保住缺陷与打断，`matchCause` 连二者一起接；`Cause` 拍平为 `cause.reasons`；`timeoutOption` 只在超时代表空值时用 | [cases.md](.agents/skills/vv-effect/references/cases.md) #6–#10、#22、#42、#43 |
| Requirements Management（[Services](https://effect.website/docs/v4/requirements-management/services) · [Default Services](https://effect.website/docs/v4/requirements-management/default-services) · [Layers](https://effect.website/docs/v4/requirements-management/layers) · [Layer Memoization](https://effect.website/docs/v4/requirements-management/layer-memoization)） | 依赖留在 `Layer` 构造期，方法签名保持 `R = never`；5 个默认服务（`Clock`、`ConfigProvider`、`Console`、`Random`、`Tracer`）可局部 `provideService` 或 `Random.withSeed`；全局 `Layer` 按引用去重（隔离实例用 `Layer.fresh`），**局部多次 `Effect.provide(eff, layer)` 不做记忆化**，动态按需构建应配 `Layer.makeMemoMap` + `Layer.buildWithMemoMap` | #1、#2、#35、#44 |
| Resource Management（[Introduction](https://effect.website/docs/v4/resource-management/introduction) · [Scope](https://effect.website/docs/v4/api/effect/Scope)） | 无条件收尾用 `ensuring`；按 `Exit` 分支收尾用 `onExit`；失败（含纤程打断）时跑不可打断补偿用 `onError`；跨调用资源与租约挂 `Scope`、[Pool](https://effect.website/docs/v4/api/effect/Pool)、[RcRef](https://effect.website/docs/v4/api/effect/RcRef)、[RcMap](https://effect.website/docs/v4/api/effect/RcMap) | #17、#30、[错误与回滚契约](docs/style/module-design.md#错误与回滚契约) |
| Observability（[Logging](https://effect.website/docs/v4/observability/logging) · [Metrics](https://effect.website/docs/v4/observability/metrics) · [Tracing](https://effect.website/docs/v4/observability/tracing) · [Tracking Fibers](https://effect.website/docs/v4/observability/tracking-fibers)） | span 内的 `Effect.log*` 自动转为当前 Span 的 Span Events；`Metric.counter` / `gauge` / `histogram` 经 `Effect.trackSuccesses` 无侵入挂载；`FiberSet` 收拢动态子纤程，可查 `size`、用 `join` 联动失败或 `awaitEmpty` 平滑排空 | #3、#25、#28、`apps/server/src/infra/log.ts` |
| [Configuration](https://effect.website/docs/v4/configuration) | 数字用 `Config.Finite` / `Int` / `Port`（不用放行 `NaN` 和 `Infinity` 的 `Config.Number`），密钥用 `Config.Redacted`，结构用 `Config.schema`；`Config.withDefault` 与 `ConfigProvider.orElse` 只在缺失时回退，填错值照常失败，而 `Config.orElse` 连校验错误一起吞；`fromEnv` / `fromUnknown` 默认把 `""` 当缺失，空串有义传 `{ preserveEmptyStrings: true }` | #24、#48、`apps/server/src/infra/config.ts` |

| Scheduling（[Choosing & Combining](https://effect.website/docs/v4/scheduling/choosing-and-combining-schedules) · [Cron](https://effect.website/docs/v4/scheduling/cron) · [Cookbook](https://effect.website/docs/v4/scheduling/cookbook)） | 跑完再等用 `Schedule.spaced`，固定节拍用 `Schedule.fixed`，日历时刻带时区用 `Schedule.cron`；把 `Retry-After` 解成错误上的 `Duration` 交 `Schedule.modifyDelay` 覆盖退避，并用 `Schedule.upTo` 封顶 | #21、#31 |
| State Management（[Ref](https://effect.website/docs/v4/state-management/ref) · [SynchronizedRef](https://effect.website/docs/v4/state-management/synchronizedref) · [SubscriptionRef](https://effect.website/docs/v4/state-management/subscriptionref)） | 纯同步更新用 `Ref`；含 `yield*` 的读改写用 `SynchronizedRef` 串行化；多观察者响应式快照用 `SubscriptionRef`（写端当 `Ref` 用，读端拿先发当前值再推增量的 `Stream`） | #20 |
| [Batching](https://effect.website/docs/v4/batching) & Caching（[Caching Effects](https://effect.website/docs/v4/caching/caching-effects) · [Cache](https://effect.website/docs/v4/caching/cache)） | `Effect.cached(task)` 每次求值都会新建独立缓存，应在构造期 `yield*` 一次再复用；`Cache` 并发同 key 只算一次、缓存失败防雪崩、纤程打断自动剔除该 key、超容量按 LRU 淘汰 | #34、#45 |
