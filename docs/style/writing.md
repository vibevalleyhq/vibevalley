# 写作

文档、Note、README、提交说明、PR 描述、代码注释和界面上的帮助文字，都照这一篇写。目标是只有一种读法：一个词一个意思，一句一件事，每个动作写明谁做，要求的强弱用固定的词。文档放在哪、写什么，见 [docs/AGENTS.md](../AGENTS.md)；代码注释写什么，见 [code.md](code.md)。

规则来自 [hai-simplified-technical](https://github.com/hylarucoder/hai-stack/blob/main/skills/hai-simplified-technical/SKILL.zh_CN.md)，它又来自 ASD-STE100。只用于技术文字；官网的宣传文案和首页的诗句不用它，那些靠节奏和修辞。

## 规则

硬规则全守；软规则做到八成，不守的地方要有理由。

- **词**：一词一义，一义一词，用[用语表](../README.md#用语)里的词；不用适当、有关的、一定程度上、较为、基本上、若干、显著、大幅、明显；不用处理、操作、优化这类空动词。
- **名词短语**：一个名词前最多两个「的」；连着的名词不超过三个；「的、地、得」分开用。
- **动词**：不用进行、加以、予以、做出、实现了对……的；用主动句；陈述事实不用「正在」；写要求只用应、不应、宜、不宜、可、不必。
- **句子**：一句一事；主语换了就写出来；代词只指一个东西；用因为、所以、如果、但写明关系；三项以上用列表。
- **步骤**：编号列表，一步一条指令，动词开头，条件在前，每句不超过 40 字，结果单独写。
- **说明**：结论在段首，一段一个主题，每句不超过 50 字，数字写明条件和日期，分清已做和计划。
- **警告**：放在步骤前；先写指令再写后果；分「警告」和「注意」两级。
- **标点和写法**：全角标点，全文一种引号（「」），中文和英文、数字之间空一格，范围用「–」，代码名放在反引号里；不用开箱即用、无缝、赋能这类套话。

## 不要过度

规则是为了让读者读得准，不是把文字写成电报。

- 软规则在会让句子别扭或丢信息时，可以不守。
- 规则管说法，不管内容：原文的事实、条件、例外和不确定都要保留。缺了读者要的东西（风险、回退办法），照样写出来。
- 改别人的文字时，原来的说法按原来的强度保留，只删空的程度词（「显著提升」改成「提升」）。
- 引文、代码、命令输出、专有名词和原话照原样保留。
- 不为了句子短，删掉注意事项或风险；不为了守规则，改掉正确的技术术语。
