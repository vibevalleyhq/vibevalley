# 子系统

每个子系统一篇，只写当前沉淀的架构现状。未完成计划放 [Agent Notes](.agents/notes/README.md)，上线后沉淀至此并删除原 Note（索引见 [文档地图](docs/README.md)）。

## 一篇怎么写

按以下顺序编写，用不上的小节直接省略：

1. **一句话**：它是什么，在农场和工作台里对应什么。
2. **管什么，不管什么**：职责边界；不管的部分链向负责的子系统。
3. **在哪**：目录、主要文件、库表与接口位置（接口清单链向 [capabilities.md](docs/reference/capabilities.md)）。
4. **模型和不变量**：核心概念，以及任何时候都应成立的约束（一条一事，主动句）。
5. **怎么走**：主要流程或状态机（编号步骤，一步一动作）。
6. **和谁打交道**：上下游依赖及交互媒介（事实、流、服务方法）。
7. **为什么这样**：每个关键决策写清理由与放弃的方案，不写过程与日期。
8. **还没做的**：链向 `.agents/notes/proposed/` 下的提案。
9. **怎么验证**：覆盖该子系统的测试文件。
