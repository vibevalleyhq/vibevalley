# 媒体任务与输入

「媒体」页由 `Media` 服务管理生图与图片／视频理解。主人在[AI 服务](docs/subsystems/provider.md)分别绑定连接与模型；任务先落库，页面通过同一状态流观察进度。生图结果保存在本机附件，理解结果保存文本、截断状态和实际用量，可以另存为稿子。管家可以发起生图、读取和取消媒体任务；理解的上传授权与发起仅对主人开放。

## 管什么，不管什么

| 管 | 不管（谁管） |
|---|---|
| 去重、排队、生成与下载的独立状态、重启恢复 | 连接与密钥（Provider、Setting） |
| 下载地址、网络目标、时间、字节和 PNG 校验 | 厂商图像协议与参数（`packages/provider`） |
| 最近任务的核心状态投影 | 附件存储、访问与频道发布（Channel） |

模型任务分为 `image` 与 `understanding`，共用 `MediaJob` 联合类型与最近任务投影。没有图片编辑、局部重绘、视频生成、TTS 或音色管理。协议及隔离程序使用厂商替身通过，不代表真实 MOSS 账号可调用或效果已验收。

| 位置 | 职责 |

| `apps/server/src/media/understanding.ts`、`apps/server/db/queries/media_understanding.sql` | 理解的授权核对、输入保留、持久化、恢复与清理 |

## 不变量

- **同一请求不重新生成**：调用者给出 1–80 位字母、数字、下划线或连字符的 ID。同一 ID、参数与调用来源返回原任务，参数或来源不同则拒绝。浏览器重试保持 ID 与参数；修改输入或再次生成须明确新建。
- **先落库再发出**：任务保存连接 ID、配置 revision、完整模型 ID、参数和阶段；Key 只留在排队任务的内存快照，改连接不改变已排队任务。任务登记与本机工作纤程注册在同一临界区内，不因浏览器断开留下未启动的排队任务。
- **来源由服务端确认**：HTTP 入口记为主人；管家工具从执行上下文取档案、频道与主人委托，不接受模型自报身份。来源随任务落库并进入公共投影，重启保留；任务的来源频道不等于图片后来发布的目标频道。
- **只记录厂商报告的用量**：成功响应的图片数和输出尺寸随签名 URL 一起落库，下载失败、重试和重启保留。未收到用量时省略该字段，页面明确未知不代表未计费，不猜价格或填零。
- **有界并发**：当前全服务端最多一个生成或下载工作、最多八个在途任务；这是比每连接一个更保守的初始限制。数据库保留历史，状态流只带最近 100 条。
- **生成与下载分开**：取得签名 URL 后先存到任务私有字段，再下载。URL 不进入公共任务、帧或工具结果；保存完成后清掉 URL。失败时可单独重试下载，不再次提交生成。
- **未知不重做**：厂商响应不完整、超时或网络错误可能已经计费，记为 `unknown`。重启把 `generating` 改为 `unknown`，未发出的 `queued` 改为 `canceled`；只自动恢复 `downloading`。
- **取消不承诺停计费**：取消改变本机状态并中断对应工作，不代表厂商停止。旧工作的取消不能中断之后明确重试的下载。
- **可用意味着落盘**：沿用 `Channel.attach`，不新建第二份资产表或存储目录。字节以 SHA256 存在附件目录；`writeOnce` 先完整写临时文件，再以硬链接原子发布，取消或写失败不留下半截哈希文件。已有文件不覆盖。
- **页面不折事实**：每次状态变化由 `Core.apply(mediaChanged)` 投影；`phaseText`、可取消和可重试下载均由服务端给出。页面不在本地猜任务是否完成。

发布沿用 Channel 接口与附件 ID。页面用命名空间、任务 ID、目标频道的 JSON 元组计算 SHA256，作为 64 字符的 `sendKey`；刷新后再次发布到同一频道不会多发一条，不同频道各有自己的发布。稿子引用同一个本机附件地址，不复制资产。

## 本机输入

`media.input.create` 校验名称、MIME、用途与声明大小，返回服务端生成的输入 ID；它只预留本机空间，不读取服务器上的任意路径、不联系厂商。主人随后 `PUT /api/v1/media/input/:id/content`，请求类型为 `application/octet-stream`，正文直接流式落盘，不经频道的 Base64 JSON。`media.input.get/list/delete` 查询、列出和删除输入；`media.input.previewDelete` 只预览，供 CLI 的 `--dry-run` 使用。五个 JSON 接口与二进制上传都只给本机主人，LAN 和 agent 工具不开放上传。

图片上限为 30,000,000 字节，视频为 200,000,000 字节。支持 PNG、JPEG、WebP、GIF、BMP、TIFF，以及 MP4、M4V、MOV、AVI、WebM、MKV 的容器签名；签名检查不代表整个文件能够解码。上传核对声明与实际字节数，计算 SHA256；流式暂存限时 300 秒，最多同时八路。输入以 `0600` 权限写入临时文件，完整写完后才以硬链接发布到 `$VIBEVALLEY_HOME/media-inputs/content/<sha256>`，不把私有路径返回给页面。相同内容共用文件，不共用输入 ID；再次上传已经就绪的 ID 返回原结果，不改内容。

所有输入预留（包括失败的和被任务保留的）最多 256 条、按每条声明大小保守计入 2 GiB 配额；相同内容也各占一条预留。未保留的预留和文件在 24 小时后回收，每分钟检查一次，接受新预留前也先回收。删除先落 `deleting` 标记，再删除没有其他输入引用的文件，最后删记录；删除失败保留标记供下次检查恢复。断线、取消和失败会关闭写入并清理临时文件；未能清理的部分文件归原输入 ID，预留继续占配额，清理成功前不能再次接收文件或删掉预留。发布前先记录预期哈希，数据库拒绝提交且文件回滚也失败时，完整文件同样仍有所属预留。一个输入的回收失败不阻塞其余输入。本机上传可以明确重试，和可能计费的厂商调用不是同一种重试。

任务保留输入与任务登记可以在同一事务内完成；被保留的输入不按期限删除，也不能由主人单独删除。只有对应的保留者可以取得磁盘支持的 Blob，读取前流式核对大小和哈希，不把大文件转为 ArrayBuffer。文件丢失或内容损坏时标失败；修复只接受原内容，新内容必须新建输入。重复内容的发布也检查已有文件，损坏时用已核对的完整临时文件原子替换，不覆盖仍然完整的文件。

重启把未结束的本机上传记为失败，清除暂存目录和没有记录引用的哈希文件；丢失文件的就绪记录改为失败。它不会自动重新读取主人的原始文件，更不会重传给厂商。理解任务登记与输入保留在同一个事务中完成。

### 远端文件记录

`media/remoteFiles.ts` 管上传与删除记录，不直接对主人开放接口。调用方必须已保留本机输入；上传前取得经过完整性核对的磁盘 Blob，并先把意图写入 `media_remote_file`，再发出一次上传请求。文件名用服务端随机 ID 加格式后缀，不把主人的原始文件名发给厂商。同一任务最多五份输入，重复请求只返回已记录的文件 ID，不重复上传；拒绝、未知和已结束的上传也不能用同一个任务重新提交。

记录包括连接 ID、配置版本、凭据的 SHA256 等值指纹、内容哈希和厂商文件 ID，不保存第二份明文 Key，也不进入公共任务或 Core。恢复时可以经 Provider 按原连接 ID 取仍启用的凭据，不跟随当前用途的默认连接；连接或 Key 不一致则在请求前拒绝。其他配置导致版本递增、但原连接和 Key 都没有变化时，可以继续清理。

取消、超时或重启中的上传记为未知，不自动重传。删除先记 `deleting`，成功回执或同一账号下的 404 才记已删除；失败保留记录，允许明确重试。重启不自行联系厂商。没有取得文件 ID 的未知上传不能盲目删除账号中的其他文件。远端记录独立于本机输入的寿命，删本机输入不会顺带抹掉远端清理依据。上传回执只有 `processed` 或 `active` 才允许随后推理；`failed` 拒绝，未识别的状态保守记为未知。即使状态不适合推理，已取得的文件 ID 仍保留，清理时必须真的删除，不把失败回执当成没有文件。

### 理解任务

`media.understanding.create` 只接受本机输入 ID、问题、输出上限和明确的上传许可，不接受服务器路径或任意远端文件 ID。许可携带页面显示的连接 ID 与配置 revision，服务端在登记前核对当前绑定；页面的勾选也绑定这份快照，连接变化不沿用旧许可。只允许最多五张图片或一个视频，不混传；不合规则不登记任务、不发厂商请求。

生图与理解共用 ID 空间、八项在途上限和一个执行槽。理解把问题、输入名称与哈希快照、连接、模型和 revision 落库，再顺序上传已保留的输入；排队时的 Key 只在内存中冻结。同一 ID 与参数只返回原任务，参数不同或与生图 ID 冲突则拒绝。

阶段为排队、上传、理解、完成、截断、失败、未知或取消。收到结果后先保存正文、供应商回报的模型和 token 用量，再清理已知远端文件并释放输入保留。`incomplete` 保留正文，不改写成成功，不自动追加请求补完。重启取消未发出的排队任务并释放其输入；上传或理解中的任务记为未知，不重传或重新推理；清理中断则保留结果并标为需要处理。

取消先记录本机状态，再中断对应工作；它不承诺供应商停止。失败、未知和取消后的文件保留到主人明确执行 `media.understanding.cleanup`，`previewCleanup` 仅列出影响、供 `--dry-run` 使用。清理只按原账号与凭据指纹操作，换 Key 后不借用新账号；失败可再点清理，只重试删除，不重做理解。没有 ID 的上传不盲删：释放本机保留，显示无法确认的随机文件名，供主人在供应商后台核对。页面切换会中止尚未完成的本机传输，已登记的服务端任务不因此重发。

## 下载边界

下载只接受 HTTPS、默认或 443 端口、无用户名密码的 URL，不带厂商认证头，不跟随重定向。专用 socket lookup 校验 DNS 返回的全部 IPv4 地址，并把已校验地址直接交给连接，不再次解析；本机、私网、链路本地、云元数据、共享地址、文档和保留地址段均拒绝。当前不支持 IPv6 结果下载。

响应必须为 200 与 `image/png`，60 秒覆盖读取，最多 25 MiB。校验 PNG 签名、chunk CRC、IHDR 尺寸与格式、完整结尾、解压长度和行过滤字节；解压上限 32 MiB，当前拒绝隔行 PNG。下载或保存失败显示可单独重试，不把错误正文、认证头或签名 URL 展示给主人。
