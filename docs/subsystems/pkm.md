# 笔记

笔记（PKM）是主人自己的知识库：一个文件夹里的 Logseq 式大纲页面，按 PARA 分在几个文件夹里，在工作台的「笔记」页（`/pkm`）里看和写。文件是真相，服务端读进来、改完写回去，主人同时用别的编辑器改也行。

## 管什么，不管什么

| 管 | 不管（谁管） |
|---|---|
| 笔记库的文件夹、页面文件读成大纲、大纲写回文件 | 帮工和管家交上来的产出（[产出](docs/subsystems/artifact.md)） |
| 块的操作（插、改、缩进、挪、标记）、找页面、搜、反链、块引用读出来 | 帮工的档案的记性（[记性](docs/subsystems/memory.md)）；搜索只借它的切词 |
| 闪念记进今天的日记、剪藏、聚类、改名和合并、导出、撤销 | 帮工和管家用的笔记工具：还没接上 |
| 主人在文件里写的批注，和对一块提的改写（接受、拒绝） | |

## 在哪

- 服务端 `apps/server/src/pkm`（服务 `Pkm`），归 Collaboration，排在 `artifact` 后面：
  - `pkm.ts`：服务本身：读文件、写文件、一把锁、批注和撤销的表。
  - `outline.ts`：文件和大纲互相转换（纯函数）：`parse`、`print`、块的边（`[[页]]`、`#标签`、`((块))`、属性里的 `[[页]]`）、别的编辑器改过以后接回块 id（`carryIds`）。
  - `ops.ts`：块的操作（纯函数）；`graph.ts`：几页合起来的查询（纯函数）：找页、块引用、反链、搜索、回顾雷达、导出、改名时改链接、改写时留住链接；`para.ts`：PARA 的文件夹和文件名。
- 笔记库在 `$VIBEVALLEY_HOME/pkm/`，配置 `pkm.root` 可以换成别的文件夹（[设置和配置](docs/subsystems/setting.md#模型和不变量)）：`00_Inbox`、`01_Projects`、`02_Areas`、`03_Resources`、`04_Archives`、`journals`，剪藏的原文在 `.pkm/snapshots/`。
- 表：`pkm_comment`（批注和改写：哪页哪块、谁、状态、提的字、理由）、`pkm_change`（每次改动写的那个文件：改之前和之后的字，撤销用）、`pkm_term`（FTS5 的全文索引：每一块的词）。
- 形状在 `packages/protocol/src/shapes.ts` 的 `Pkm*`；块的操作是封闭的联合 `PkmBlockOp`（按 `op` 区分）。接口 `pkm.*`（[capabilities.md](docs/reference/capabilities.md)），命令行照接口来（`vibevalley pkm page list`、`vibevalley pkm capture --json …`）。
- 页面 `apps/web/src/features/pkm`。

## 模型和不变量

- **页面就是文件**：一个 `.md` 一页，它在哪个 PARA 文件夹就是哪一层；标题是 `title::`，没有就是文件名（`__` 读成 `/`）。页面的属性是文件开头的 `key:: value` 行。
- **块**：每个 `- ` 是一块，缩进两个空格一层，`TODO`、`DOING`、`DONE`、`NOW`、`LATER`、`WAITING`、`CANCELED` 和 `[#A]` 这类优先级写在开头；块下面紧跟的 `key:: value` 是块的属性，`id::` 是它的 id。块里的代码围栏原样是字，里面的 `- `、`[[ ]]`、`key::` 都不算。
- **读写不变**：服务端写出的文件读进来再写，一个字节都不变：属性按固定顺序，两个空格缩进，行尾没有空格。
- **id 只在需要时写进文件**：文件里本来有的、别的块用 `((id))` 引用的、有批注或改写的块写 `id::`，别的不写。新加一个指向某块的引用时，那块所在的页面跟着写出它的 `id::`，下次从文件读进来，引用仍然找得到。
- **块 id 编辑之后不变**：服务端改完写回的页面不再从文件重读。别的编辑器改了文件、重读时，没写 `id::` 的块按「同一层、同样的标记和字」接回原来的 id，对不上的按位置生成。
- **文件改了才重读**：一页被读到时比对文件的修改时间，变了就重读，字一样只记下新时间。列表、回顾雷达会先把整个库扫一遍。服务端开机后第一次被问到笔记时才把整个库读进内存。
- **一把锁**：所有会读文件或写文件的操作一个一个来；一页读出来、改完、整页写回。写文件先写临时文件再改名。
- **批注的状态在库里**：主人在文件里写的 `==那几个字==^[批注]` 和块属性 `comment::` 按块和序号记进 `pkm_comment`，状态比文件多活一次读写。改写（`pkm.comment.suggest`）必须留住原来那块里所有的 `[[链接]]` 和 `((引用))`，提上来的字里少了的补在末尾。接受以后那块换成提的字，批注标记和 `comment::` 去掉，这块上没答的批注一起算答过；拒绝只改状态。
- **撤销**：每次改动记下写的那个文件改之前和之后的字，撤销把最新一条放回去（新建的文件就删掉）；只留最近 200 条。只为写 `id::` 而写的不算改动。

## 怎么走

**闪念**（`pkm.capture`）：今天的日记（`journals/2026_11_03.md`）末尾加一块 `LATER …`，没带 `#inbox` 的加上；没有今天的日记就新建一页。

**新建和设属性**（`pkm.page.save`）：没有这个标题的页就在给的那一层（默认收件箱）新建，`markdown` 是它的大纲；有了就合并属性，层变了就把文件挪到那一层的文件夹（`pkm.page.move` 同样）。

**改块**（`pkm.block.apply`）：先比对文件，再按顺序施加每个操作，整页写回一次。插入的块 id 由插入的一方给（页面的编辑器），没给的由服务端生成。

**看一页**（`pkm.page.get`）：页面、页上每个 `((引用))` 现在读出来的字（引用里的引用再读，最多两层，绕回来的说循环）、别的页面链接到它的块（按项目、日记、领域和资源、归档分组，新改的页在前）、这页没答的批注。

**搜**（`pkm.search`）：每一块的页标题、路径（上面几层块的第一行）和字，照记性的切法（中文按 gse）切成词存进 FTS5 的 `pkm_term`，每读进或写出一页就整页重写它那几行，开机后第一次用时整个重建。查询切成同样的词，每个词按开头匹配、用 `OR` 连起来，`bm25` 给分；整句出现再加两分，乘以这一层的权重（项目 2、领域 1.5、日记 1.4、资源 1.2、收件箱 1、归档 0.5）。可以只要某一层、某种标记、链接到某页的块。

**剪藏**（`pkm.clip.create`）：同一个地址（去掉末尾的 `/`）只有一页：再剪一次把划线加进那一页。新的一页原文存进 `.pkm/snapshots/`，属性写来源、作者、剪藏日期、原文的位置和摘要。

**聚类**（`pkm.cluster.create`）：收件箱、日记和资源里写到这个话题（或页标题里有）的块，各引用一次，放进一页新的资源。

**改名和合并**（`pkm.page.rename`）：新名字没有页就改名、挪文件，旧名字记进 `alias::`；有了就把旧页的块接到它后面、删掉旧文件。然后全库里写着 `[[旧名字]]`（含 `[[旧名字|别的字]]`）的都改成新名字。

**导出**（`pkm.page.export`）：给人的 Markdown：引用读成字，`[[链接]]` 留下字，批注标记去掉，顶层有子块的一块变成标题。

## 和谁打交道

- **记性（`memory`）**：只借 `termsList` 切中文的词（索引和查询用同一种切法），不读不写记性。
- **处理函数（`handlers.ts`）**：`pkm.*` 只转发到 `Pkm`；主人和「连接到本机」能调，`pkm.undo` 只有本机的主人。
- 不进核心状态：笔记不在 `StateFrame` 里，页面用 `pkm.*` 取，看着的时候每几秒再取一次。

## 为什么这样

- **文件是真相，库里只放文件里没有的。** 笔记是主人自己的东西，要能用 Logseq、Obsidian、编辑器打开、进 git；放进库里就只能经 VibeValley 看。放弃了把页面和块存进表：那样就有两份真相，别的编辑器一改就要合并。页面的索引放在内存：几千页读一遍是几秒的事，反链、引用、回顾雷达都是纯函数，测试不用库；只有全文检索放进库里的 FTS5，它要倒排和打分，自己写不划算。
- **id 按需写进文件。** 每块都写 `id::` 会让文件里满是 uuid；一个都不写，引用和批注重读以后就找不到块。只写有人用的，和 Logseq 一样。
- **服务端写出的页面不重读。** 重读会按位置重新生成没写 `id::` 的块的 id，编辑器里正改着的块的 id 就变了。别的编辑器改过的文件只能重读，按内容接回 id 是能做到的最好的。
- **改写必须留住链接。** 改写是模型写的，最容易丢的就是 `[[链接]]` 和 `((引用))`，丢了反链和引用就断了；补在末尾，比拒绝整个改写好用。
- **撤销按文件，不按操作。** 改名会改好几个文件，每个文件一条；只放回一个文件，比回放操作简单，也和别的编辑器的改动不打架。
