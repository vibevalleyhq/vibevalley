# 概念

VibeValley 是 AI 版的 [Linear](https://linear.app)，穿着农场的皮：工单派给 agent，agent 在项目里一轮一轮干活、汇报，你看改动，合进主分支。和 [Multica](https://github.com/multica-ai/multica) 是一类东西。和它们不同的地方有三点：

- 只给一个人用，跑在自己的机器上；
- 多了一个替你派活的管家，主界面是群聊；
- 外面画成了一座农场。

对象模型照 Linear：Workspace、Issue、优先级、状态都用它的词；项目是我们自己的，指一个 git 仓库，不是 Linear 的 Project。

本文先讲实际的东西，再讲农场怎么画它们。代码、接口和讲服务端的文档用这里的概念；界面用农场的叫法（[用语](README.md#用语)）。

## 层次

```
Workspace（工作目录，一张大地图）
├── 项目（工作目录下的一个 git 仓库，大地图上的一座岛）
│   └── worktree（岛上的一块地；一次执行占一块）
└── 工单（挂在 Workspace 下，可以指一个项目）
    └── 执行（派一次帮工是一次；重开是同一张工单的下一次）
```

现在只有一个 Workspace：工作目录 `VIBEVALLEY_WORK_ROOT` 和家目录 `VIBEVALLEY_HOME` 里的农场。

## 一件活怎么走

1. **派出去**：主人写下一张**工单**（或者管家替主人写），选一个 **agent 档案**和一个**项目**，派出去。
2. **执行**：服务端为它开一次**执行**，也就是档案在一个 **runtime** 上开的会话，在项目的 worktree 里、自己的分支上干活。
3. **一轮一轮做**：每一**轮**从一次输入开始（工单、带的话、对某一步的评论），到一次汇报结束；中间的每一**步**都记下来。
4. **看改动**：做完一轮，主人看**改动**，可以：
   - **合并**进主分支，工单就关上了；
   - 带句话，让它接着做；
   - 不合就关。

主人、管家和在做的执行都在**群聊**里说话，每张工单一个串。同时干活的执行有上限，派不出去的工单排队。

## 东西

| 概念 | 代码里 | 是什么 | 农场里 |
|---|---|---|---|
| 主人 | user | 用这台机器的人，只有一个 | 主人 |
| Workspace | `Config.WorkRoot`、`Config.Home` | 主人干活的一整片：工作目录下的全部项目、全部工单、群聊、帮工档案。同时干活的上限（6）是它的 | 一张大地图（`/map`）；农场本身 |
| 管家 | `Foreman` | 主人的助理 agent：听主人说，拆成工单，挑档案派出去，转告结果。它是 VibeValley 自己的 agent，语音时也是它 | 管家 |
| agent 档案 | `AgentProfile` | 一个能派活的「同事」：用哪个 runtime 和模型、人设、技能、MCP、不让用的工具、环境变量、长什么样 | 帮工档案（一种小动物） |
| runtime | `RuntimeInfo` | 本机上的一种编码 agent 程序（claude、codex、pi……），由 smith 驱动。记着装没装、有哪些模型、额度、花了多少、每日预算 | 农机 |
| 项目 | `Project`、`ProjectSummary` | Workspace 里的一个 git 仓库，以及同时能有几个执行在里面干活（`slots`）。不是 Linear 的 Project | 大地图上的一座岛，也是一张小地图（`/map/<项目>`） |
| 工单 | `Issue`、`Issues` | Workspace 里的一件活：标题和说明、在哪个项目、派给哪个档案、优先级，从写下到关上始终一个 id，开着的在核心状态里。状态由服务端给：待办、排队、处理中、等你看、已关；关上的能重开，重开是同一张工单的下一次执行 | 看板上的一张卡片 |
| 执行 | `Helper`、`Crew`（派活是 `Dispatch`）；工单下的 `runs` | 一个档案为一张工单开的会话：跑在一个 runtime 上，有自己的 worktree 和分支（`vibevalley/<id>-…`），一轮一轮做，直到它离开（收获、收工），工单就跟着关上。阶段有开工中、干活、做完一轮等你看、失败、歇着 | 帮工，在一块地里干活 |
| 轮 | `FactTurn` 到 `FactReport`、`LastTurn` | 从一次输入到一次汇报。汇报说做完了、失败了还是被叫停了，加上结论和花了多少 | 一季庄稼 |
| 步骤 | `WorkStep`；一个执行的全部步骤是 `Trajectory` | 一轮里的每一步：收到的话、想、说、工具调用和结果、重试、问题 | 干活过程 |
| 改动 | `Changes`、`Merges.Changes` | 分支上的提交、文件、diff，以及合进主分支会不会冲突 | 收成清单 |
| 合并 | `Merges.Harvest` | 把分支合进主分支，关上工单 | 收获（不合就关叫收工） |
| 频道 | `Channel`（`Chat` 管着） | Workspace 里说话的地方：主人在这里跟管家说话，管家在这里派活。默认的是田头，主人可以再开（按项目、按事情），可以带一个默认项目。外面的聊天软件（微信、飞书、QQ）各接在一个频道上，进来的话说在这里，这里的话发出去。Linear 没有频道，相当于它接 Slack 的那部分 | 田头和别的频道 |
| 工单串 | 频道消息下面的串；`ChatMessage` | 一张工单下的对话：派活的那条消息下面开的串，执行在这里汇报，主人在这里带话、评论某一步，@ 谁就是叫谁。相当于 Linear 工单下的评论 | 田头里的工单串 |
| 计划 | 带 `plan` 的父工单，读出来是 `Playbook` | 一件大活拆成有先后的几步：父工单是这件活，每一步是一张子工单，等它前面的步骤（`blockedBy`）。拆计划是父工单的一次执行；每步合进计划分支，最后父工单合进主分支 | 种植计划 |
| 定时 | `FarmSchedule` | 按时间在频道里对管家说一句话；写了帮工档案的是周期工单（Linear 的 recurring issue）：每次到点写一张新工单（`Issue.schedule` 记着来自哪条）、开工 | 定时 |
| Inbox | `InboxItem`、`protocol.Inbox` | 要你处理的事，从核心状态现算：等你看的、要修的、有冲突的、好久没动静的、计划等你看或卡住了、@ 你没读没回的话。巡查（`Heartbeat`）不调模型地看它，放久了才叫醒管家 | 手机来电；巡查 |
| 记忆 | `Memory` | 一个档案记得的事，每轮开头想起有关的几条；管家另有一份 | 记性 |
| 技能 | `Skill` | 档案能带的技能 | 技能书 |
| 并发位 | `protocol.MaxRunning`、`HelperPlay.Station` | 同时最多 6 个执行在干活；每个 runtime、每个项目还各有上限；满了的工单排队 | 6 块地 |

外面接进来的有：

- 客户端用的 HTTP 接口和 SSE；
- `/mcp`，执行在群聊里说话用的工具；
- 语音线路（声网）；
- 连接器（微信、飞书、QQ），各接在一个频道上；
- 局域网里的设备（院门）。

## 农场是皮

农场只画上面这些东西现在的样子，自己不管事：

| 农场里 | 画的是 |
|---|---|
| 一块地 | 一个执行占着的并发位 |
| 地里的庄稼 | 这一轮做到哪了：刚派出去时撒了种，开始干活冒芽，改了文件长叶，改完又跑了命令开花，这一轮做完结出麦子或胡萝卜。失败了枯萎，好久没动静就干裂（[game-ui.md](game-ui.md)「地里长什么」） |
| 地上的小动物 | 执行，长成它档案的样子 |
| 小动物走去哪 | 它正在用的工具：读文件、搜索去书屋，跑命令去工坊，查网页去电台，等待去长椅，其余时候在自己的地里 |
| 手、浇水、杀虫、收获、铲除 | 派活或看详情、带话、让失败的接着修、看改动再合并、叫停或请走 |
| 手机来电 | Inbox |
| 等级 | 一共提交了多少次 |
| 金币、连胜、成就、称号 | 从账本（`Ledger`）里的真实事件折出来：合并了、一轮没做成、带了话、看过改动…… |
| 地图上的岛 | 项目；岛上的地是它的执行和空着的并发位 |
| 仓库 | 收获进主分支的工单 |
| 院子里的建筑和东西 | 各个页面的入口：书屋是技能，工坊是 runtime，告示板是任务和成就，图纸桌是计划…… |

每个农场里的东西都对得上一件实际的事，或者主人能做的一件事；游戏规则只读事件、算画面，不反过来管事。

服务端的包也按这些概念分（`server/internal/` 下一个概念一个包）：base、projects、memory、runs、chat、tickets、manager、channels，最后是游戏 game（[server/README.md](../server/README.md#服务)）。

## 和代码还没对齐的地方

（[提案](../.agents/notes/proposed/architecture/2026-10-15-concepts-first.md)）

- **核心状态里混着皮**：`FarmState` 既装着执行、群聊、工单、定时，也装着金币和成就（`Progress`）、算等级用的提交数（`Commits`）。执行身上还带着它在哪块地（`HelperPlay.Station`）。
- **名字跟着皮走**：比如包名 `farm`，核心状态叫 `FarmState`，事件流叫 `Site`（工地时期的名字），给执行用的工具叫 `FarmTools`，合并叫 `Harvest`。
