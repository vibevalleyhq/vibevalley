# docs 写作骨架与质量清单（docs / craft）

## 常见长文骨架

1. **技术方案 / RFC**：
   - `structure/index.md`：一句话结论、背景约束、非目标（Non-goals）。
   - `structure/01-design.md`：数据模型、边界接口与关键不变量。
   - `structure/02-tradeoffs.md`：备选方案对比与放弃原因。
   - `structure/03-rollout.md`：灰度、回滚路径与 `- [ ]` 验收清单。
2. **产品需求（PRD）**：问题与指标 → 用户场景与边界态 → 核心流程（可嵌入 `chart`/`genui` 或 `asset/` 线框图）→ 埋点与上线标准。
3. **事故复盘（Postmortem）**：影响面与时长 → 精确时间线 → 根因（区分触发点与系统脆弱点）→ 短期止血与长期防复发行动项（带负责人与截止时间）。

## 交付前核对清单

- [ ] `structure/index.md` 首屏 30 秒内能读出结论，无空洞寒暄。
- [ ] 每个章节文件职责单一，标题层级连续（不跳级 H1 → H4）。
- [ ] 所有引用图片与附件均存在于 `asset/` 且路径拼写精确匹配。
- [ ] 关键数据对比优先以表格或原生 `chart` 块呈现，避免把 10 组数字埋在长段文字里。
- [ ] 涉及用户原文的润色或删改均以 `artifact_suggestion` 提议，未静默覆盖。
