# 交互原型体验工艺与核对清单（prototype / craft）

## 1. 做「真可点」而非「假截图」

- **关键路径全部闭环**：主流程的每一次点击、筛选、切换标签、提交表单、撤销与错误提示都必须有真实状态反馈，不留点不动或只弹 `alert("TODO")` 的死按钮。
- **内置状态切换栏（Prototype Switcher）**：在角落提供轻量可收起的演示状态条（如「正常 / 空态 / 加载中 / 错误态 / 重置演示」），方便评审者一键验证所有边界态。
- **键盘与可访问性**：弹窗支持 `Esc` 关闭，交互控件用原生 `<button>` / `<input>` 而非 `<div onclick>`，保留清晰的 `:focus-visible` 轮廓。

## 2. 区分 `prototype` 与 `design`

- 需要多画板静态视觉排布、响应式并排评审与属性杆调参时用 `design`。
- 需要真实点击体验、多步交互状态流、键盘导航或动画反馈验证时用 `prototype`。

## 3. 交付前核对清单

- [ ] 打开 `structure/index.html` 控制台零报错（无未捕获异常、无 404 资源路径）。
- [ ] `index.html`、`styles.css`、`app.js` 职责分明，无巨型单文件混写。
- [ ] 全部图片与静态资源均存于 `asset/`，无外链防盗图与沙箱违规标签。
- [ ] 主流程与至少 1 个空态/错误态均可直接操作触发并一键重置。
- [ ] 修改用户原稿的文案或交互行为均经 `artifact_suggestion` 提议，未静默覆盖。
