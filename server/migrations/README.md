# migrations

`Up(db)` 升级这份连接实际打开的 SQLite 主库。它固定一条连接，从 `PRAGMA database_list` 读取 `main` 的身份，在同一连接上读取版本、备份和执行迁移；调用者不再传第二个路径，也不判断内存库。

已有文件库需要升级时，先用 `VACUUM main INTO` 在实际数据库文件旁保留 `.v<当前版本>` 备份。已有同名备份不覆盖。SQLite 返回空文件名的内存库、URI 内存库和临时库不生成旁路备份。相对路径和 URI 转义由已打开的 SQLite 连接解析，备份不会跟着调用时的工作目录走。

备份失败时不开始迁移。每个 SQL 文件独占一个事务，提交前检查外键，版本号与该迁移一起提交；失败回滚本次迁移并恢复连接的外键检查。数据库版本比嵌入的迁移更新时拒绝升级。

`Names` 按文件名给出内嵌迁移，`Version` 读取主库的版本。`cmd/migrate` 提供命令行入口，服务端通过 `base.OpenDB` 在打开时升级。

## 验证

`go test -race ./migrations ./internal/base ./cmd/migrate`。身份测试覆盖附加数据库、相对路径、URI 特殊字符、内存与临时库、原始备份内容、备份失败以及外键失败的事务回滚。
