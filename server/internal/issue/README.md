# issue

工单拥有从待办、派发、排队到结束的状态，以及与执行、计划和定时的关联。按工单操作时，本包解析它对应的执行；调用者不先查帮工再自行拼动作。

## 派发队列

排队时，把首次派发的频道和 `RunTrigger` 写入 `issue_queue`，与 `issue.queued_at` 在同一事务提交。直接重试和后台重试都恢复这份上下文；定时的 schedule id、missed 标记也随队列保存。执行成功关联工单时，在同一事务里清除队列记录；主动退队同时清除排队状态和上下文。

队列按工单当前内容和档案启动，保留首次入队的来源。重复派发已排队工单不会把来源改成田头，也不会把定时触发改成普通工单触发。

## 计划与执行结束

父子工单在数据库中按一个事务保存，随后以 `Core.ApplyBatch` 发布完整聚合；状态读取者不需要等到父工单最后一条事件才拼出完整计划。

管家执行可以在一个 Run 中消费多张工单。执行 owner 仅为实际消费的输入建立关联；本包订阅成功完成通知后逐张关闭。失败和中断不算答复成功；关闭写入失败会记录 Run 与工单身份，保持工单未关闭。

历史查询的返回约定见 [帮工](../../../docs/subsystems/session.md)。

## 验证

`go test -race ./internal/issue ./internal/workspace`。队列测试分别通过直接重试和后台重试验证频道、定时来源及 missed 标记；执行归属测试在 `internal/manager/execution_test.go`。
