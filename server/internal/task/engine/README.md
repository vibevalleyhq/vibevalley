# engine

agent 自己的任务图：一件活拆成的几件事，每件写明要做什么（`brief`）、要等哪几件（`after`）、谁做（`by`：自己或帮手）、做到哪（等着、在做、做完、没做成、跳过）和结果。等的都做完或跳过了就能做（`Ready`）；全部做完或跳过，这张图就收起来（`Finished`）。

边的规则（id 的写法、重复、等自己、等不存在的、成圈、分层）在 `protocol/dag.go`，和种植计划的步骤共用一份；状态能怎么变、话怎么说归本包。`Add` 整批收或整批不收，回给模型的问题说清是哪一条；`Update` 只让没开始和没做成的改正文和先后，做完的不能退回。

`Store` 是一个主人（一个会话，或管家）没做完的那张图：`Change` 整张读、改、写回，一次做完。`DBStore` 存在农场的库里（表 `task_graph`，一张图一个 uuidv7，做完的盖上 `finished_at` 留着）；`MemoryStore` 给没有农场的命令行，进程退出就没了。做完的图，主人就没有打开的图了。

帮手的那几步：`Begin`（派出去）、`Settle`（交回：做完，或失败；失败在 `Retries` 次以内退回等着）、`Requeue`（叫回或进程没了：在做的退回等着）。

工具在 [brain](../brain/README.md)（`TaskTools`）。`go test ./internal/task/engine` 覆盖收、拒、状态的变化、帮手的几步、给模型看的文字，和两种存储的存取（库用临时文件跑完迁移）。
